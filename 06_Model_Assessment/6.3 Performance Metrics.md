## 速览 At a glance

**速记**

回归侧的三个数：RMSE 与目标同量纲、对大误差「同罪同罚」所以对离群点敏感；MAPE 是相对量、可跨数据集比，但真值接近 0 会炸；R² 只回答「解释了多少方差」，可以为负。分类侧的一切都从混淆矩阵的四个格子长出来：Accuracy = 判对比例，Precision = 标记里有多少是真的，Recall = 真的里抓到多少，AUC = 排序能力、与阈值无关，`Gini = 2·AUC − 1`。选择取决于哪类错误更贵：误杀贵就看 Precision，漏掉贵就看 Recall。两个数要记住：基础率 5% 的欺诈模型，标记 80 单、命中 30 单时 Precision 只有 37.5%，而「全不标记」的 Accuracy 是 95%；基础率减半、模型不变，Precision 会掉到 22.6%。所以 Precision / Recall / Accuracy / F1 都不能跨数据集直接比，AUC 可以。

**一句面试答法**

> "Everything starts from the confusion matrix — accuracy, precision and recall are just different ways of reading the same four cells. Accuracy is misleading under imbalance, so I'd look at precision when false positives are expensive and recall when false negatives are, and pair AUC with lift or Gini for ranking."

**术语**

| 中文 | English | 一句话 |
|---|---|---|
| 混淆矩阵 | confusion matrix | TP / FP / FN / TN 四个格子 |
| 准确率 | accuracy | 判对的比例，不平衡时骗人 |
| 精确率 | precision | 标记为正中真的比例，也叫 PPV |
| 召回率 | recall | 真命中抓到的比例，也叫 TPR / sensitivity |
| 特异度 | specificity | 真负中判对的比例 |
| 假阳率 | false positive rate (FPR) | FP/(FP+TN)，ROC 的横轴 |
| 调和平均 | F1 | Precision 与 Recall 的调和平均 |
| ROC 曲线 | ROC curve | TPR 对 FPR 的全阈值曲线 |
| 曲线下面积 | AUC | 随机正样本得分高于随机负样本的概率 |
| 基尼系数 | Gini | `2·AUC − 1`，信用风险常用 |

| 均方根误差 | RMSE | 与大误差同罪同罚的回归误差 |

## 一、先看一个问题

面试官的原话是 "Explain a confusion matrix."，这句话背后在考什么：你能不能从四个格子里讲出「这个模型上线会挨什么骂」。

具体一点。一个欺诈模型，1000 份保单里有 50 份真的欺诈。模型标记出 80 份嫌疑单，其中 30 份是对的。风控团队拿到的清单是 80 单，他们人工核实 80 次，最后只有 30 次真的立案——**62.5% 是白干**。他们问：能不能少标一点？你如果把阈值收紧到只标 20 单，命中率会好看，但漏掉的欺诈会变多。

这时你手上能报的数字有一堆：Accuracy 93%、Precision 37.5%、Recall 60%、AUC（先假设 0.9）。四个数字都对，但业务真正要的是「每 80 次核查能换来多少立案」——那是 Precision。这一篇就是把这张 2×2 表的每一种读法、以及每种读法在什么时候会骗你，讲清楚。

---

## 二、核心直觉

### 一张 2×2 的表，四种读法

混淆矩阵就是两行两列：真实的两行（是欺诈 / 不是欺诈）、预测的两列（标记 / 不标记）。四个格子各有名字，所有分类指标都是这四格的组合：

| 角色 | 业务含义 | 代价 |
|---|---|---|
| **TP**（真阳） | 是真欺诈、也标记了 | 抓对了 |
| **FP**（假阳） | 不是欺诈、却被标记 | 人工核查白干、客户被骚扰 |
| **FN**（假阴） | 是真欺诈、却放过了 | 赔付损失 |
| **TN**（真阴） | 不是欺诈、也没标记 | 正常放行 |

像的地方：这张表像医院筛查报告，「有病且查出」是 TP、「没病但报阳性」是 FP，两类错误的名字都一样。**不像的地方有两处**：医院只有一个人群基础率，而模型上线后基础率会变（第四节实测：基础率减半，Precision 从 37.5% 掉到 22.6%，模型一个字没改）；而且医院的阳性阈值是医生定的，模型这里是你自己定的——**阈值一变，四格全变，所有指标一起变**。

### 为什么不能只报一个数

Accuracy 只看对角线和，它把「误杀」和「漏放」当成一样贵；Precision 和 Recall 各只看一半；AUC 只看排序、不看水平。一个数字只能回答一个问题，所以「模型好不好」这句话必须先被翻译成「哪种错误更贵」。

## 三、机制

### 3.1 回归指标（Regression Metrics）

#### ✅ 快速对比（回归指标）

| 指标   | 含义（Interpretation） | 对量纲敏感（Scale-sensitive） | 惩罚大误差 | 对离群点稳健 |
| -------- | -------------------- | --------------- | ----------------------- | ------------------- |
| **RMSE** | 平均误差（与目标同单位） | 是             | 是                     | 否                  |
| **MAPE** | 平均百分比误差        | 否              | 否                      | 否                  |
| **R²**   | 解释了多大比例的方差 | 否              | 否                      | 否                  |

> 读表要点：**RMSE** 与大误差「同罪同罚」，所以对离群点敏感；**MAPE** 是相对量，所以跨数据集可比，但真值接近 0 时会炸；**R²** 只看解释了多少方差，对误差大小本身不敏感，而且**可以为负**。

#### 🔸 1. RMSE – Root Mean Squared Error

- **What it Measures**（度量什么）：预测值与真实值之间误差的平均幅度；因为先**平方**再开方，所以对**大误差惩罚更重**。
- **Formula**（公式）：

$$
\text{RMSE} = \sqrt{\frac{1}{n} \sum_{i=1}^{n}(y_i - \hat{y}_i)^2}
$$

逐符号读：$y_i$ 是第 $i$ 个观测的真实值（actual / true value），$\hat{y}_i$ 是预测值（predicted value），$n$ 是观测总数。先算每个点的残差、平方、求平均，再开方——开方是为了把单位换回目标的单位。
- **Pros**（优点）：对大误差敏感（想惩罚离谱预测时正合适）；与目标变量**同量纲**，好解释。
- **Cons**（缺点）：对离群点（outliers）不稳健；不缩放就很难跨数据集比较。
- **Use When**（什么时候用）：你更在意**大误差**被重重惩罚的场合（例如预测、成本估算）。

#### 🔸 2. MAPE – Mean Absolute Percentage Error

- **What it Measures**（度量什么）：预测值与真实值之间差异的**百分比**平均；把误差表达成真实值的百分比。
- **Formula**（公式）：同样是 $y_i$ 为真实值、$\hat{y}_i$ 为预测值、$n$ 为观测数。

$$
\text{MAPE} = \frac{100\%}{n} \sum_{i=1}^{n} \left| \frac{y_i - \hat{y}_i}{y_i} \right|
$$

- **Pros**（优点）：与量纲无关（scale-independent），可以跨数据集比较；直观——「平均而言预测偏了 X%」。
- **Cons**（缺点）：当 $y_i = 0$ 时无定义或严重失真（除零）；分母小的样本会让该指标被过度放大。
- **Use When**（什么时候用）：你想要一个**直观的百分比误差**，而且数据里没有 0 或接近 0 的真实值。

#### 🔸 3. R-squared (R²) – Coefficient of Determination

- **What it Measures**（度量什么）：目标变量的方差中**被模型解释**的比例。
- **Formula**（公式）：

$$
R^2 = 1 - \frac{\sum (y_i - \hat{y}_i)^2}{\sum (y_i - \bar{y})^2}
$$

分母里的 $\bar{y}$ 是真实值的均值；分子是**模型误差**总量（残差平方和，residual sum of squares, RSS），分母是真实数据中的**总方差**（总平方和，total sum of squares, TSS）。
- **Range**（取值范围）：$R^2 = 1$ 完美预测；$R^2 = 0$ 模型不比「直接用均值预测」更好；$R^2 < 0$ 比用常数均值预测还差（在验证集上完全可能出现）。
- **Pros**（优点）：反映拟合优度（goodness-of-fit）；好解释——「目标中 X% 的变异被模型解释了」。
- **Cons**（缺点）：看不出过拟合（要判断过拟合用 adjusted R² 更合适）；用在非线性模型上容易误导。
- **Use When**（什么时候用）：你想评估**模型抓住了多少数据变异**。

### 3.2 分类指标（Classification Metrics）

下面把分类指标逐个讲清楚，统一以**混淆矩阵（confusion matrix）**作为参照框架。 ^26c0e0

#### 🔲 Confusion Matrix Overview（混淆矩阵总览）

混淆矩阵（confusion matrix）是一张二维表，用来评估分类算法的表现：

|                      | **Predicted: Positive**（预测为正） | **Predicted: Negative**（预测为负） |
| -------------------- | ----------------------- | ----------------------- |
| **Actual: Positive**（实际为正） | True Positive（**TP**，真阳）  | False Negative（**FN**，假阴） |
| **Actual: Negative**（实际为负） | False Positive（**FP**，假阳） | True Negative（**TN**，真阴）  |

> 记忆方式：第一个词表示**判对了还是判错了**（True / False），第二个词表示**模型给出的判断**（Positive / Negative）。所以 FP = 模型说是坏样本、实际不是 —— 这是「误杀」。

#### 1. ✅ Accuracy（准确率）

- **What it Measures**（度量什么）：模型整体判对的比例。
- **Formula**（公式）：

$$
\text{Accuracy} = \frac{TP + TN}{TP + TN + FP + FN}
$$

- **Use Case**（适用场景）：**类别平衡**时最好用；数据不平衡时会被多数类带偏，具有误导性。

#### 2. 🎯 Precision（精确率）

- **What it Measures**（度量什么）：在预测为正的样本中，有多少真的是正？
- **Formula**（公式）：

$$
\text{Precision} = \frac{TP}{TP + FP}
$$

- **Use Case**（适用场景）：**假阳（false positive）**代价高时（例如垃圾邮件过滤、筛查阳性后的进一步检查）。

#### 3. 📈 Recall（召回率，又叫 Sensitivity 或 True Positive Rate）

- **What it Measures**（度量什么）：在实际为正的样本中，我们正确找出了多少？
- **Formula**（公式）：

$$
\text{Recall} = \frac{TP}{TP + FN}
$$

- **Use Case**（适用场景）：**假阴（false negative）**更严重时（例如疾病诊断、欺诈检测）。

#### 4. 📊 AUC – Area Under the ROC Curve

- **What it Measures**（度量什么）：模型在**所有阈值**上区分两类的能力，是**与阈值无关**的排序指标。
- **Based on**（基于什么）：ROC 曲线（TPR vs. FPR）。
- **ROC Axes**（ROC 的两轴）：纵轴 Y-axis 是 **True Positive Rate（等于 Recall）** = TP / (TP + FN)；横轴 X-axis 是 **False Positive Rate** = FP / (FP + TN)。
- **Interpretation**（怎么解读）：
  - 1.0 = 完美区分；0.5 = 相当于随机猜；<0.5 = 比随机还差（说明标签或方向搞反了）。
  - 等价定义：**AUC = P(随机取一个正样本的得分 > 随机取一个负样本的得分)** —— 这个说法在面试里比「曲线下面积」更受欢迎。
  - 与 **Gini** 的关系：`Gini = 2·AUC − 1`（信用风险场景常用 Gini 报指标）。

#### 5. 别的常用指标（同一张表的其他读法）

- **Specificity（特异度）** = TN / (TN + FP)：真负里判对多少。与 Recall 是一对。
- **F1** = $2\cdot\frac{\text{Precision}\cdot\text{Recall}}{\text{Precision}+\text{Recall}}$：两个指标的调和平均。调和平均会向小的那个靠——只要有一项很低，F1 就低。
- **Lift@k / top-decile lift**：按分数排序取前 k%，里面的正类比例是全体正类比例的几倍。业务最爱听这个。
- **KS** = 正负样本得分分布的最大间距（max |CDF₊ − CDF₋|），信用评分卡的标准报告项。

## 四、算一遍

### 第 1 步：把四个格子填满

1000 份保单，其中**真的欺诈 50 份**（基础率 5%）。模型标记出 **80 份**嫌疑单，其中 **30 份**是真欺诈。

|  | 预测：标记 | 预测：不标记 | 行合计 |
|---|---|---|---|
| **实际：欺诈** | TP = **30** | FN = **20** | 50 |
| **实际：正常** | FP = **50** | TN = **900** | 950 |
| 列合计 | 80 | 920 | 1000 |

三个合计要能自己核对：$30+20=50$（真实欺诈）、$30+50=80$（标记总数）、$20+900=920$、$50+900=950$。

### 第 2 步：五个指标一起算

$$
\text{Accuracy} = \frac{30+900}{1000} = \mathbf{0.9300} = 93.00\%
$$

$$
\text{Precision} = \frac{30}{30+50} = \frac{30}{80} = \mathbf{0.3750} = 37.50\%
$$

$$
\text{Recall} = \frac{30}{30+20} = \frac{30}{50} = \mathbf{0.6000} = 60.00\%
$$

$$
\text{Specificity} = \frac{900}{900+50} = \frac{900}{950} = \mathbf{0.9474} = 94.74\%
$$

$$
F_1 = 2\cdot\frac{0.375\times0.6}{0.375+0.6} = \frac{0.45}{0.975} = \mathbf{0.4615}
$$

顺手把假阳率也写出来：$\text{FPR} = 50/950 = \mathbf{5.26\%}$，它是 ROC 的横轴，也是「核查工作量」的源头。

### 第 3 步：跟「什么都不做」的基线比

| 策略 | Accuracy | Precision | Recall | 备注 |
|---|---|---|---|---|
| **本模型**（标记 80 单） | 93.00% | 37.50% | 60.00% | 80 次核查换 30 次立案 |
| **全不标记** | **95.00%** | — | 0% | 什么都没抓，Accuracy 反而更高 |
| **全部标记** | 5.00% | 5.00% | 100% | 核查 1000 次 |

**注意这里的反转**：不标记任何单子，Accuracy 是 95%，比模型高 2 个百分点。这就是「不平衡场景不能只看 Accuracy」的量化版——一个什么都不做的策略在 Accuracy 上赢了。

### 第 4 步：报数字的时候说清代价

- 标记的 80 单里，**50 单是误杀**（$50/80 = 62.5\%$ 白干）。风控团队的考核是「核查后立案率」，那么该看的是 Precision 37.5%；
- 真实的 50 个欺诈里漏掉 20 个（漏报率 40%），每个漏掉的都得赔付。如果赔付期望远高于一次核查成本，就该把阈值放宽——**放宽即 Recall 上去、Precision 下来，没有免费的**。

### 第 5 步：另一组数字（100 个样本的小例子）

同样的算法换一副数据，混淆矩阵变成：

|                           | **Predicted: Positive**（预测为正） | **Predicted: Negative**（预测为负） |
| ------------------------- | ----------------------- | ----------------------- |
| **Actual: Positive (40)**（实际为正 40 个） | 30（**TP**）             | 10（**FN**）             |
| **Actual: Negative (60)**（实际为负 60 个） | 5（**FP**）              | 55（**TN**）             |

- **Accuracy**： $(30 + 55) / 100 = 0.85$
- **Precision**： $30 / (30 + 5) = 0.857$
- **Recall**： $30 / (30 + 10) = 0.75$
- **AUC**：取决于模型的分数分布，但就这组值而言通常会很高（例如 0.9+）。

> 注意这里的**不平衡**：正样本只占 40%。如果模型把所有样本都判为负，Accuracy 会高达 0.60 —— 这就是为什么不平衡场景不能只看准确率，要看 Recall / AUC / Lift。另外 AUC 只衡量**排序**：它不管阈值定在哪，也不管预测的概率是否校准（calibration）；要用概率本身做决策时，还要另外看校准曲线。

### 条件检验一：基础率减半，模型不动

把欺诈率从 5% 降到 **2.5%**（1000 份保单里 25 份真的欺诈），模型一个字不改：阈值没动，所以 **Recall 仍是 60%**、**FPR 仍是 5.26%**。

于是 $TP = 0.6\times25 = 15$，$FN = 10$，$FP = 0.0526\times975 = 51.3$：

$$
\text{Precision} = \frac{15}{15+51.3} = \frac{15}{66.3} = \mathbf{0.2262} = 22.62\%
$$

**Precision 从 37.50% 掉到 22.62%（只有原来的 60%），而模型和阈值都没变。** 原因在分母：正类少了一半，但负类多出来的部分照样按 5.26% 的假阳率贡献误杀。同时 Accuracy 还升了一点（$(15+923.7)/1000 = 93.87\%$）——Accuracy 的动向和 Precision **相反**，这又一次说明它不能当主指标。

如果业务的口径是「每天人工只能核查 80 单」（标记数固定），那么基础率减半后 Precision 是 $15/80 = 18.75\%$。**同一个模型，三种口径给出 37.5% / 22.6% / 18.8%，而 AUC 一动不动。**

### 条件检验二：换个阈值，指标往哪边动

同一个模型，把标记数从 80 放宽到 130 单（假设多出来的 50 单里 10 单是真欺诈）：

| 阈值 | TP | FP | FN | Precision | Recall | F1 |
|---|---|---|---|---|---|---|
| 严（标记 80） | 30 | 50 | 20 | 37.50% | 60.00% | 0.4615 |
| 松（标记 130） | 40 | 90 | 10 | 30.77% | 80.00% | 0.4444 |

Recall 从 60% 涨到 80%，Precision 从 37.5% 降到 30.8%，F1 几乎没动（0.4615 → 0.4444）。**F1 在这两个阈值上区分不出来，而业务在这两个阈值上做的事完全不同** —— 这就是「上下线阈值要看成本、不要看 F1」的具体理由。

## 五、什么情况下会失灵

### 承重假设

**假设一：评估样本的正类比例 ≈ 部署时的正类比例。** 这是 Precision / Accuracy / F1 / Lift 的承重墙。

撤掉它的后果：第四节条件检验一给了绝对值——基础率从 5% 降到 2.5%，Precision 从 37.50% 变成 22.62%。反方向的后果更常见：用抽样（例如过采样正类）训出来的评估集上，Precision 会好看得多，上线立刻掉。排序指标（AUC、KS、Gini）在「分数分布不变」的前提下对基础率不敏感，这也是面试里应该主动说的一句。

**假设二：阈值固定，而且这个阈值与业务的成本结构匹配。** 撤掉它的后果：0.5 是软件默认值，不是业务最优值。第三、四步那张表里，标记 80 单与 130 单的 Recall 差 20 个百分点、Precision 差 7 个百分点。**阈值定错，所有指标都只是「你选的阈值有多好」的记录。**

**假设三：标签本身可信。** 撤掉它的后果：欺诈的「真值」通常来自人工复核，人工也有漏判。标签噪声会把 Precision 和 Recall 一起往下压——极端情况（标签随机）下你算出来的指标只是 0.5 附近的噪声。做评估集时要把「复核过的」和「未复核的」分开。

**假设四：评估单位和决策单位一致。** 撤掉它的后果：按保单算的 Accuracy 和按索赔额加权的 Accuracy 是两个数。欺诈金额高度集中时，按「笔数」判对 93% 可能只覆盖了 60% 的涉案金额。这时要换成金额加权的混淆矩阵。

### 与其他指标的边界

| 你想回答的问题 | 用谁 | 为什么不用别的 |
|---|---|---|
| 类别平衡时整体判对多少 | Accuracy | 不平衡时会被多数类带偏 |
| 每标记一次有多少是对的 | Precision（PPV） | 依赖基础率，不能跨数据集比 |
| 真的抓到了多少 | Recall / TPR | 与 Precision 此消彼长 |
| 阈值还没定，先看排序 | AUC / Gini / KS | 与阈值、基础率都无关 |
| 极不平衡 + 只看正类 | PR-AUC、Lift@k、top-decile | ROC 在不平衡时看着乐观 |
| 概率要拿去定价 / 定规则 | 校准曲线、Brier、分段校准 | AUC 对校准完全不敏感 |
| 回归 + 重尾目标（赔款） | 离差、MAE、分位数损失 | RMSE 被少数大额点主导 |
| 需要跨时间/跨人群监控 | 指标 + 基础率 + 校准三条一起看 | 单看 Precision 会把基础率漂移误判成模型退化 |

## 六、常见误解

### 误解一：「AUC 高就等于模型好」

**错误想法**：AUC 0.94，这个模型可以上线了。

**为什么容易这么想**：AUC 与阈值无关、与基础率无关，是所有指标里最「干净」的一个，于是被当成总评分。

**错在哪一步**：AUC 只描述排序，它同时漏掉三件事：阈值定在哪、概率是否校准、哪种错误更贵。第四节的例子里 AUC 假设是 0.9，可 Precision 只有 37.5%，标记 80 单里 50 单是误杀。要上线，得把 AUC 翻译成「在我准备用的这个阈值上，Precision / Recall 各是多少，业务接不接受」。另外 AUC 在不平衡场景里会偏乐观（少数类的排序错一点也看不出来），这时看 PR-AUC 或 Lift@k。

### 误解二：「Accuracy 高就能上线」

**错误想法**：93% 的准确率已经不错了。

**为什么容易这么想**：Accuracy 是唯一一个「猜对了多少」的直觉翻译，而且它天然看起来像成绩单。

**错在哪一步**：漏掉了「不做事的基线有多高」。第四节里全不标记的 Accuracy 是 95%，比模型高；基础率再降一半，模型 Accuracy 还升到 93.87%，而它抓到的真欺诈少了一半。**在基础率 5% 的问题上，Accuracy 的有效信息量接近 0**，因为它的分母里 95% 是 TN。看一眼混淆矩阵的第二行，就知道该不该用 Accuracy。

### 误解三：「F1 是万能的单一数字」

**错误想法**：要一个数就把模型说清楚，那就报 F1。

**为什么容易这么想**：F1 同时用到 Precision 和 Recall，看起来是「综合」了两类错误。

**错在哪一步**：调和平均隐含了「Precision 和 Recall 同等重要」，而这个权重是产品经理定的、不是数学定的。第四节条件检验二里，阈值从标记 80 单放宽到 130 单，Recall 涨 20 个百分点、Precision 降 7 个百分点，**F1 从 0.4615 变到 0.4444，几乎不动**——它恰好把业务最关心的那个取舍抹平了。而且 F1 和 Precision 一样依赖基础率：基础率减半、模型不变，F1 从 0.4615 掉到 0.3285。

### 误解四：「指标可以直接跨数据集、跨时间段比较」

**错误想法**：我们模型的 Precision 是 42%，比竞品的 37% 好。

**为什么容易这么想**：都是比例数字，量纲一样，自然可以比。

**错在哪一步**：Precision、Accuracy、F1、Recall、Lift 都依赖基础率或阈值（Recall/FPR 依赖阈值，Precision/Accuracy/F1 两个都依赖）。同一个模型在 5% 基础率的数据上 Precision 37.5%，在 2.5% 的数据上 22.6% —— 37.5% 和 22.6% 之间的差别可以完全来自人群不同，而不是模型不同。要比较就得固定两件事：**同一份评估集、同一个阈值**；跨时间的监控则要同时看基础率和校准，否则会把「人群变了」误判成「模型坏了」。

## 七、面试怎么答

### 30 秒版

> 我从混淆矩阵出发：Accuracy 是判对的比例，Precision 是标记里真的比例，Recall 是真的抓到的比例，AUC 是全阈值下的排序能力、等于「随机正样本得分高于随机负样本」的概率。不平衡数据里 Accuracy 会骗人——1000 份保单 50 份欺诈，什么都不标也有 95%。误杀贵就看 Precision，漏掉贵就看 Recall，纯排序就用 AUC 或 Gini。

### 2 分钟版（要包含的四块）

1. **混淆矩阵**：TP / FP / FN / TN 四个格子，第二个词是模型的判断，所以 FP 是误杀。
2. **公式与口径**：Accuracy $=(TP+TN)/N$、Precision $=TP/(TP+FP)$、Recall $=TP/(TP+FN)$、Specificity $=TN/(TN+FP)$、F1 = 调和平均、`Gini = 2·AUC − 1`。
3. **一个带数字的例子**：1000 份、50 份欺诈、标记 80 命中 30 → Accuracy 93%、Precision 37.5%、Recall 60%、Specificity 94.7%、F1 0.46；「全不标记」Accuracy 95%。
4. **口径敏感性**：基础率减半、模型不变 → Precision 22.6%（AUC 不变）。所以 Precision / Accuracy / F1 不能跨数据集比，AUC / KS / Gini 可以。

### 会被追问到哪

| 追问 | 答法要点 |
|---|---|
| 「Precision 和 Recall 怎么选？」 | 看哪类错误更贵：误杀贵（垃圾邮件、客户骚扰）看 Precision；漏掉贵（欺诈、疾病）看 Recall |
| 「为什么不用 Accuracy？」 | 不平衡下 TN 占大多数；举「全不标记 95%」的例子 |
| 「AUC 的直觉解释？」 | P(随机正样本得分 > 随机负样本得分)；与阈值、基础率无关 |
| 「KS 和 AUC 什么关系？」 | 都衡量排序，KS 是分布最大间距（0–1 更直观），AUC 是整条曲线下的面积 |
| 「模型上线看什么？」 | AUC/KS 看排序 → Lift 看前端富集 → 校准曲线看概率能不能直接用 → 混淆矩阵看选定阈值下的工作量 |
| 「不平衡怎么办？」 | 换指标（PR-AUC、Lift）、调阈值或类权重；重采样会破坏概率校准（要截距校正） |
| 「回归用什么？」 | 大误差重要 → RMSE；要稳健 → MAE；要百分比 → MAPE（真值近 0 不能用）；重尾 → 离差 / 分位数损失 |

## 🗣️ 英文表达 / How to Say It

**30-second version**

> "For regression I'd use RMSE when large errors matter and MAE when I want robustness, and R-squared to say how much of the variation is explained — remembering that R-squared can be negative. For classification I always start from the confusion matrix, because precision, recall and accuracy are just different ways of reading it."

**Mechanism**

> "Accuracy is misleading under imbalance, so I'd look at precision, recall or F1 instead. AUC measures ranking across all thresholds — it's the probability that a random positive scores higher than a random negative, and it's threshold-free."

**If they push back**

> "A common pitfall is reporting AUC on its own. It ignores the business cost and it says nothing about the probability level, so in a risk setting I'd pair it with KS or Gini, add lift in the top decile for the business, and check calibration if the probability itself is going to be used. MAPE is another trap — it's unusable when the actual value is near zero."
