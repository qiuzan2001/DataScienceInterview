Proper data splitting is **critical for unbiased model performance evaluation** and avoiding overfitting. Here's a comprehensive breakdown:

---

## **1. Why Split the Data?**

The goal is to **simulate how the model will perform on unseen data** and tune it effectively without leaking information from test sets.

---

## **2. Standard Splitting Strategy**

| Split Type         | Purpose                                                 | Typical Size (%) |
| ------------------ | ------------------------------------------------------- | ---------------- |
| **Training Set**   | Used to **fit/train** the model's parameters.           | 60–80%           |
| **Validation Set** | Used to **tune hyperparameters** and compare models.    | 10–20%           |
| **Test Set**       | Used only at the end to **evaluate final performance**. | 10–20%           |

---

## **3. Key Concepts**

### ✅ **Training Set**

* Input to the model during the learning phase.
* The model “sees” this data and updates internal weights/coefficients accordingly.

### 🧪 **Validation Set**

* Acts like a **"mini test set"** during training.
* Used to:

  * Tune hyperparameters (e.g., tree depth, learning rate).
  * Perform model selection (comparing different algorithms).
* Must not be used for final performance claims.

### 📊 **Test Set**

* **Held back entirely** until the very end.
* Only used once to simulate how the model performs in the real world.
* Final metric used for reporting accuracy, RMSE, AUC, etc.

---

## **4. Common Practices**

### 🔁 **When Data Is Limited**:

Use **Cross-Validation** instead of a static validation set to better estimate model generalization.

### 🧼 **Ensure Stratification (for Classification)**:

Preserve class distribution across splits using **stratified sampling**, especially if classes are imbalanced.

### Q: What is cross-validation? Which flavor for which data?

> 🎯 真题问法（MAGNet §6）｜ 深潜来源：MAGNet §6 Cross-validation ＋ 本文件 §4「When Data Is Limited」＋ [[05. 高频追问 TOP 30]]

> ⚡ 先说的那一句
> 「把验证角色在 **k 折之间轮转再平均**，于是**每条记录既用于拟合、也用于验证** —— 在不牺牲训练数据的前提下，拿到一个**更低方差**的性能估计。」

**一句话机制**：切 k 折 → 每次留 1 折做验证、其余 k−1 折拟合 → 得到 k 个分数 → **取平均**。相比「一个固定的验证集」，它把**验证的运气**平均掉了。

**场景对照表（面试照这张念）**：

| 变体 | 什么时候用 |
|---|---|
| **k-fold（k = 5 或 10）** | **默认** |
| **Stratified k-fold** | **分类，尤其不平衡** —— 每折保持**类别比例（class proportions per fold）** |
| **LOOCV（k = n）** | **极小数据集**。几乎无偏，但**高方差且昂贵** |
| **Repeated k-fold** | 想平均掉「**折分配的运气（fold-assignment luck）**」 |
| **GroupKFold** | **聚类数据** —— 一个保单 / 一个人多行，必须**整组进同一折** |
| **Time-series / rolling-origin CV** | **时序数据**：扩张窗口（expanding）或滑动窗口（sliding）；**永远用过去训练、未来验证，绝不 shuffle** |
| **Nested CV** | **你在调参、同时又要报告性能**：**内层调参（inner loop），外层度量（outer loop）** |

**选 k 是偏差-方差问题**：**小 k → 每个模型训练数据更少 → 更悲观的偏差，但折间方差更低；大 k → 偏差更小、方差更大、算得更多。5–10 是标准折中。**

**⚠️ TRAP**：**用同一个 CV 循环既调参又报告** —— 那个数字是**乐观有偏**的（你正是因为这些折表现好才选了那组超参数；被 200 次比较用过的验证集，不再是任何东西的无偏估计）。**修法：嵌套 CV，或留一个干净的最终留出集（clean final holdout）。**

**配套必须说的三句**：① **预处理要在折内做**（标准化、WOE 分箱、插补、SMOTE 都在**训练折里 fit**，否则等于泄漏）；② 有**时间维度**时用 **out-of-time** 切分，而不是随机切分；③ **分组数据**要保证**实体完整性**（同一保单 / 同一家庭的行不跨折）。

> 🔗 会被追问到
> - 「**5 万条数据还要 CV 吗？**」→ 要：留出集够大时 5-fold 仍比单次划分稳；数据极大时可退回 **train/validation/test + 一次留出**。
> - 「**嵌套 CV 贵不贵？**」→ 大约贵 k 倍；代价换的是**报告数字的无偏性**，只在「调参 + 报告」同时发生时才必须。
> - 「**k 取 5 还是 10？**」→ 没有普适答案：**小数据 / 对偏差更敏感 → 10（或 LOOCV）；要快、要在折间做很多比较 → 5**。
> - 「**不平衡 + 时序同时存在怎么办？**」→ **先按时间切**，再在训练窗口内做分层或分组；**永远不要为了分层而 shuffle 时间**。
> - 「**CV 分数和测试分数差很多说明什么？**」→ 三类原因：**折内泄漏**（预处理 fit 在折外）、**折间分布不同**（时间漂移 / 分组泄漏）、**调参过密**（乐观偏差）。

---

## **5. Mistakes to Avoid**

* ❌ **Using test set for tuning** – causes **data leakage** and **overestimation** of performance.
* ❌ **Not stratifying** when class imbalance exists – leads to skewed evaluation.

## 🗣️ 英文表达 / How to Say It

**30-second version**

> "I split into train, validation and test: the model fits on the training set, I tune on the validation set, and the test set is held back until the end so the final number is genuinely out of sample. When data is limited I'd rather use cross-validation than one static validation split, because every observation gets to be validated once."

**Mechanism**

> "For classification I stratify the splits so the class balance is preserved in every fold, which matters a lot when the event rate is low — otherwise one fold can end up with almost no positives."

**If they push back**

> "A common pitfall is tuning on the test set. That's leakage, and the number you report stops being an out-of-sample number. The related trap is fitting the preprocessing before splitting: standardisation, WOE binning, imputation and SMOTE all have to happen inside the training fold. And if there's a time dimension, I'd use an out-of-time split rather than a random one, because claims and policies drift."
