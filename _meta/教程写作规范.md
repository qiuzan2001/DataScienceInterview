# 教程写作规范（教学形式）

> **目标**：把读者**从「看不懂」带到「能讲给别人听」**。
>
> 这是**结构规范**，管「讲什么、按什么顺序讲、讲到什么程度」。
> 句子层的文风要求见 §7（去 AI 腔调）。语言政策（中文讲解 / 英文术语）见 [[写作规范]]。
>
> **方法论来源**：本规范改编自 FRM-Vault 的 `DEEP-NOTE-AUTHORING.md` 与 `ANTI-AI-STYLE.md`
> （含其援引的 worked-example effect、cognitive load、conceptual change 等教学研究线索）。
> 本库的差异：终点不是「考试答对」，而是**面试时能开口讲出来**。

---

## 0. 一条判断标准

> 读完一篇笔记，读者应该能**合上笔记，用自己的话把这件事讲给一个不懂的人听**。
>
> 做不到，就是没写完——不管内容多全、引用多准。

**「空洞」的四个典型症状**（本库曾全部命中）：

| 症状 | 表现 | 根因 |
|---|---|---|
| 定义开场 | 第一段就是「X 是……」 | 读者没有「为什么需要它」的抓手 |
| 有公式没直觉 | 公式旁边只有符号解释 | 没见过这个东西长什么样、在干什么 |
| 有结论没演算 | 「可以用 A 算」但从没算过一遍 | 读者无法自己复现，只能背 |
| 有知识点没误解 | 全是正确表述 | 不知道**别人会怎么错**，也就不知道自己有没有真懂 |

## 1. 骨架（**必填**，可按内容合并，但不得省略环节）

```markdown
# <中文名>（English Name）

## 速览 At a glance
- **速记**（硬要求，见 §2）：读者不翻别处就能读懂的一段话
- **一句面试答法**：面试官问「这是什么」时，你开口的第一句
- **术语**：`中文 | English | 一句话`

## 一、先看一个问题
用一个**具体场景**开场：手里的办法卡在哪一步。**不要用定义开场。**

## 二、核心直觉
大白话讲清机制，先不堆公式。若用类比，说明**哪里像、哪里不像**。

## 三、机制
### 3.1 定义与逐项说明（公式与每个符号紧贴写）
### 3.2 它是怎么来的（逐步推导，标出关键一步）
### 3.3 变形与口径（不同写法、参数化、软件口径差异）

## 四、算一遍
**一个完整、可复算、数字对得上的例子**，每步给理由，最后做一次条件检验。

## 五、什么情况下会失灵
承重假设是什么；撤掉它会出现什么**具体后果**。

## 六、常见误解
每条按 **错误想法 → 为什么容易这么想 → 错在哪一步** 写。

## 七、面试怎么答
30 秒版 / 2 分钟版 / 会被追问到哪。

## 八、真题与自测
保留既有的 `### Q: "..."` 真题问法块与题库链接。

## 🔤 本页术语 / Key Terms

## 🔗 相关
```

**已有的固定块不要动**：`<!-- priority-banner -->`、`<!-- real-exam-questions -->`、
`## 📖 标准定义`、`## 🗣️ 英文表达 / How to Say It`、frontmatter。

> `📖 标准定义`（教材原文）与 `一、先看一个问题` **不冲突**：前者是「权威措辞，面试要用」，
> 后者是「学习入口，帮你理解」。**顺序上问题在前、定义紧随其后**，因为先有疑问再给标准答案才记得住。

## 2. 速记（硬要求）

两条验收**必须同时成立**：

1. **没学过的人读完它**，就知道这条在讲什么、大框架是什么；
2. **学过的人复习时读完它**，就能想起本篇所有核心结论。

具体要求：

- **不许出现裸编号**。「1.2 判…」「条款 1–3」这类写法一律不合格——读者不知道 1.2 是什么。
- **不许出现要翻回去才懂的指代**。「见 §3」「详见前文」不是内容。
- **篇幅由内容决定**：短条目 80–150 字，覆盖多个主题的可以到 250 字。
- **禁止**写「介绍了…」「…很重要」这类空话；也**不要**把正文要点逐条抄一遍——那是目录。

**范例对照**

❌ `逻辑回归是 GLM 的一种，用在二值结局变量时。它建模事件发生的概率。`
（正确但空洞：读者学完不知道它为什么存在、什么时候会坏）

✅ `二值结局时不能直接对概率做线性回归——概率被卡在 0 和 1 之间，而直线会跑出去。`
`逻辑回归的做法是把概率先换成 odds 再取对数，这一步把取值范围从 (0,1) 拉到整条实数轴，`
`于是可以用线性预测子。代价是系数只能在 log-odds 尺度上解释（exp(β) 是 odds 倍数），`
`而且当某个变量能完美分开两类时，系数会跑到无穷——这时要用 Firth 惩罚而不是普通 MLE。`

## 3. 各环节的写法要求

### 3.1 先看一个问题（**替代定义开场**）

- 用**具体场景**：数字、决策、卡住的那一步。
- 反例：`久期是……` → 正例：`两只债券今天价格相同，收益率都上升 25bp，为什么其中一只跌得更多？`
- 本库用**面试官的真实问法**开场最自然：直接引 `### Q:` 的原话，然后说「这句话背后在考什么」。

### 3.2 核心直觉

- 先讲**机制**，别急着上公式。
- 用类比时写明**边界**：「像……，但不一样的地方是……」

### 3.3 机制

- **公式与符号紧贴**：写完公式立刻逐符号解释，不要让读者去别处找（就近解释能降低认知负荷）。
- 先定义基本量，再讲增量。
- 推导**标出关键一步**：哪一步是「转念一想」的地方，其余可以快。

### 3.4 算一遍（**最容易被省略、也最不能省的一环**）

- 必须有**一个完整例子，数字从头算到尾，读者能自己复现**。
- 每步给理由（为什么这一步这么做），不是只给结果。
- 结尾做**条件检验**：换一个条件，结论会怎么变。
- 有教学研究支持「先给完整例题，再逐步撤提示」，但**前提是例题本身算得对**——数字要自己验算。

### 3.5 什么情况下会失灵

- 写清**承重假设**（去掉它整套就塌的那个假设），以及**撤掉后的具体后果**。
- 不要写「有一定局限性」这种空话；要写「如果 X 不成立，预测会偏高约 Y%」。

### 3.6 常见误解（**本库最缺的一环**）

每条严格三段式：

1. **错误想法**（写成读者真会说的那句话）
2. **为什么容易这么想**（来源往往是某个近似或某个常见场景）
3. **错在哪一步**（指出具体是哪个推理跳错了）

题库里的「❌ 错误答案」是**面试场景**的错答；本节的误解是**理解层面**的错解。两者都要有。

## 4. 按目标选型

| 内容类型 | 必须有 | 可以简省 |
|---|---|---|
| **公式/推导型**（如 GLM、AdaBoost、CCP） | 逐步机制 + **可复算全例** + 条件检验 | 类比可短 |
| **概念/判断型**（如共线性、缺失值机制、模型选择） | 有依据的情境 + 反例 + 机制解释 | 不硬造数字 |
| **工程/流程型**（如 SAS 语句、调参配方） | 可运行的完整片段 + 每步作用 | 不强行推导 |
| **混合型** | 分别落实两类要求 | — |

---

## 5. 新手 vs 熟练

- **新手**（第一次看这个主题）：先看完整例题或完整情境分析，再逐步撤掉提示。
- **熟练**（复习）：可以从「哪里会错」或「迁移到别的场景」起手，再回头补机制。
- 本库**默认按新手写**（因为面试准备多半是第一次系统学），但在 `## 七、面试怎么答` 里给出熟练者要的取舍。

---

## 6. 「越学越清晰」的三条结构原则

1. **每节开头一句话说这节要解决什么** —— 读者知道自己在哪、要去哪。
2. **不重复**：同一件事只在最合适的一节讲透，别处只引用结论（不要每节都总结一遍）。
3. **层层递进而非并列**：问题 → 直觉 → 机制 → 演算 → 边界 → 误解，后一节要用到前一节的结论。

## 7. 去 AI 腔调（句子层）

**验收口径**：读起来该像**一个懂行的人写给同事看的讲解**，不是「一份正确的文档」。
这是**加权问题不是零容忍**：先问「这句话有没有信息」，再问「像不像 AI」。

### 十条改法（按性价比）

| # | 症状 | 改法 |
|---|---|---|
| 1 | **段尾升华式评价**（「由此可见其重要性」） | 尾句是复述就删；有**新结论或新条件**才留 |
| 2 | **抽象名词主语**（「该机制的存在使得…」） | 还原成「谁做了什么」；一句话「的」超过 3 个就拆 |
| 3 | **「不是 A，而是 B」** | 全篇最多一处，且 A 必须是**读者真会犯**的误解 |
| 4 | **三连对称**（「准确、稳健、高效」） | 真有三个才写三项；有就让颗粒度不对称 |
| 5 | **句长均匀** | 一段里至少一次明显短句（5–8 字判断句）和一次长句（30+ 字推导） |
| 6 | **万能连接词**（「值得注意的是」「综上所述」） | 删一半；读不通说明缺的是内容不是连接词 |
| 7 | **空泛评价词**（「至关重要」「显著提升」） | 换成量 + 方向 + 条件；答不上就删 |
| 8 | **同概念换词**（机制/体系/框架/范式） | 一个概念只用一个词；**术语重复是优点** |
| 9 | **替读者说蠢话再纠正** | 只处理最重要的一个反例 |
| 10 | **「挑战与展望」式收尾** | 换成：哪些条件会失效、失效后错多少、还剩什么没讲 |

### 不适用（这些**看着像 AI 味但必须保留**）

1. **固定格式块**：`速览`、`📖 标准定义`、`🗣️ 英文表达`、`🔤 术语`、两个 HTML 注释块 —— 一个字符都不要动。
2. **重复关键定义与符号说明**：每节重申是让读者能跳读的脚手架，不是段尾总结。
3. **真正的并列清单与表格**：步骤、参数、条件对照用列表优于散文。
4. **明确的小节标题**：教学文依赖可定位性。
5. **术语首次出现写「中文（English）」**：这是本库规范，不是翻译腔。
6. **适量的节间指代**（「这里要用到上一节的条件」）：是脚手架；句句「原文说」才违规。
7. **公式、完整算例、条件检验**：这是规范要求的产物。
8. **来源与页码、诚实的「未验证」标注**：摊开不确定性，与 AI 的「堵住所有反驳」相反。
9. **真有三个并列对象时的三项**。
10. **术语与标点高度一致**：不要为了「人类感」故意制造不一致。

- *Wikipedia:Signs of AI writing* / *Wikipedia:AI生成文的特徵* —— AI 词表、否定平行、rule of three

## 8. 写完逐条自查

- [ ] **速记自足**：没学过的人知道在讲什么、大框架；学过的人能想起全部核心结论。**无裸编号、无「见 §x」**，不是目录。
- [ ] **第一段是问题，不是定义**。
- [ ] **有核心直觉**，且类比写明了边界。
- [ ] **公式旁逐符号解释**，推导标出了关键一步。
- [ ] **有可复算的全例**，数字自己验算过；**有条件检验**。
- [ ] **写清了承重假设与失效后果**（具体后果，不是「有局限性」）。
- [ ] **常见误解三段式**齐备（错误想法 → 为什么这么想 → 错在哪一步）。
- [ ] **没有段尾升华、抽象主语、三连排比、万能连接词**。
- [ ] **固定块未被破坏**（banner / 真题问法 / 标准定义 / 英文表达 / 术语）。
- [ ] **中文讲解达标**（`python3 _meta/tools/lang_audit.py` ≥60%）。
- [ ] **引文仍逐字**（若动了含引文的段落，跑 `python3 _meta/tools/verify_quotes.py`）。
