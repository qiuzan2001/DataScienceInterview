# ID3 算法：把熵与信息增益算到能手工复现（ID3 Algorithm）

<!-- priority-banner -->
> [!important] 优先级 **⭐⭐ 高频** ｜ 重点：信息增益・熵三种视角
> 🚀 捷径：[[02. 三条学习路径]] ・ 📋 公式：[[04. 公式速查卡]] ・ ✅ 自测：[[99.3 决策树]] ・ 🔎 追问：[[05. 高频追问 TOP 30]]

## 速览 At a glance

**速记**

ID3 在每个节点上挑一个属性把样本切开，标准是**信息增益（information gain）**：父节点的**熵（entropy）**减去各子节点熵按样本占比的加权和，也就是「知道这个属性之后能省下多少比特」。熵只跟类别比例有关，纯节点是 0、两类各半是 1 bit，单位是比特。麻烦在于增益对属性的**取值个数**很敏感，取值越多越容易虚高：本页算例里「城市」5 档拿到 $0.570951$ bits，「近 3 年有出险」只有 $0.256426$ bits，ID3 会选城市，而城市那点纯度是每格 2 笔样本碰巧凑出来的。流程是递归的——选属性、按取值分叉、在每条分支里删掉这个属性再来一遍；节点纯、属性用完、分支为空，三种情况就停，原版没有剪枝，噪声会把树拉得很深。治这个偏置的是 C4.5 的增益率。

**一句面试答法**

> "ID3 picks the split that maximizes information gain — the parent's entropy minus the weighted entropy of the children, measured in bits. The catch is that gain is biased toward attributes with many distinct values: a high-cardinality feature can carve the data into small, nearly pure groups and score high without generalizing. That bias is what C4.5 divides out with the split information."

**术语**

| 中文 | English | 一句话 |
|---|---|---|
| 熵 / 信息熵 | entropy | $-\sum_c p_c\log_2 p_c$，单位比特，纯节点为 0 |
| 信息增益 | information gain (IG) | 父熵 − 子熵加权和，读作「省下的比特数」 |
| 分裂后的加权不纯度 | weighted impurity after split | $\sum_v \frac{\lvert S_v\rvert}{\lvert S\rvert}H(S_v)$，按分支样本占比加权 |
| 分裂信息 | split information (SI) | 只看「切了几块、每块多大」，不看标签 |
| 增益率 | gain ratio (GR) | $\mathrm{IG}/\mathrm{SI}$，C4.5 的分裂准则 |
| 多取值偏置 | bias toward multi-valued attributes | 属性取值越多，增益越容易虚高 |
| 贪心分裂 | greedy split | 只看当前节点的增益最大，不回溯 |
| 多数类回落 | majority-class fallback | 属性用完或分支为空时，用多数类当叶子 |

## 一、先看一个问题

手上有 10 笔车险保单：**6 笔续保、4 笔不续保**。要建一棵树给业务看，就得决定根节点这一刀砍在哪个特征上。候选有四个，先把主要的两个摆出来：

- **近 3 年是否有出险**：2 个取值
- **城市**：5 个取值（上海、北京、广州、杭州、深圳），每城 2 笔

另外两个是**是否新车**（是 6 / 否 4）与**是否自动续保**（是 4 / 否 6）。它们也是候选，本节的算例只把前两个算细（另两个的增益在名次表里一并给出：$0.046439$ 与 $0.019973$，都低于 $0.05$，翻不了名次）。这两个弱候选的用处不在这一页——[[7.2.3.3 C4.5 Algorithm|C4.5 篇]]要靠它们才看得出「平均增益门槛」在做什么。

业务上的直觉没有悬念：出险跟续保的关系，是这家公司每年花几百万精算费去测的东西；城市只是记录字段。但把四个候选都算一遍会得到一个反直觉的名次：**ID3 会选城市**，因为城市的增益最高。

卡住的这一步在这里：**增益这个分数的刻度不是所有属性通用的**。城市把 10 笔切成 5 个格子、每格 2 笔，其中 3 个格子的标签恰好一致，它们的熵就是 0——这 3 个 0 会把加权子熵压得很低，增益于是被抬起来，而这一点跟「城市有用没用」完全无关。

第四节会把两个数从头算出来（$0.570951$ 对 $0.256426$），并且顺手把「城市切成 2 档、5 档、10 档」三种情形的增益并排放在一张表里——加上档数，同一个变量的分数会一路往上漂。至于怎么把这个漂移修掉，是 [[7.2.3.3 C4.5 Algorithm|C4.5 的增益率]]那一篇的事。

顺带定一下本页的分工：分裂准则的全景和「为什么建树不能用误分类率」在 [[7.2.2 Decision Tree]]，Gini 与回归树在 [[7.5 CART Algorithm]]，**本页只负责把熵与信息增益算到你能在一张纸上复现**。题库里的落点是 Q2「信息增益怎么算？」与 Q7「为什么信息增益偏爱取值多的特征？」，两道题的答案都能从下面第五步的数字里直接念出来。

## 📖 标准定义

> **教材原文 · PSL §12.3 Misclassification Rate vs. Entropy（页面 w12_3_compare.html）**（<https://liangfgithub.github.io/PSL/w12/w12_3_compare.html>）
> > "Crucially, the gain in the impurity measure will be positive if the function f is strictly concave. This property ensures that the difference between impurity measures at the parent node and the child nodes is always positive when evaluating the gain."
> >
> > "The misclassification rate (blue curve) is piecewise linear, while entropy (red curve) is strictly concave."
> >
> > "However, if both p1 and p2 fall on the same side of 0.5 (for instance, both on the left side), using the misclassification rate results in a zero gain because there is no additional benefit gained from the split. Conversely, entropy (and Gini index) consistently yield positive gains, encouraging the creation of pure nodes."
> >
> > "In summary, when constructing the tree, it is advisable to use either entropy or the Gini index as impurity measures because they are strictly concave functions. They encourage the creation of pure nodes."

**标准记法**：以两类、负面类比例 $p$ 记：误分类率 $f(p) = \min(p, 1-p)$（分段线性，$p = 0.5$ 处不可导）；熵 $f(p) = -p\log p - (1-p)\log(1-p)$（严格凹）。严格凹保证 $f\big(\frac{n_R p_{t_R} + n_L p_{t_L}}{n_R+n_L}\big) \ge \frac{n_R f(p_{t_R}) + n_L f(p_{t_L})}{n_R+n_L}$，故增益 $\Phi > 0$。

**中文解释**：误分类率是分段线性的，当左右子节点的多数类相同时增益为 0，树「看不出」这次分裂的价值；熵（和 Gini）严格凹，由 Jensen 不等式保证任何分裂的增益都严格为正，因此倾向把节点越切越纯。所以建树用熵/Gini，剪枝阶段可以换回误分类率。

> 完整条目与更多来源见 [[定义原文库#C16. 误分类率 vs 熵（严格凹 vs 分段线性）|C16. 误分类率 vs 熵（严格凹 vs 分段线性）]]

## 二、核心直觉

下面把镜头拉近到 **ID3 的心脏——「选分裂」这个循环**，并解释它每一块数学为什么必要。
数学保持在本科可接受的难度，但把每一个逻辑缺口都补上，让你能在一张白纸上自己把算法重新推出来。

### 分裂要回答的三个问题

想象你站在一个节点上，手里有 $k$ 个候选问题（属性）。
你想要的是那个能让子节点**尽可能纯（pure）**的问题——因为子节点越纯，往下每条分支上**还需要问的问题就越少**。

所以我们需要的三件东西是：

1. ♦ **一把衡量纯度 / 不纯度的尺子**（→ *熵 entropy*）。
2. ♦ **一条把不纯度折算成「每个候选项一个分数」的规则**（→ *信息增益 information gain*）。
3. ♦ **一种更新训练集并递归下去的办法**。

ID3 核心循环里的全部内容，无非就是把这三条写成了公式。

### 2.1 编码长度视角

假设你必须把一个随机样本的类别标签通过二进制信道发出去。
任何编码方案能达到的**最小期望比特数**就是香农熵（Shannon entropy）：

$$
H(S)=\!\!\sum_{c=1}^{C}p(c)\log_2\!\bigl(\tfrac1{p(c)}\bigr).
$$

* 所有样本同类时：$p=1$ ⇒ $H=0$ 比特（没有任何不确定性）。
* 各类等概率时：$H$ 最大 ⇒ 需要最多比特来编码。

>[!Example ]-   🧠 Deeper Explanation
>  熵这个概念最早来自*信息论*（Claude Shannon, 1948）。想象你要在一条线上发数据（比如类别标签）——你希望用尽可能少的比特发完。
>  
>  假设要发一个样本的类别标签。如果有 3 个类别，并且：
>  
>  * 类别 A 出现 50% 的时间，
>  * 类别 B 出现 25% 的时间，
>  * 类别 C 出现 25% 的时间，
>  
>  一个好策略是**给常见的类别分配更短的二进制码**，给罕见的分配更长的码（这就是 Huffman 编码）。例如：
>  
>  * A → `0`
>  * B → `10`
>  * C → `11`
>  
>  这样在大量传输中，你的*平均每条消息比特数*就降下来了。
>  
>  ##### 为什么熵能量化这件事？
>  
>  公式：
>  
>  $$
>  H = -\sum p(c) \log_2 p(c)
>  $$
>  
>  给出的正是**发送一个类别标签所需的期望比特数**，前提是做完美压缩。
>  
>  > ⚠️ 重要：这里之所以出现对数，是因为对数在度量一次选择里包含多少*信息*——概率越小 = 越意外 = 信息越多 = 比特越多。
>  
>  ---
>  
>  #### ✅ 要点：
>  
>  * **熵 = 把类别标签「发出去」有多贵**。
>  * **熵低 ⇒ 需要的比特少 ⇒ 类别可预测**。
>  * **熵高 ⇒ 需要更多比特 ⇒ 类别很不确定**。
>  
>  ---
>  
>  #### 🔁 与决策树的类比：
>  
>  * 树里的每一次判断（测试），都相当于*揭示了若干比特*的标签信息。
>  * 目标是选出那些能**最大幅度减少「猜类别」所需比特数**的属性（分裂）。
>  
>  所以当 ID3 选出一个信息增益高的分裂时，它挑的正是那个能把你总通信成本压到最低的分裂。
>  
>

### 2.2 问答游戏视角

你在玩「猜类别」游戏，每个是/否问题花掉 1「比特」。
熵就是你还需要的**最好情况下的平均问题数**。

>[!Example]- Example - 「猜盒子里是哪种动物」
>  
>  假设有人偷偷选了下面四种动物之一，概率由历史数据估计得到：
>  
>   | 动物        | 概率        ||
>   | ----------- | ----------- |-|
>   | 🐶 Dog      | 40 %        ||
>   | 🐱 Cat      | 30 %        ||
>   | 🐰 Rabbit   | 20 %        ||
>   | 🦔 Hedgehog | 10 %        ||
>  
>  你唯一的手段是问**是/否问题**，例如：
>  
>  * 「它会叫（bark）吗？」
>  * 「它是常养在室内的哺乳动物吗？」
>  * 「它体重超过 5 kg 吗？」
>  
>  每个回答花**一个比特**（一个问题）。
>  如果你把问题设计得完美，*最少*平均需要多少个比特？
>  
>  ---
>  
>  ##### 第 1 步 – 算熵
>  
>  $$
>  \begin{aligned}
>  H &= -\Bigl(0.4\log_2 0.4 + 0.3\log_2 0.3 + 0.2\log_2 0.2 + 0.1\log_2 0.1\Bigr) \\
>    &\approx 1.846 \text{ bits}.
>  \end{aligned}
>  $$
>  
>  所以 $\mathbf{1.846}$ 是**理论下界**：再聪明的提问策略，平均也不能比它更低。
>  
>  ---
>  
>  ##### 第 2 步 – 设计一棵接近最优的问题树
>  
>  一种 Huffman 式的策略：
>  
>  1. **Q1：** 「它*不是*狗？」
>     *是 → 概率 = 0.6*
>     *否 → 我们就知道它是狗。*
>  
>  2. **如果答「是」：**
>     **Q2：** 「它*不是*猫？」
>     *是 → 概率 = 0.3*
>     *否 → 是猫。*
>  
>  3. **如果还答「是」：**
>     **Q3：** 「它是兔子吗？」
>     *是 → 兔子*
>     *否 → 刺猬*
>  
>  期望问题数：
>  
>  $$
>  E = 0.4(1) + 0.3(2) + 0.2(3) + 0.1(3) = 1.9 \text{ bits/questions}.
>  $$
>  
>  只比熵的下界高一点点，正好印证了两者的联系：
>  
>  * **熵（1.846 bits）** = 最好情况下的平均问题数。
>  * **你实际设计的问题树（1.9 bits）** ≈ 实用的、接近最优的提问。
>  
>  ---
>  
>  ##### 这对理解 ID3 有什么帮助
>  
>  ID3 选属性分裂时，行为和你上面设计 Q1、Q2、Q3 完全一样：
>  
>  * **挑那个「此刻」最能砍掉未来平均问题数的问题**。
>  * 然后在每条分支里继续递归。
>  
>  熵是尺子；信息增益是「先问这个属性能省掉多少个问题」。
>  
>  ---
>  
>  **记住这点**：把决策路径想象成一场高速的「猜动物」游戏，ID3 的*贪心（greedy）*本质（以及信息增益的含义）会比只看公式具体得多。
>  
### 2.3 误判概率视角

二分类时，$H(p)$ 是 $p(1-p)$（伯努利试验的方差）的单调变换。
两者都在 $p=0.5$ 取到峰值。所以最小化熵，等于把叶子推向「误分类风险低」的方向。

> [!Example]- 🧠 Deeper Explanation
>   
>   假设你在决策树里走到这样一个节点：
>   
>   * 90% 的样本是类别 A，
>   * 10% 是类别 B。
>   
>   你不再往下分裂——那么你会把**多数类** A 作为这个叶子的预测。
>   
>   在这里把一个新样本判错的概率正好是：
>   
>   $$
>   \text{Error} = 1 - p_{\text{majority}} = 0.1
>   $$
>   
>   这就是**误分类率（misclassification rate）**。
>   
>   现在看熵怎么说：
>   
>   $$
>   H(p) = -p \log_2 p - (1-p) \log_2(1-p)
>   $$
>   
>   * 当 $p = 0.9$ 时，$H ≈ 0.47$
>   * 当 $p = 0.5$ 时，$H = 1$
>   * 当 $p = 1$ 时，$H = 0$
>   
>   所以熵在你「确定」时（p = 0 或 1）最低，在你「完全不确定」时（p = 0.5）最高。这与**出错的可能性**和**方差**完全对应。
>   
>   ---
>   
>   #### 📊 为什么要提方差 $p(1-p)$？
>   
>   因为它是一个**更简单的不纯度度量**，决策树里也常用（比如 CART 就用它，而不是熵）。和熵一样：
>   
>   * 在 $p = 0$ 和 $p = 1$ 处方差为 0，
>   * 在 $p = 0.5$ 处最大
>   
>   所以最小化这两者中的任何一个，都能减少类别混淆的机会。
>   
>   ---
>   
>   #### ✅ 要点：
>   
>   * **熵与节点上的期望分类误差高度同步**。
>   * 当你分裂并降低熵时，你也在**降低期望误分类率**。
>   * 这让熵不只是一个数学概念，而是一个直接可用的实务工具。

**这里像什么、不像什么**：熵像「二十问」里你最少还得问几句——问得越准，剩下的不确定就越少。**像的地方**是每一次回答（每一次分裂）都真的砍掉一块不确定性，而这块的大小可以算出来。**不像的地方**是二十问里问题随你设计，ID3 只能问「这个属性取什么值」；而且问题集是数据给的，你没法临时发明一个更好问的问题。另外，二十问里问 1 句话就花 1 个比特，熵是**理论下界**——真实的提问方案一般比它贵一点（上面的动物例子里，下界 1.846，实际 1.9）。

## 三、机制

### 3.1 定义与逐项说明

#### 熵

$$
H(S) = -\sum_{c=1}^{C} p(c)\,\log_2 p(c)
$$

逐项读：

* $C$：当前节点 $S$ 里的类别数（二分类时 $C=2$）。
* $p(c)$：$S$ 中类别为 $c$ 的样本占比，$\sum_c p(c) = 1$。
* $\log_2$：底数取 2，所以 $H$ 的单位是**比特（bit）**；约定 $0\log_2 0 = 0$（实现里要显式处理，否则当机）。
* 取值范围 $0 \le H(S) \le \log_2 C$：纯节点 0（所有样本同类），各类等比例时顶到 $\log_2 C$。

同一件事的三种写法：$-\sum_c p\log_2 p$、$\sum_c p\log_2 \frac{1}{p}$（2.1 里那个形式），以及把 $p$ 换成正类比例 $p$ 的二分类写法 $-p\log_2 p-(1-p)\log_2(1-p)$（2.3 里那个）。三者在数学上完全一样，2.1 和 2.3 保留原写法，是为了让「编码」「误判」两个直觉各自贴着自己的公式。

#### 分裂后的加权不纯度

如果按属性 $A$、以取值 $v_1,\dots,v_r$ 分裂，你就把 $S$ 划分成 $S_{v_1},\dots,S_{v_r}$。
**分裂后的期望不纯度**是

$$
\overline{H}(S,A)=\sum_{i=1}^{r}\frac{|S_{v_i}|}{|S|}\,H(S_{v_i})
$$

它就是你「问完这个问题之后」预期要付的熵账单。逐项读：$|S_{v_i}|/|S|$ 是第 $i$ 条分支分到的样本比例（权重），$H(S_{v_i})$ 是那条分支内部的混乱度。**权重那一步最容易记错**——不按分支大小加权的话，一个只装 1 笔样本的纯分支会「假装」贡献很大。

#### 信息增益与单位

$$
\operatorname{Gain}(S,A)=H(S)-\overline{H}(S,A)\quad\text{(measured in *bits*).}
$$

* $H(S)$：父节点的熵，是这次比较的**基线**。
* $\overline{H}(S,A)$：分裂之后的期望熵。
* 差值单位是**比特**，读作「知道 $A$ 的答案后省下的期望比特数」。

因为第二项永远不大于第一项，

* **Gain ≥ 0**，而且
* 它正好等于「知道 $A$ 的答案后**省下的期望比特数**」。

于是贪心规则就是：**挑那个能省下最多比特的属性**。

#### 停止条件

ID3 的原版没有剪枝，停下来全靠这三条（它们逐条对应下面的伪代码）：

| 停在哪一步 | 触发条件 | 返回什么 | 为什么必须写 |
|---|---|---|---|
| 节点已纯 | $S$ 中所有样本同类 | 该类的叶子 | 再分也没有信息可省，Gain 恒为 0 |
| 属性用完 | 候选属性集为空，但类别仍混杂 | **多数类**叶子 | 保证树有限，且任何输入都能给一个标签 |
| 分支为空 | 某个取值 $v$ 在训练数据里从未出现 | **多数类**叶子（挂在这一支上） | 不写它就会造出一个没有任何样本、也没有标签的空节点 |

### 3.2 它是怎么来的：从「省比特」到「增益」，以及贪心为什么成立

**关键一步在这里**：熵是「把标签发出去要多少比特」，所以每问一个属性、数据被分到几支之后，你还需要的**期望**比特数就是各支熵的加权和 $\overline{H}(S,A)$。两者的差就是这次提问省下来的比特——增益的物理含义由这一步确定，它不是一个拍脑袋的打分函数。

剩下的推导很短：

1. 比较两个候选属性时，父节点 $H(S)$ 是同一个数。所以**名次完全由 $\overline{H}(S,A)$ 决定**：加权子熵越小，增益越大。
2. 因此「最大化 Gain」和「最小化加权子熵」是同一件事，伪代码里写哪个都行。
3. 也可以换个词：增益等于标签 $y$ 与属性 $A$ 的**互信息（mutual information）**——「知道 $A$ 之后 $y$ 的不确定性掉了多少」。这就是它非负的来源（互信息不为负），也是它在连续变量、特征筛选里到处露脸的原因。

**为什么可以贪心？——一个最优子结构的论证**

* **目标**：最小化走到「纯」所需的*期望*比特数（问题数）。
* **熵是可加的**：总比特 = 根节点那个问题的比特 + 到达的子树里的比特。
* 因此，**要让总和最小，必须先让根节点那一项最小**，不管子树将来会怎样。
* 根节点定下来之后，问题就**分解**成 $S_v$ 上互相独立的子问题。

这就是*最优子结构性质（optimal-substructure property）*的一个实例——和 Huffman 编码、Dijkstra 这类算法背后的原理相同。因此贪心选择是有道理的。

注意（nota bene）：如果你的不纯度度量**不可加**，这个性质就不成立，此时增益也就不再与全局最优对齐。

#### 实际算法循环（伪代码）

```text
function ID3(S, Attributes):
    if all examples in S share class c: return Leaf(c)
    if Attributes is empty: return Leaf(MajorityClass(S))

    bestA ← argmax_{A∈Attributes} Gain(S, A)
    node ← DecisionNode(bestA)

    for each value v of bestA:
        Sv ← {examples in S with bestA = v}
        if Sv is empty:
            node.addBranch(v, Leaf(MajorityClass(S)))      # missing-value path
        else:
            node.addBranch(v, ID3(Sv, Attributes \ {bestA}))
    return node
```

### [[7.2.2.3.1.4 ID3 Complete Code]]（可运行的完整实现）

#### 循环里的几个「坑」

| 细节                                                 | 为什么要有它                                                                | 漏掉会怎样                                                         |
| ------------------------------------------------------ | ---------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 递归时把 bestA **从属性集合里删掉** | 防止无限循环，并让每条路径成为若干不同测试的*合取（conjunction）*。 | 你可能会在更下面再把同一个问题问一遍 ⇒ 白做功，甚至出现环。 |
| **空子集检查**                                   | 某些属性取值可能从未在训练数据里出现。                    | 没有默认叶子，你会造出一个没有类别标签的空节点。          |
| **属性集为空时退到多数类**       | 问题问完了，但类别仍然混杂。                       | 保证树是有限的，并且永远能返回一个类别。                                   |

#### 平局怎么处理

偶尔会有两个属性增益完全相同。好的做法是：

1. **优先选取值个数少的那个**（测试更简单 → 过拟合风险更小）。
2. 若还是平局，就按字母序或列顺序取第一个（保证确定性 determinism）。

### 3.3 变形与口径

#### 在同一个循环里处理连续特征

ID3 是为类别数据而生的，但稍微改一下逻辑就能延伸到数值特征：

1. 把属性 $A$ 的取值**排序**。
2. **试每一个边界**——取在类别标签发生变化的两点之间，例如阈值 $\tau$。
3. 对每个二分「$A ≤ τ$ ?」计算信息增益。
4. 保留增益最大的那个 τ，把它当成一个两值属性。

核心循环（熵 → 增益 → 最优分裂 → 递归）完全不动。代价是每个节点都要重排一次（$O(n\log n)$），而且阈值也是数据里挑出来的，照样会过拟合——C4.5 后来把「排序一次、顺着扫」这套做成了标准动作，见 [[7.2.3.3 C4.5 Algorithm]]。

#### 与其他不纯度准则的关系

熵并不神圣；循环里真正重要的是**不纯度单调下降**。

| 准则                   | 公式                    | 循环要改什么吗？                                               |
| --------------------------- | -------------------------- | --------------------------------------------------------------- |
| **Gini**                    | $G(S)=\sum_c p(c)(1-p(c))$ | 把熵换成 Gini，其余完全一样。                      |
| **误分类率（misclassification error）** | $1-\max_c p(c)$            | 能用，但不敏感；实践中长出来的树更差。 |

补充一点（PSL §12.3）：**熵与 Gini 都是严格凹（strictly concave）函数**，所以只要子节点比父节点更纯，增益**恒为正**；而**误分类率是分段线性的**——如果一次分裂后两个子节点都落在 $p = 0.5$ 的**同一侧**（多数类没变），它的增益**恰好为 0**，算法会完全看不出这次分裂的价值。这就是「**建树用熵 / Gini，剪枝才可以用误分类率**」的由来。

任何「**在纯节点处为 0、且对 $p$ 凹（concave）**」的不纯度度量，都能满足上面的最优子结构论证，因此贪心逻辑成立。

#### 对数底数与报数口径

| 口径 | 写法 | 要注意什么 |
|---|---|---|
| 底数 | 熵用 $\log_2$、PSL 的 deviance 用 $\ln$、`rpart` 的 `split="information"` 用 $\log$ | 换底数等于把所有熵乘一个常数，**增益的名次不变**；但跨论文/跨软件报数字时必须说清底数 |
| 连续变量的离散化 | 取相邻取值中点当阈值 | 阈值来自训练数据，换一份样本就可能换位置 |
| 报数习惯 | 增益写成 `0.256426 bits` | 差距常常在小数点后第三位（本页算例 $0.256426$ 对 $0.570951$），只写两位会把两个候选看成一样 |

#### 结合循环看复杂度分析

设总样本数 $n$，属性数 $m$，每个属性平均取值数 $k$。

* **父集合的熵**：类别计数算一遍 → $O(n)$。
* **每个属性**：需要每个取值下的类别计数。从头扫一遍 $S$ 填一张二维表是 $O(nm)$。
  *省内存的技巧*：把所有属性的计数放进一组哈希表，一次遍历里同时累加。
* **选最大增益**：$O(mk)$（相比 $nm$ 通常可以忽略）。

所以*每一层*的工作量是 $O(nm)$。
如果树的深度是 $d$、且每次分裂大致把 $n$ 对半砍，总量就是 $O(nm d) ≈ O(nm \log n)$。

#### 要留在脑子里的心智模型

```
ENTROPY = how many “20-questions” still needed
GAIN    = how many questions you save by asking attribute A next
GREEDY  = keep asking the question that chops off the most uncertainty right now
```
对应的中文读法：**熵**（entropy）= 还差多少个「二十问」才能问出答案；**增益**（gain）= 接着问属性 A 能省下多少个问题；**贪心**（greedy）= 永远先问「此刻能砍掉最多不确定性」的那个问题。

这三种量握在手里，你就能重新走一遍 ID3、C4.5、CART 的设计动机，也能自己定一套分裂准则。

## 四、算一遍

用第一节那 10 笔保单，把候选属性的增益从头算出来：主体算「是否出险」与「城市」，另外两个弱候选的增益在名次表里一并给出。这一节的所有数字都精确到小数点后 6 位，你可以拿计算器对。

### 第 1 步：数据长这样

| 保单 | 近 3 年有出险 $A$ | 城市 $B$ | 是否新车 $C$ | 是否自动续保 $D$ | 续保 $y$ |
|---|---|---|---|---|---|
| 1 | 否 | 广州 | 否 | 否 | 续 |
| 2 | 是 | 上海 | 否 | 是 | 续 |
| 3 | 否 | 杭州 | 是 | 否 | 续 |
| 4 | 是 | 上海 | 否 | 是 | 不续 |
| 5 | 是 | 深圳 | 是 | 否 | 不续 |
| 6 | 否 | 北京 | 否 | 是 | 续 |
| 7 | 否 | 深圳 | 是 | 否 | 不续 |
| 8 | 否 | 广州 | 是 | 否 | 续 |
| 9 | 是 | 北京 | 是 | 是 | 不续 |
| 10 | 否 | 杭州 | 是 | 否 | 续 |

四个候选的分布先数清楚（**这一步不能省**，后面所有熵都从这里来）：

* $A$（是否有出险）：**是** 4 笔（1 续 / 3 不续），**否** 6 笔（5 续 / 1 不续）。
* $B$（城市）：上海 2 笔（1 续 / 1 不续）、北京 2 笔（1 续 / 1 不续）、广州 2 笔（2 续 / 0 不续）、杭州 2 笔（2 续 / 0 不续）、深圳 2 笔（0 续 / 2 不续）。
* $C$（是否新车）：**是** 6 笔（3 续 / 3 不续），**否** 4 笔（3 续 / 1 不续）。
* $D$（是否自动续保）：**是** 4 笔（2 续 / 2 不续），**否** 6 笔（4 续 / 2 不续）。
* 父节点 $S$：10 笔，**6 续 / 4 不续**。

### 第 2 步：父节点的熵

$$
H(S) = -\Bigl(\tfrac{6}{10}\log_2\tfrac{6}{10} + \tfrac{4}{10}\log_2\tfrac{4}{10}\Bigr)
= -(0.6 \times (-0.736966) + 0.4 \times (-1.321928))
= \mathbf{0.970951}\ \text{bits}
$$

对数怎么来的：$\log_2 0.6 = \ln 0.6 / \ln 2 = -0.510826/0.693147 = -0.736966$，$\log_2 0.4 = -1.321928$。检验一下量级：两类几乎对半（6∶4），所以熵应该很接近上界 1 bit，$0.970951$ 正好落在 1 的下面一点。这个数就是两个候选共同的**基线**。

### 第 3 步：候选一 —— 近 3 年有出险 $A$

两支的熵（各自算一遍，因为两支的类别比例不同）：

$$
H(S_{\text{出险}}) = -\Bigl(\tfrac{1}{4}\log_2\tfrac{1}{4} + \tfrac{3}{4}\log_2\tfrac{3}{4}\Bigr)
= -(0.25\times(-2.000000) + 0.75\times(-0.415037)) = 0.811278
$$

$$
H(S_{\text{无出险}}) = -\Bigl(\tfrac{5}{6}\log_2\tfrac{5}{6} + \tfrac{1}{6}\log_2\tfrac{1}{6}\Bigr)
= -(0.833333\times(-0.263034) + 0.166667\times(-2.584963)) = 0.650022
$$

按样本数加权（4 笔那一支的权重是 $4/10$，6 笔那一支是 $6/10$）：

$$
\overline{H}(S,A) = \tfrac{4}{10}(0.811278) + \tfrac{6}{10}(0.650022)
= 0.3245112 + 0.3900135 = 0.7145247 \approx 0.714525
$$

$$
\operatorname{Gain}(S,A) = H(S) - \overline{H}(S,A) = 0.970951 - 0.714525 = \mathbf{0.256426}\ \text{bits}
$$

读这个数：出险把「还差多少信息才能确定续不续」压掉了差不多四分之一比特。它的两个子节点都还有 0.65 到 0.81 的熵，没切干净，但这个方向是对的。

### 第 4 步：候选二 —— 城市 $B$

5 个城市的子节点熵，只要看那 2 笔标签是否一致：

| 城市 | 续 / 不续 | 子节点熵 $H(S_v)$ |
|---|---|---|
| 上海 | 1 / 1 | $1.000000$ |
| 北京 | 1 / 1 | $1.000000$ |
| 广州 | 2 / 0 | $0$ |
| 杭州 | 2 / 0 | $0$ |
| 深圳 | 0 / 2 | $0$ |

$$
\overline{H}(S,B) = \tfrac{2}{10}(1) + \tfrac{2}{10}(1) + \tfrac{2}{10}(0) + \tfrac{2}{10}(0) + \tfrac{2}{10}(0) = 0.200000 + 0.200000 = 0.400000
$$

$$
\operatorname{Gain}(S,B) = 0.970951 - 0.400000 = \mathbf{0.570951}\ \text{bits}
$$

### 第 5 步：名次表 —— ID3 会选哪个

| 候选属性 | 取值个数 | $\overline{H}(S,\cdot)$ | $\operatorname{Gain}$（bits） | ID3 的选择 |
|---|---|---|---|---|
| $A$ 近 3 年有出险 | 2 | 0.714525 | 0.256426 | 第二名 |
| $B$ 城市 | 5 | 0.400000 | **0.570951** | ✅ **被选中** |
| $C$ 是否新车 | 2 | 0.924511 | 0.046439 | 第三名 |
| $D$ 是否自动续保 | 2 | 0.950978 | 0.019973 | 第四名 |

ID3 选城市。三个 $0$ 权重地落在加权和里（$0.2+0.2+0.2$ 各乘一个 0），把 $\overline{H}$ 从 0.714525 一路压到 0.400000。**但「广州 2 笔都续保」这件事是 2 笔样本的记录，不是城市的性质**——换一批保单，广州很可能就变成 1 比 1。增益不知道这件事，它只看见 0。

对比一下两个分数：$0.570951/0.256426 = 2.2266$，城市的增益是出险的 2.2 倍。如果只看这个数，你会把根节点交给一个记录字段。修法是拿一个只由「切了几块、每块多大」决定的量当分母——**分裂信息（split information）**：

$$
\mathrm{SI}(S,B) = -5\times\tfrac{2}{10}\log_2\tfrac{2}{10} = 2.321928\ \text{bits},\qquad
\mathrm{SI}(S,A) = -\Bigl(\tfrac{4}{10}\log_2\tfrac{4}{10}+\tfrac{6}{10}\log_2\tfrac{6}{10}\Bigr) = 0.970951\ \text{bits}
$$

（$A$ 的 SI 恰好等于 $H(S)$，那是因为它的两支刚好 4∶6，跟类别比例撞了车。SI 里没有任何标签信息，这个相等是巧合，别读成「有信息」。）

分子比分母，**增益率（gain ratio）**这一层就把名次翻过来了：$\mathrm{GR}(S,A) = 0.256426/0.970951 = 0.264098$，$\mathrm{GR}(S,B) = 0.570951/2.321928 = 0.245895$。分母怎么造出这个翻转、以及它什么时候也救不了场，写在 [[7.2.3.3 C4.5 Algorithm]]。

### 条件检验：把城市切粗、切细各一遍

同一个变量的分数会随**取值个数**漂。把城市这一列换三种粒度，其余数据不动：

| 城市切成几档 | 具体切法 | 每档样本 | $\operatorname{Gain}$（bits） | $\mathrm{SI}$（bits） | 谁是冠军 |
|---|---|---|---|---|---|
| 2 档 | 一线（上海、北京、广州）vs 非一线（杭州、深圳） | 6 + 4 | 0.019973 | 0.970951 | 出险（$0.256426$ 完胜） |
| 5 档 | 原样，5 个城市 | 2 × 5 | **0.570951** | 2.321928 | **城市** |
| 10 档 | 每笔一个编号（保单号） | 1 × 10 | **0.970951** | 3.321928 | **保单号** |

三行读下来：

1. **切粗就掉分**：2 档的城市增益只有 $0.019973$，远低于出险。同一列数据、同一个含义，只是粒度粗一点，分数掉到十分之一以下——这就是「增益的刻度不是变量本身的属性」的具体样子。
2. **切到 10 档就顶到天花板**：每档 1 笔、每档必纯，$\overline{H} = 0$，增益 = $H(S) = 0.970951$。父节点的熵就是增益的**上界**，任何特征都不可能超过它。换句话说，**只要允许切得足够碎，增益一定能拿到最大值**，这跟这个特征有没有预测力无关。
3. **SI 三个值单调上升**（$0.970951 \to 2.321928 \to 3.321928$）：它正好是罚「切得多碎」那把尺子。到 10 档时 $\mathrm{GR} = 0.970951/3.321928 = 0.292285$，已经超过出险的 $0.264098$——**档数极端多的时候，增益率也压不住**。这一点 C4.5 篇会接着说。

### 第二个例子：16 笔的校验（原例，也是 [[7.2.2.3.1.9 ID3 Build Example| 9 一个验算用的数值例子（proof-of-concept）]]）

同一套三步骤换一份数据跑：某节点上有 $10$ 个正例、$6$ 个负例：

$$
H(S)= -\tfrac{10}{16}\log_2\tfrac{10}{16} - \tfrac{6}{16}\log_2\tfrac{6}{16}=0.954\text{ bits.}
$$

属性 $A$ 有三个取值，各自产生的子节点类别分布是：

| 取值 | 正例 | 负例 | 子节点熵 |
| ----- | --- | --- | ------------- |
| v₁    | 4   | 0   | 0             |
| v₂    | 4   | 4   | 1.000         |
| v₃    | 2   | 2   | 1.000         |

$$
\overline{H}(S,A)=\frac4{16}\cdot0 + \frac8{16}\cdot1 + \frac4{16}\cdot1 = 0.75
$$

$$
\operatorname{Gain}(S,A)=0.954-0.75 = 0.204\text{ bits.}
$$

如果另一个属性 $B$ 给出 $\overline{H}=0.60$，那么
$\operatorname{Gain}(S,B)=0.354$ bits ⇒ 选 $B$。
这些「小数点后几位」的数字看起来很小，但成千上万次分裂累积下来的 $0.15$ 比特差别，最终可能变成一棵浅得多的树。

完整的手算全过程（PlayTennis 那 14 天）在 [[7.2.2.3.1.9 ID3 Build Example]]，逐行代码在 [[7.2.2.3.1.4 ID3 Complete Code]]。

## 五、什么情况下会失灵

### 承重假设一：不同取值数的属性之间，增益的刻度可比

整套贪心建立在「把两个候选的 Gain 放在一起比大小」上。这只在候选的取值个数差不多时成立。

撤掉它的后果很具体：本页算例里，5 档城市的增益 $0.570951$ 是 2 档出险 $0.256426$ 的 $2.2266$ 倍，ID3 会把根节点交给城市；切到 10 档（编号）时增益直接顶到父熵 $0.970951$，任何有意义的特征都赢不了。**训练集上的增益越高，越可能只是切得越碎**——如果拿这个树去留出集，那三个纯格子大概什么都不剩。处理办法就是把「切得多碎」也计进分数（增益率），或者干脆限制取值个数。这一步由 C4.5 补上。

### 承重假设二：小格子里的「纯」代表规律

增益里的 $H(S_v)$ 是由**样本**估出来的，格子越小，这个估计越不可靠。

撤掉它的后果：一个只装 2 笔样本的格子，熵只能是 $0$（两笔同标签）或 $1$（一正一负），中间值压根不存在。本页算例里 5 个城市各 2 笔，出现 **3 个纯格子**并不稀奇（$0.2\times0$ 三项），加权熵 $0.400000$ 里有 $0.6$ 是这两笔的巧合撑起来的。样本越小，「巧合的纯」出现得越频繁，增益越乐观；等你在留出集上复核，会发现这些格子对泛化几乎没有贡献，而树已经把它们焊进了结构里。这就是决策树在小样本上必须配剪枝或交叉验证的机制原因（剪枝细节见 [[7.2.2.4. Pruning Decision Trees]]）。

### 承重假设三：属性问完了，树就该停

ID3 的停止条件只有三条（节点纯、属性用完、分支为空），**没有一条跟「泛化」有关**。

撤掉它的后果：只要属性还有、节点还没纯，它就一直分下去，直到叶子纯或属性耗尽。噪声点和离群点会因此长出只含一个样本的枝条——$n$ 笔数据、$m$ 个属性，深度上限由属性个数决定，而宽度由取值个数决定。树大、难解释、留出误差差。C4.5 保留生长循环，另加一步基于误差的后剪枝；CART 走得更远，先长满再用 $\alpha$ 剪。

### 与其他算法的边界

| 场景 | 用谁 | 为什么 |
|---|---|---|
| 属性全是类别、要一眼能读的规则 | ID3 / C4.5 | 多路分裂天然写成「属性 = 某值 ⇒ 走这支」 |
| 类别属性取值很多、还有缺失值 | C4.5 | 增益率罚多取值，分数实例加权不用丢行 |
| 需要回归、或者坚持二分 | CART | Gini / SSE + 二叉 + 代价复杂度剪枝 |
| 计算预算卡在对数上 | CART | Gini 不用对数，熵要 |

### ID3 撞墙的地方——以及 **[[7.2.3.3 C4.5 Algorithm| C4.5]]** 怎么翻过去

即便有了「熵 → 增益 → 递归」这么优雅的循环，真实数据仍会暴露 ID3 的四个弱点。Quinlan 的下一代算法 **C4.5** 保留了骨架，但为每一个弱点都塞进了聪明的绕行方案。把这些局限弄清楚，是通往 C4.5 最顺的跑道。

| 原版 ID3 的局限                                                                                                                                                         | 为什么在实践里要紧                                                                    | C4.5 的修法（预告）                                                                                                                                         |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **1. 偏爱多取值属性**<br>信息增益随不同取值个数增加而变大，于是「ZIP Code」可能压过真正有预测力但水平数少的特征。 | 分裂在训练数据上看起来很漂亮，对新样本却没用（过拟合）。           | **增益率（Gain Ratio）** 用属性自身的熵来重新缩放增益，惩罚不必要的细碎划分。                                                      |
| **2. 没有剪枝——树会爆炸**<br>ID3 会一直扩展到叶子变纯或属性用完为止。噪声或离群点于是长出很深的、只含单个样本的枝条。                       | 大树既难解释，泛化也差。                                      | **后剪枝（post-pruning）**（子树替换 / 基于误差）剪掉统计上很弱的枝条，用微小的偏差换取大幅方差下降。                        |
| **3. 处理连续特征很粗糙**<br>我们只能手工地（3.3）在每个节点、对每个数值属性去试「每一个边界」。                                                     | 每个节点重新排序是 $O(n\log n)$；而且固定阈值照样会过拟合。           | C4.5 **只排序一次**，把类别计数带着走，用一次线性扫描评估所有阈值——又快*又*不脆。                                |
| **4. 缺失值处理是全有或全无**<br>标准 ID3 要么丢掉这些行，要么训练前用众数 / 均值填掉。                                                  | 两种做法都会注入偏差：丢数据浪费样本，全局插补忽略局部上下文。 | C4.5 用**分数实例加权（fractional instance weighting）**：取值 $A=\text{?}$ 的样本按学到的概率被分数化地送进 $A$ 的每一条分支。 |

> **关键结论**：ID3 是一个出色的*第一代*算法——简单、快、好教——但它从来不是终点。
> **C4.5** 保留了它的精神（熵、贪心分裂、递归），同时把上面四个痛点都补上。
> 下一节我们会细看 **Gain Ratio**、**error-based pruning** 与 **fractional splits**，看每个小改动如何严丝合缝地嵌进你已经熟悉的那个核心循环。

## 六、常见误解

### 误解一：「信息增益越大越好」

**错误想法**：增益是分裂价值的分数，两个候选比一比，谁大选谁——分数高就是更好的分裂。

**为什么容易这么想**：在取值个数差不多的候选之间，增益确实就是好坏排序；而且它带单位（比特），「省下 0.57 个比特」这种说法听起来像一个绝对刻度，不像一个会随属性结构漂移的相对量。

**错在哪一步**：刻度不跨属性可比。增益的上界是父节点熵 $H(S)$，而**只要你把数据切得足够碎，就一定够得着这个上界**——切到每格 1 笔时 $\overline{H} = 0$，增益 $= 0.970951$，本页条件检验那张表的第三行就是这么来的。取值多的属性离上界更近，跟预测力无关。所以看到「增益最高的那个恰好也是取值最多的那个」（$0.570951$ 对 $0.256426$ 那一步），第一件事是查两者的取值个数，而不是直接下结论。

### 误解二：「熵降到很低就该停」

**错误想法**：熵 0 就是纯节点，纯了就没有信息可省，算法当然停在这里。

**为什么容易这么想**：熵的目标就是把节点切纯，而且 Gain ≥ 0 说明「越纯越低」——方向一致，于是很容易把「某个子节点熵为 0」当成「这次分裂很值」。

**错在哪一步**：把**样本量**漏掉了。一个 2 笔的格子，熵只能是 0 或 1，纯不纯完全看这两笔的标签是否碰巧一致。本页算例里广州、杭州、深圳三个格子各 2 笔、熵都是 0，加权熵 $0.400000$ 里有 $0.6$ 来自两个混合格子——换句话说，「纯」的那部分正好是最不可靠的部分。停留与否要看的不是熵有多低，而是这个分裂在没见过的样本上还剩多少收益；处理这个问题的工具是剪枝（[[7.2.2.4. Pruning Decision Trees]]）和最小叶样本数，不是「熵低就收工」。

### 误解三：「C4.5 只是在 ID3 上换了个公式」

**错误想法**：把 Gain 换成 Gain Ratio，循环照旧——所以 C4.5 ≈ ID3 + 一个除法。

**为什么容易这么想**：伪代码确实一模一样（算分 → 选属性 → 按取值分叉 → 递归），而增益率也只是在分子上做了归一，看上去是一个纯公式层面的改动。

**错在哪一步**：C4.5 一共动了四处，公式只是第一处——**分裂准则**（增益率，还要先用平均增益过滤一轮）、**连续变量**（根节点排序一次，后代节点线性扫候选阈值）、**缺失值**（分数实例加权，既不丢行也不插补）、**剪枝**（基于误差的后剪枝）。四个痛点在第五节那张表的右列里逐条对应。面试里被问到「C4.5 和 ID3 的区别」，只答增益率会丢掉一半的分数。

## 七、面试怎么答

### 30 秒版

> ID3 的每个节点都在最大化信息增益：父节点的熵减去各子节点熵按样本占比的加权和，单位是比特，读作「知道这个属性之后省下多少信息」。熵只跟类别比例有关，所以它在比较不同候选时是可加的、可算的。最大的坑是增益偏爱取值多的属性——取值多就能把数据切成又小又纯的格子，增益被抬起来，却不泛化；极端情形是编号，每格 1 笔、增益直接顶到父节点熵。C4.5 用增益率（除以分裂信息）来罚这件事，另外还补了连续变量、缺失值和剪枝。停止条件只有三条：节点纯、属性用完、分支为空。

### 2 分钟版（三块）

1. **熵与增益的机制**：$H(S) = -\sum_c p_c\log_2 p_c$，纯节点 0、两类各半 1 bit；增益 $= H(S) - \sum_v w_v H(S_v)$，$w_v$ 是分支样本占比。比较候选时 $H(S)$ 是常数，所以名次只看加权子熵；增益也等于标签与属性的互信息，因此恒非负。
2. **它怎么被偏置骗**：本页 10 笔算例——出险 $0.256426$ bits、城市 $0.570951$ bits，ID3 选城市，而那三个纯格子各只有 2 笔。把城市切到 10 档，增益顶到 $0.970951$（父熵），说明上界本身与预测力无关。
3. **流程与边界**：递归分叉时把用过的属性删掉；空分支和属性用完都回落多数类。原版不剪枝，噪声会让树长得很深，所以生产里要么用 C4.5 的剪枝，要么用 CART 的 CCP，要么把树装进集成。

### 会被追问到哪

| 追问 | 答法要点 |
|---|---|
| 「熵和 Gini 怎么选？」 | 两者都严格凹、都能建树，多数场景名次一致；Gini 不用对数更快；加权求和之后排序可以反向（极不平衡 + 小子节点），细节见 [[7.2.2 Decision Tree]] |
| 「信息增益和互信息什么关系？」 | 同一个量：$IG(S,A) = I(S;A)$，即标签与属性的互信息，所以非负；也因此在连续变量离散化、特征筛选里到处出现 |
| 「ID3 能处理连续特征吗？」 | 原版不能；扩展做法是排序后试每个边界，把阈值当成两值属性，核心循环不动 |
| 「父节点的熵可以省掉吗？」 | 比较候选时可以，$H(S)$ 是常数；但报数、「解释省了多少信息」时必须留着 |
| 「ID3 的停止条件是什么？」 | 节点纯 / 属性用完（回落多数类）/ 分支为空（回落多数类）；没有剪枝，所以树的大小由噪声和取值个数决定 |
| 「增益率为什么能罚多取值属性？」 | 分母 SI 只由「切了几块、每块多大」决定；编号的 SI $= \log_2 n$，把增益顶到上界的那部分抵消掉。但 SI 也能反过来帮忙，见 [[7.2.3.3 C4.5 Algorithm]] |
| 「ID3 和 C4.5、CART 一句话区别？」 | ID3 = 熵 + 多路 + 不剪枝；C4.5 = ID3 + 增益率 + 连值/缺失/剪枝；CART = Gini 或 SSE + 二分 + $\alpha$ 剪枝 |

## 🔤 本页术语 / Key Terms

| 中文 | English | 一句话 |
|---|---|---|
| ID3 | Iterative Dichotomiser 3 | 用信息增益多路分裂、不剪枝的第一代决策树 |
| 熵 / 信息熵 | entropy | $-\sum_c p_c\log_2 p_c$，比特；纯节点 0、等比例最大 |
| 香农熵 | Shannon entropy | 完美压缩下一个标签的期望比特数 |
| 信息增益 | information gain | $H(S)-\sum_v w_v H(S_v)$，等于与标签的互信息 |
| 分裂后的加权不纯度 | weighted impurity after split | 子节点熵按分支样本占比加权求和 |
| 互信息 | mutual information | 增益的另一个名字：知道 $A$ 后 $y$ 掉多少不确定性 |
| 分裂信息 | split information | $-\sum_v w_v\log_2 w_v$，只看切块大小、不看标签 |
| 增益率 | gain ratio | IG / SI，C4.5 用来治多取值偏置 |
| 多取值偏置 | bias toward multi-valued attributes | 取值多 ⇒ 格子小 ⇒ 增益虚高 |
| 最优子结构 | optimal-substructure property | 熵可加，所以先让根节点那一项最小是有理的 |
| 贪心分裂 | greedy split | 只看当前节点的增益最大，不回溯 |
| 停止条件 | stopping criterion | 节点纯 / 属性用完 / 分支为空 |
| 多数类回落 | majority-class fallback | 停下时用多数类当叶子，保证有输出 |
| 连续特征离散化 | discretisation by thresholds | 排序后取相邻取值中点当候选阈值 |
