## 速览 At a glance

**速记**

整份实现只有四个零件：`entropy()` 数标签分布、把「混」折成比特；`info_gain()` 用父节点熵减去按子集大小加权的子节点熵；`ID3()` 递归建树；`DecisionNode` / `Leaf` 存结构和预测。递归有两个出口——标签全同类返回纯叶子，属性集空了返回多数类叶子；另外那段「子集为空」的分支在本实现里永远不会执行（取值是从数据里取的）。预测沿 `branches` 字典往下走，遇到训练时没见过的取值返回 `None`，等于弃权，兜底要调用方自己接。三处最容易写错：熵的底数（`math.log2` 才给 bit，`math.log` 给 nat，数值差 1.4427 倍）；递归时的 `attributes - {best_attr}` 如果不减，同一条路径上会把同一个问题问第二遍；`max(gains, key=gains.get)` 在增益打平时由集合遍历顺序决定赢家，同一份数据两次可能得到两棵不同的树。这份实现只吃类别型属性：连续变量得先离散化，或者照 C4.5 那样在循环里做二分。

**一句面试答法**

> "Four pieces: entropy, information gain, a recursive build function, and a node class. Recursion stops when the labels are pure or when the attributes run out — and if they run out while the labels are still mixed, you return the majority class. The base of the logarithm sets the unit, so log base two gives bits. Attributes are dropped from the set as you recurse, and that is what makes the recursion terminate."

**术语**

| 中文 | English | 一句话 |
|---|---|---|
| 熵 | entropy | $-\sum_c p_c\log_2 p_c$，单位 bit |
| 信息增益 | information gain | 父节点熵 − 子节点熵的加权和 |
| 多数类 | majority class | 节点里出现最多的标签，兜底答案 |
| 递归终止条件 | base case | 标签全同类 / 属性用完 |
| 取值个数 | cardinality | 一个属性有几个不同取值，就是几个分支 |
| 弃权 | abstain | 遇到没见过的取值返回 `None` |
| 离散化 | discretisation | 连续变量转成类别型，切点位置影响树形 |

## 一、先看一个问题

白板上你刚把增益推完：

$$
Gain(S,A)=H(S)-\sum_{v\in values(A)}\frac{|S_v|}{|S|}H(S_v)
$$

面试官说：「好，写出来。」你写到第八行停住了。

卡住的不是公式，是三个边界：

* 什么时候 `return`？标签全同类当然返回；属性问完了、标签还混着，返回什么？
* 属性集合要不要往下传？传的话传什么？
* 某一枝的取值在训练数据里一条样本都没有，这枝怎么办？

再加一个输入类型的问题：`Humidity = 65` 直接扔进 `set()`，每个不同数值算一个取值，树会碎成一百片叶子。连续变量到底能不能进 ID3？

本页回答这四个问题。下面按顺序走一遍 ID3 的每个零件：熵的计算、信息增益、递归建树、以及最终的类别预测。这份实现假设：

- 所有属性都是**类别型（categorical）**。
- 数据是表格形式（列表套字典，list of dictionaries）。
- 目标变量用一个字符串键来指定（例如 `"label"`）。

> 说明：代码块内容保持原样（逐字未改），只在代码外加中文说明，方便对照着读。

## 二、核心直觉

整份代码做着同一件事的四种写法：数一遍（`Counter`）、折成比特（`log2`）、算一次提问的分数（增益）、把数据切片后重新调自己（递归）。

像「二十问」游戏：每轮挑一个能把剩下的可能性砍掉最多的问题问下去。像的地方是每轮只挑一个问题、挑完立刻按答案切开数据；不像的地方是二十问每一问都是是非题，而 ID3 问一次属性就把它所有取值一次切完，分支数等于取值个数。所以取 100 个值的属性一次能切出 100 枝——这正是第五节说的多取值偏置。

递归能停，靠的是一个会单调变小的量：属性集合。每进一层少一个，最多走「属性个数」层就必然到底。

## 三、逐段讲代码

### 3.1 主函数 `ID3()`：两个出口 + 一次贪心

读法：`ID3()` 先处理两个终止情形（全同类 → 叶子；属性用完 → 多数类叶子），然后用 `info_gain()` 选出增益最大的属性，建内部节点，再按该属性的每个取值切出子集并递归。递归时把 `best_attr` 从属性集中去掉，正是为了避免重复提问。

```python
def ID3(dataset, attributes, target_attr):
    """Build a decision tree using the ID3 algorithm."""
    labels = [example[target_attr] for example in dataset]

    # Case 1: All examples have the same class → make a leaf
    if labels.count(labels[0]) == len(labels):
        return Leaf(labels[0])

    # Case 2: No more attributes to split on → return majority class
    if not attributes:
        return Leaf(majority_class(dataset, target_attr))

    # Step 1: Choose attribute with highest information gain
    gains = {attr: info_gain(dataset, attr, target_attr) for attr in attributes}
    best_attr = max(gains, key=gains.get)

    # Step 2: Create internal node
    node = DecisionNode(best_attr)

    # Step 3: Partition dataset and recurse
    attr_values = set(example[best_attr] for example in dataset)

    for value in attr_values:
        subset = [ex for ex in dataset if ex[best_attr] == value]

        if not subset:
            # No data for this value → create leaf with majority class of current dataset
            leaf = Leaf(majority_class(dataset, target_attr))
            node.add_branch(value, leaf)
        else:
            # Recurse with remaining attributes
            new_attrs = attributes - {best_attr}
            subtree = ID3(subset, new_attrs, target_attr)
            node.add_branch(value, subtree)

    return node
```

三个地方值得盯一眼：

* **出口的顺序**。「全同类」写在「属性用完」前面：只含 1 条样本、或标签一致的子集先被第一个出口接住，不会白算一遍增益。
* **属性的传递**。`new_attrs = attributes - {best_attr}` 写在 `for` 里面，每切一枝重算一次，结果相同，只是重复；位置无所谓，**减号必须存在**。不减的话同一条路径上会把同一个问题问第二遍，递归要的「单调变小」就没有了。
* **空子集分支**。`if not subset` 在这份实现里是死代码：`attr_values` 是从 `dataset` 里取出来的，每个取值至少有一条样本，`subset` 永远非空。它有用的场合是另一种写法——从属性的定义域（schema 里的全部可能取值）枚举分支，那时训练数据没覆盖的取值才会造出空枝。

### 3.2 节点类：`DecisionNode` 与 `Leaf`

节点类：`DecisionNode` 存「按哪个属性分裂」以及「取值 → 子树」的字典，`predict()` 沿字典往下走；`Leaf` 只存一个类别标签，任何样本进来都返回它。遇到没见过的属性取值（`subtree is None`）时返回 `None`，相当于弃权。

```python
import math
from collections import Counter, defaultdict

class DecisionNode:
    def __init__(self, attribute):
        self.attribute = attribute         # Attribute to split on
        self.branches = {}                 # Dict: attribute value → subtree (node or leaf)

    def add_branch(self, value, subtree):
        self.branches[value] = subtree

    def predict(self, example):
        attr_value = example.get(self.attribute)
        subtree = self.branches.get(attr_value)

        if subtree is None:
            # Handle unseen or missing attribute values
            return None
        return subtree.predict(example)

class Leaf:
    def __init__(self, label):
        self.label = label

    def predict(self, example):
        return self.label
```

`predict()` 里用的是 `example.get(self.attribute)` 而不是下标：样本缺这个键时返回 `None`，然后被当成一个名叫 `None` 的取值去找分支，找不到就弃权。训练路径上用的是 `example[best_attr]` 直接下标，缺键当场 `KeyError`——训练和预测对缺失值的态度不一致，这点要自己统一。

`return None` 会一路传回调用方。生产里这里必须接一个默认方向（多数类，或者父节点的多数类），否则下游拿到的是空值。

### 3.3 熵：把「混」折成比特

熵只依赖标签的分布：把各类的占比 $p$ 代进 $-\sum p\log_2 p$。节点越纯，这个值越接近 0；二分类最混（各 50%）时取到 1 bit。

```python
def entropy(dataset, target_attr):
    """Calculate entropy of the dataset with respect to target attribute."""
    total = len(dataset)
    label_counts = Counter(example[target_attr] for example in dataset)

    ent = 0.0
    for count in label_counts.values():
        p = count / total
        ent -= p * math.log2(p)
    return ent
```

**易错点 1：底数决定单位。** `math.log2(p)` 给 bit，`math.log(p)` 给 nat，两者差 $\ln 2$：1 bit = 0.6931 nat。拿 9 个 Yes / 5 个 No 的数一遍——底数 2 得 0.940286，底数 $e$ 得 0.651757。底数只做单调缩放，名次不变，所以 bug 会安静地活着，直到你和教材对数字或者面试报单位时才露头。

### 3.4 信息增益：分母永远是当前节点

信息增益 = 父节点熵 −「按属性切分后、用子集大小加权」的子节点熵之和。实现上是先按属性取值分组，再对每组算熵加权求和，最后与整体熵相减。

```python
def info_gain(dataset, attr, target_attr):
    """Compute information gain from splitting on attr."""
    total = len(dataset)
    attr_values = defaultdict(list)

    # Partition data by attribute value
    for example in dataset:
        attr_values[example[attr]].append(example)

    weighted_entropy = 0.0
    for subset in attr_values.values():
        weighted_entropy += (len(subset) / total) * entropy(subset, target_attr)

    return entropy(dataset, target_attr) - weighted_entropy
```

**易错点 2：权重里的 `total` 是当前节点的样本数。** 不是数据集总数、也不是分组个数。漏掉权重（对各子集熵直接取平均）会让一条样本的纯子集和一个五条样本的混杂子集拥有同等发言权，增益被人为抬高，属性选择跟着变。

### 3.5 多数类：兜底的答案

当一个节点已无属性可问、却又必须给出预测时，退回到「出现次数最多的类别」。这也是叶子节点的默认答案。

```python
def majority_class(dataset, target_attr):
    """Return the most common class label in the dataset."""
    label_counts = Counter(example[target_attr] for example in dataset)
    return label_counts.most_common(1)[0][0]
```

**易错点 3：票数打平时由数据顺序决定。** `Counter.most_common(1)` 在计数相同时按插入顺序返回，所以 `[No, Yes]` 得 `No`、`[Yes, No]` 得 `Yes`（两行都实测过）。要确定性就得自己定规则：按类别名的字母序，或者按训练集的先验频率。

### 3.6 用法示例

用一个 5 行的玩具数据集（沿用 Play Tennis 里的属性名）建树，再预测一条新样本。注意这里的数据量很小，树的形态（以及输出是 "No" 还是 "Yes"）取决于属性顺序等实现细节。

```python
dataset = [
    {"Outlook": "Sunny", "Humidity": "High", "Wind": "Weak", "Play": "No"},
    {"Outlook": "Sunny", "Humidity": "High", "Wind": "Strong", "Play": "No"},
    {"Outlook": "Overcast", "Humidity": "High", "Wind": "Weak", "Play": "Yes"},
    {"Outlook": "Rain", "Humidity": "High", "Wind": "Weak", "Play": "Yes"},
    {"Outlook": "Rain", "Humidity": "Normal", "Wind": "Weak", "Play": "Yes"},
]

attributes = {"Outlook", "Humidity", "Wind"}
tree = ID3(dataset, attributes, target_attr="Play")

example = {"Outlook": "Sunny", "Humidity": "Normal", "Wind": "Strong"}
print("Prediction:", tree.predict(example))  # Output might be "No" or "Yes" depending on tree structure
```

实测补一句：这 5 行数据里 `Outlook` 的增益 0.970951 一枝独秀（`Wind` 0.321928、`Humidity` 0.170951），没有平局，所以树是唯一的——`Overcast` 和 `Rain` 各是一刀切纯的叶子，输出稳定是 `"No"`。用六个哈希种子（`PYTHONHASHSEED=0/1/2/3/7/11`）各跑一遍，树和输出都一样。代码注释里那句 `# Output might be "No" or "Yes" depending on tree structure` 担心的随机性，在这份数据上不会发生；换一份有增益平局的数据才会。

### 3.7 零件对照表

| 部件 | 它做什么 |
|---|---|
| `entropy()` | 衡量类别不确定性（标签「混」到什么程度） |
| `info_gain()` | 衡量一次分裂能减少多少不确定性 |
| `majority_class()` | 需要时给出兜底的类别标签（用于叶子节点或空分支） |
| `ID3()` | 递归建树：在最优属性上分裂，并往下建子树 |
| `DecisionNode` / `Leaf` | 分别代表内部节点与终端节点；两者都提供 `predict()` 方法 |

## 四、怎么验证实现写对了

四个检查，从便宜到贵。前三步对的是 [[7.2.2.3.1.9 ID3 Build Example]] 那份十四天手算。

### 第 1 步：熵的三个定点

```python
entropy([{"Play": "Yes"}], "Play")                    # 纯节点 -> 0.0
entropy([{"Play": "Yes"}, {"Play": "No"}], "Play")    # 50/50 -> 1.0
# 14 天（9 Yes / 5 No）-> 0.9402859586706311
```

三个数里有一个不对：第二个跑出 0.693147 就是用了 `math.log`，第一个跑不出 0 就查分母。

### 第 2 步：增益的名次

```python
# 根节点：Gain(Outlook) 0.246750 > Gain(Humidity) 0.151836 > Gain(Wind) 0.048127 > Gain(Temperature) 0.029223
# Sunny 支：Gain(Humidity) 0.970951 > Gain(Temperature) 0.570951 > Gain(Wind) 0.019973
# Rain  支：Gain(Wind) 0.970951 > Gain(Temperature) 0.019973 = Gain(Humidity) 0.019973
```

这三行和手算页的分裂顺序逐位对得上——那边的根节点就是按 0.246750 选的，Sunny 支按 0.970951、Rain 支按 0.970951。名次对不上，先查权重和子集划分，再查底数。

### 第 3 步：和手算的树整体对拍

把十四天表喂进 `ID3()`，形状必须是「3 个内部节点 + 5 个叶子」：根 `[Outlook]`；`Overcast` 直接是 `Yes` 叶；`Sunny` 下接 `[Humidity]`（`High → No`、`Normal → Yes`）；`Rain` 下接 `[Wind]`（`Strong → No`、`Weak → Yes`）。再验三条样本的预测：D1（Sunny / Hot / High / Weak）→ `"No"`、D5（Rain / Cool / Normal / Weak）→ `"Yes"`、D14（Rain / Mild / High / Strong）→ `"No"`。

### 第 4 步：故意喂边界

```python
tree.predict({"Outlook": "Sunny", "Humidity": "Medium", "Wind": "Weak"})   # -> None
ID3([], set(), "Play")                                                     # -> IndexError: list index out of range
```

第一条说明叶子只在训练出现过的取值上有效；第二条说明空数据集会先炸在 `labels[0]`，那两个出口根本轮不到。两个都是实现的一部分，写测试时要写成预期行为，别当成偶发 bug。

## 五、什么情况下会失灵

### 承重假设一：所有属性都是类别型，而且取值数少

`set(example[best_attr] for example in dataset)` 把数值属性也当类别处理：温度 25.3 和 25.4 是两个毫不相关的分支，每个取值一枝。

撤掉它的后果可以量化。在十四天表里加一列 `Day`（14 个互不相同的编号），它在根节点的增益是 **0.940286**——正好等于根节点熵，因为每个取值下只剩 1 条样本、熵全为 0，加权熵也是 0。0.940286 直接压过 `Outlook` 的 0.246750，树会拿一个毫无预测力的编号做根节点。这就是 ID3 的多取值偏置，也是 **[[7.2.3.3 C4.5 Algorithm]]** 引入增益率的原因。

### 承重假设二：训练集覆盖了将来会出现的取值

撤掉它的后果很具体：预测遇到没见过的取值，`predict()` 返回 `None`。线上若 5% 的样本落在训练没覆盖的取值上，这 5% 就没有预测值；在 `subtree is None` 处接一个多数类默认方向能补上，代价是这批样本全判成多数类。

### 承重假设三：同一属性取值内部的标签不冲突

每个叶子最终得给一个标签。相同特征向量出现不同标签时，递归会一路下到属性用完，然后由 `majority_class()` 拍板，错的比例就是该叶子里少数类的占比。

### 承重假设四：贪心 + 不剪枝

代码里没有深度上限，也没有剪枝。属性足够多时（比如混进一列近似唯一的 ID），树能把训练集切到每个叶子一条样本，训练误差 0，而这样的树对新样本没有用。想限制就得自己加 `max_depth` 之类的参数。

## 六、常见误解

### 误解一：「代码跑通、输出对了，就说明理解 ID3 了」

**错误想法**：`print("Prediction:", tree.predict(example))` 打出 `No`，和参考答案一致，说明实现对了、算法也懂了。

**为什么容易这么想**：拿一个已知输出的玩具数据集验收集是常规做法，这份 5 行数据的结果还特别稳定。

**错在哪一步**：输出对只证明那一棵树对。真正的检验是能不能预测第二次分裂——不看代码说出：根节点用 `Outlook` 之后，`Sunny` 那一支下一步切谁？答案是 `Humidity`（增益 0.970951），因为按它切出来 High 全是 No、Normal 全是 Yes，一刀切纯；`Temperature` 只有 0.570951，`Wind` 只有 0.019973。说不出这个，掌握的是输出，不是循环。

### 误解二：「连续变量必须先离散化才能进 ID3」

**错误想法**：熵和增益只对类别型属性有定义，温度这种连续量必须先分箱。

**为什么容易这么想**：这份实现的 `set()` 分组确实只适用于离散值，而例题里的 `Temperature` 又长成 Hot/Mild/Cool 的样子，看起来天生分好了档。

**错在哪一步**：把「原版 ID3 的实现限制」当成了「熵与增益的限制」。增益循环本身不要求离散化——C4.5 在同一个循环里加了一步：把属性排序，对每对相邻取值的中点 $\tau$ 试二分「$A\le\tau$」的增益，留下最好的 $\tau$。熵、增益、递归一个字没改，变的只是候选分裂的集合。代价是每个节点要重排一次，$O(n\log n)$。

### 误解三：「代码里有 `if not subset`，说明缺失值和空枝都处理了」

**错误想法**：空分支有兜底，这份实现足够稳健。

**为什么容易这么想**：空枝和缺失值是决策树的两个经典坑，代码里出现了对应的片段，自然会放心。

**错在哪一步**：这段是死代码（取值从数据里来，子集不可能为空），而且它兜的不是缺失值。训练路径上完全没处理缺失：`ID3()` 用 `example[best_attr]` 直接下标，缺键当场 `KeyError`；`predict()` 用 `.get()`，缺失被当成一个名叫 `None` 的取值。真要支持缺失值，得先决定它在熵的分组里算哪一支。

## 七、面试怎么答

### 30 秒版

> 实现是四个零件：`entropy()`、`info_gain()`、递归的 `ID3()`，以及 `DecisionNode` / `Leaf` 两个类。递归有两个出口：标签全同类返回纯叶子，属性集空了返回多数类叶子。属性每递归一次少一个，这是保证终止的量。底数取 2，单位就是 bit。预测沿分支字典走，遇到没见过的取值返回 `None`，等于不做预测。代码假设属性都是类别型，连续变量要么在外面先离散化，要么像 C4.5 那样在循环里二分。

### 会被追问到哪

| 追问 | 答法要点 |
|---|---|
| 「熵的底数为什么是 2？」 | 底数只决定单位：2 → bit，$e$ → nat，10 → dit。名次不变、数值变（差 $1/\ln 2=1.4427$ 倍），报数必须带单位 |
| 「属性问完了、标签还混着怎么办？」 | 返回多数类叶子；票数打平时 `Counter.most_common(1)` 返回先出现的那个，平局规则实际由数据顺序决定，要确定性得自己定 |
| 「为什么递归时要把属性从集合里删掉？」 | 每条路径上不重复提问，同时属性集合单调变小，深度不超过属性个数，递归必然停 |
| 「Sunny 那一支的第二刀切在哪？」 | `Humidity`，增益 0.970951；它把这枝一刀切纯，`Temperature` 0.570951、`Wind` 0.019973 |
| 「连续特征怎么进来？」 | 原版 ID3 进不来；C4.5 在同一个增益循环里排序 + 扫相邻中点做二分，每个节点 $O(n\log n)$ |
| 「这棵树会过拟合吗？」 | 属性一多就会：一列近似唯一的编号能把每个叶子切到 1 条样本，训练误差 0，而代码里没有剪枝和深度上限 |

## 🔤 本页术语 / Key Terms

| 中文 | English | 一句话 |
|---|---|---|
| 熵 | entropy | $-\sum_c p_c\log_2 p_c$，单位 bit |
| 信息增益 | information gain | 父节点熵 − 子节点熵的加权和 |
| 加权熵 | weighted entropy | $\sum_v\frac{\lvert S_v\rvert}{\lvert S\rvert}H(S_v)$，分母是当前节点样本数 |
| 多数类 | majority class | 节点里出现最多的标签，兜底答案 |
| 递归终止条件 | base case | 标签全同类 / 属性用完 |
| 取值个数 | cardinality | 属性有几个不同取值，就是几个分支 |
| 弃权 | abstain | 遇到没见过的取值返回 `None` |
| 离散化 / 二分阈值 | discretisation / binary threshold | 连续变量转类别型；C4.5 用相邻取值中点 |
| 死代码 | dead code | `if not subset` 在本实现里永远不会执行 |
