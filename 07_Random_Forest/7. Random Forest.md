## 速览 At a glance

**速记**

随机森林让很多棵长到很深的树各看一份 bootstrap 样本、每次分裂各看一小撮特征，再把答案平均。单棵树偏差低方差高；而平均只压得住互相独立的那部分：单棵树方差 σ²、树间相关系数 ρ 时，B 棵平均后的方差是 `ρσ²+(1−ρ)σ²/B`，第二项随 B 变小，`ρσ²` 是地板——本页算例 ρ=0.5、100 棵树的方差 0.505，其中 99% 是这块地板。所以上限由 ρ 决定，压 ρ 的唯一旋钮是 `max_features`（分类 √p、回归 p/3）。有放回抽 n 条约 36.8% 的行抽不到，这些袋外（OOB）行天然是每棵树的测试集，可免费估计泛化误差。代价是不能外推，MDI 偏向高基数变量。

**一句面试答法**

> "A random forest averages many deep trees, each grown on a bootstrap sample and each allowed to split on only a random subset of the features. The bootstrap gives you diversity plus a free out-of-bag validation set; the feature subsampling is what decorrelates the trees, and that is what makes the averaging actually reduce the variance."

**术语**

| 中文 | English | 一句话 |
|---|---|---|
| 自助抽样 | bootstrap | 有放回地抽 n 条；约 36.8% 的行抽不到 |
| 袋装法 | bagging | 抽 B 个 bootstrap 样本各建一个模型再聚合 |
| 袋外样本 | out-of-bag (OOB) | 某棵树没抽到的那些行，天然是它的验证集 |
| 随机子空间 | random subspace | 每次分裂只看随机抽出的 m 个特征 |
| 树间相关性 | correlation ρ | 平均之后压不下去的那部分；由 m 控制 |
| 不纯度平均下降 | mean decrease in impurity (MDI) | 分裂带来的不纯度下降，按节点大小加权求和 |
| 置换重要性 | permutation importance | 打乱一列后在 OOB 上量误差涨多少 |

## 一、先看一个问题

8 万条车险保单，40 个特征，你按 `min_samples_leaf=1` 建了一棵树。训练集 AUC 打到了 0.99——这个数你自己都不信，因为谁都知道这棵树已经把训练数据背下来了。

问题出在它的另一面。你把训练集换掉 1%（800 行）重训五次，五次 5 折 CV 的 AUC 落在 **0.69 到 0.74** 之间，上下差 5 个点。更麻烦的是单个客户：保单 #41287 的续保概率预测，五次分别是 **0.183 / 0.264 / 0.211 / 0.175 / 0.239**。业务要的是「这单客户值不值得打电话」，你手里是五个数。

再看清楚这是谁的问题。这棵树的平均误差并不离谱，抖得厉害的是它自己：**偏差不高，方差很大**。换 800 行数据，就足以把根节点的第一刀换到另一个变量上去，后面整棵树跟着变。

所以需要的是一个「预测不抖」的估计器，而且必须能用同一份数据做出来——砍掉树深能压方差，但同时把偏差推上去，等于换了一个问题。

真题里这两句问的是同一件事：

> "Walk me through the algorithm." ／ "What is OOB error?"

随机森林就是给这个问题的一套标准答案：让很多棵仍然会抖的树各自出错，再挑一个出错方式不同的位置聚合。面试官追问 OOB，是看你知不知道这套随机化还顺手送了一个验证集。

## 📖 标准定义

> **教材原文 · PSL §4.2.1 Introduction to Random Forest、§4.2.3 Variable Importance（页面 w4_2_randomforest.html）**（<https://liangfgithub.github.io/PSL/w4/w4_2_randomforest.html>）
> > "These omitted data points are referred to as “ Out-of-Bag ” (OOB) samples."
> >
> > "Random Forest improves upon simple bagging by introducing constraints aimed at decorrelating the individual trees."
> >
> > "The key constraint in Random Forest is that at each split, only a random subset of ‘m’ features is considered out of the total ‘p’ features. The optimal split is then chosen among these ‘m’ features. The recommended values for ‘m’ are the square root of ‘p’ for classification tasks and ‘p/3’ for regression tasks."

**标准记法**：袋外样本概率：每个 $x_i$ 不被某次 bootstrap 抽中的概率 $\approx (1 - 1/n)^n \to e^{-1} \approx 0.368$。袋外误差 $\text{OOB-Err} = \frac{1}{n}\sum_{i=1}^n L\big(y_i, \hat{f}^{[-i]}(x_i)\big)$，$\hat{f}^{[-i]}$ 只用不含第 $i$ 个观测的树。重要性 I：分裂带来的 RSS 下降（按变量归集后取平均）；重要性 II：置换前后 OOB 预测误差之差，$\text{VI}_j = \frac{1}{B}\sum_b (\text{Err}^{\text{perm}}_b - \text{Err}_b)$。

**中文解释**：Bagging 抽 B 个 bootstrap 样本各长一棵树再平均，专治高方差低偏差的树；随机森林再多加一层限制：每次分裂只看随机抽出的 $m$ 个特征（分类 $\sqrt{p}$、回归 $p/3$），把树之间的相关性压下来。没被抽中的 OOB 样本天然可当验证集。重要性有两套：分裂的 RSS 收益，和 OOB 上打乱该变量后误差的上升。

> 完整条目与更多来源见 [[定义原文库#C13. 随机森林 / m 的推荐值 / OOB / 两种重要性|C13. 随机森林 / m 的推荐值 / OOB / 两种重要性]]

## 二、核心直觉

### 两处随机化，各管一件不同的事

随机森林在袋装法（bagging）之上加了第二层随机，两层的目标不一样：

| 随机化 | 抽什么 | 抽的目的是什么 |
|---|---|---|
| **数据的随机化** | 每棵树抽一份**有放回**的 bootstrap 样本（行） | 让每棵树看到的数据不同 → 制造**多样性**，且附赠 OOB 行 |
| **特征的随机化** | 每个节点只从随机抽出的 $m$ 个特征里挑分裂（列） | 让强势特征（dominant feature）不能出现在每一棵树里 → **去相关** |

第一层让树彼此不同，第二层保证它们「不同在点子上」。

### 平均为什么救得回一棵树，以及它救不回什么

先把袋装法想成一件事：单棵树的预测在真值附近抖，抖的原因大半是它只看了一份数据。那就多建几棵，各看一份，然后取平均。抖的方向如果彼此独立，平均之后互相抵消，方差被压下去；偏差不受影响，因为每棵树都不是系统性偏一边。

**这里像什么、不像什么**：像叫一组人分别估同一套房的价格——每个人看的户型图不同（数据不同），而且每人只许问 5 个问题（特征受限）。**像的地方**是最后的平均确实比任何一个人稳。**不像的地方**是这些人并不是独立的：他们看的是同一批挂牌记录，市场一涨，所有人的报价一起偏高。所以误差里有一块是**所有树同时犯同一个错**，平均多少遍都消不掉。这块残差就是下面公式里的 $\rho\sigma^{2}$。

这一点直接决定了随机森林的设计：既然平均消不掉相关的那部分，就得先把相关性本身压下去——而压 $\rho$ 的手段只有一个，就是每个节点随机抽特征。

### 三条先记住的结论

1. 加树只降方差：$B$ 变大时误差单调收敛到一个平台，**偏差不含 $B$**。
2. 上限由 $\rho$ 定：`ρσ²` 是地板，`max_features` 是唯一能压它的旋钮。
3. 预测是训练集里 $y$ 的平均（回归）或票数（分类），所以**森林不能外推**，也天然不给方向。

## 三、机制

### 3.1 定义与逐项说明

森林的预测就是 B 棵树预测的平均：

$$
\hat f_{\text{RF}}(x) = \frac{1}{B}\sum_{b=1}^{B} f_b(x)
$$

逐项读：

- $x$：一条待预测的记录，走进每棵树都从根节点开始比较。
- $f_b$：第 $b$ 棵树。它是**长满且不剪枝**的 CART，训练数据是第 $b$ 份 bootstrap 样本 $Z^{*}_b$；每个节点上只在随机抽出的 $m$ 个特征里挑分裂。
- $B$：树的数量（`n_estimators`）。它只出现在平均号里，不出现在任何一棵树的训练里。
- 分类任务：每棵树投一票，取**多数票**。它与「先平均各树给出的正类概率、再取 argmax」通常结果一致，但票数比例并不等于校准过的概率。
- 回归任务：每棵树输出一个数，取**平均数**。所以叶子给的是训练 y 的均值 → 训练集里没出现过的 y 区间，森林给不出来。

OOB 是哪来的：抽一份 bootstrap 样本时，每条记录单次不被抽中的概率是 $1-1/n$，独立抽 $n$ 次后是

$$
\Bigl(1-\frac{1}{n}\Bigr)^n \;\longrightarrow\; e^{-1} \approx 0.368
$$

所以每棵树大约有 36.8% 的训练行没见过。把这些行按「哪些树没见过它」收集起来，就得到 $\hat f^{[-i]}$——不含第 $i$ 条记录的树组成的子森林，用它预测第 $i$ 条，就是袋外误差（见第四节实算）。

### 3.2 它是怎么来的：从一棵树推到两层随机

**第一步，单棵树的账。** 树是低偏差、高方差的学习器：深度放开后训练误差趋近 0，但换一份样本就换一套分裂。处方是「让它长，但别只长一棵」。

**第二步，bootstrap + 平均。** 设单棵树的方差是 $\sigma^{2}$，任意两棵树预测的相关系数是 $\rho$。平均之后：

$$
\operatorname{Var}\Bigl(\frac{1}{B}\sum_{b=1}^{B} f_b\Bigr)
= \frac{1}{B^{2}}\Bigl[B\sigma^{2} + B(B-1)\rho\sigma^{2}\Bigr]
= \rho\sigma^{2} + \frac{1-\rho}{B}\,\sigma^{2}
$$

逐项读：$B\sigma^{2}$ 是同方差项（$B$ 个各自 $\sigma^2$，来自 $B^2$ 项里的对角线），$B(B-1)\rho\sigma^{2}$ 是两两协方差项（$B^2-B$ 个非对角项）。除以 $B^2$ 之后：

- $\rho\sigma^{2}$：**地板**。它不随 $B$ 变化，加多少树都在。
- $(1-\rho)\sigma^{2}/B$：唯一随 $B$ 缩小的那一项。

**关键一步在这里。** 上面这个式子把「加树」能拿到的东西一次性讲完了：只有 $(1-\rho)\sigma^{2}/B$ 这一项。$\rho$ 越接近 1，这一项越小，加树的边际收益会快速用完。也就是说，单纯 bagging 的天花板被 $\rho$ 焊死了——想再往下走，唯一的出路是**动 $\rho$ 本身**。

**第三步，随机抽特征来压 $\rho$。** 如果某个变量很强，它会在每棵树上都成为根节点或高层分裂的依据，所有树的错误就跟着它一起偏。于是规定：每个节点只从随机抽出的 $m$ 个特征里挑分裂（分类默认 $\sqrt{p}$、回归 $p/3$）。强变量被随机挡在门外的时候，树必须去找别的依据，错误模式因此分开。代价是单棵树更弱（偏差略升），换来的是 $\rho$ 下降——而 $\rho$ 是天花板。

**第四步，顺手拿到 OOB。** bootstrap 的抽样缺口本身就是一组样本外数据，所以随机森林不需要额外切验证集就能看泛化误差。这也是它「开箱即用」口碑的一半来源。

**为什么这一步不剪枝。** Bagging 的前提是基学习器低偏差、高方差。剪过枝的树偏差已经抬起来了，平均只能压方差，压不了偏差，等于白扔了一层。

### 3.3 与 bagging 的关系、以及两处随机的口径

| 做法 | bootstrap 行采样 | 分裂时抽特征 | 备注 |
|---|---|---|---|
| **单棵 CART** | 无 | 用全部 $p$ 个 | 方差大 |
| **Bagging** | 有 | 用全部 $p$ 个 | 只有第一层随机；$\rho$ 常常很高 |
| **随机森林** | 有 | 只看 $m$ 个 | 第二层随机专治 $\rho$ |

**极端组合的口径**：`bootstrap=False` 同时 `max_features=p` 时，每棵树的训练数据与候选分裂完全一样 → **B 棵完全相同**，聚合成一棵树，集成为零收益（一个很好的「你到底懂不懂」答案）。

**实现口径差异**：分类任务的 `max_features` 在 scikit-learn 里默认 `"sqrt"`、在 R 的 `randomForest` 里默认 `floor(sqrt(p))`；回归任务常用 $p/3$。H2O、LightGBM 的 RF 模式还各有自己的默认值。报数时要说清用的是哪个库的默认值，别把「$\sqrt{p}$」说成随机森林的定义。

### 3.4 算法步骤

给定 n 个样本、p 个特征的数据集（详见 [[7.2. Building the Forest]]）：

1. **重复** b = 1 到 B（树的数量）：

   * **自助抽样（bootstrap sample）：** 从原始数据里**有放回**地抽 n 条样本。
     *为什么？* 制造树之间的**多样性（diversity）**；每棵树看到的数据集都是独一份。
   * **长树（grow tree）：**

     * 在每个节点上，从全部 p 个特征里随机抽出 `max_features` 个。
     * 选出最好的分裂（例如最大化 Gini 下降，或最小化 MSE）。
     * 一直分到满足某个停止规则（`max_depth`、`min_samples_leaf` 等）。
       *为什么要随机抽特征？* 保证所有树不会都盯着同一个强预测变量，从而让集成的降方差更有效。
2. **聚合（aggregate）** 这 B 棵长满、**不做剪枝**的树。

因为每棵树既做了**数据随机化**、又做了**特征随机化**，它们犯的错就变得高度不相关。聚合（平均或投票）时，个别树的错误互相抵消。

$$
\mathrm{Var} = \rho\sigma^{2} + \frac{1-\rho}{B}\,\sigma^{2}
$$

读这个式子：随着树数 B 增大而消失的只有 $(1-\rho)\sigma^{2}/B$ 那一项，**`ρσ²` 是地板（floor）** —— 它由树间的相关性 ρ 决定，**加再多树也压不下去**。换句话说，**bagging 只能把方差降到 `ρσ²` 这个地板**；**而唯一能压低 ρ 的旋钮，就是每次分裂随机抽特征**（`max_features`）。所以 `max_features` 是随机森林的**标志性旋钮**，不是随手加的一点随机性。完整推导见 [[7.2. Building the Forest]] §4。

### 3.5 特征重要性：两把尺子

随机森林提供两把互补的尺子，量每个特征对预测的贡献：

| 方法 | 怎么算 | 怎么读 |
| :--- | :--- | :--- |
| **Mean Decrease in Impurity (MDI)** | 把「特征 j 被用到」的所有树、所有分裂上的**杂质下降（impurity reduction）**加总（按节点大小加权），再归一化。 | 衡量一个特征**被选中做分裂的频率与有效性**。 |
| **Permutation Importance** | 在**袋外数据（out-of-bag, OOB）**上把特征 j 的取值打乱（shuffle），看准确率掉多少（回归则看 MSE 涨多少）。 | 反映**真实的预测能力（包括交互效应）**；受特征**基数（cardinality）**的偏差更小。 |

* **关键结论：** MDI 快，但**会偏向高基数的类别变量与连续变量**（它们可选的切点更多，天然更容易被选中）；permutation importance 更接近真实影响，代价是额外的计算量，而且**必须在 OOB 或测试集上算** —— 在训练集上算会因为「模型已经记住训练数据」而被掩盖。
* **两者的共同局限：** 当两个特征高度相关时，**两者都会把贡献分摊掉**（各自看起来都没那么重要），所以不要只看单变量排名，要按相关特征分组去读重要性。

细节（偏置的量级、分组置换、PDP / SHAP）见 [[7.4. Quantifying Feature Importance]]。

### 3.6 核心超参数与权衡

| 参数 | 作用 | 对偏差 / 方差的影响 |
| :--- | :--- | :--- |
| **n\_estimators** | 森林里树的数量 | 加树 → 方差↓（只降方差，**不会过拟合**）；代价是计算与内存↑ |
| **max\_depth** | 每棵树的最大深度 | 深度↓ → 偏差↑、方差↓；深度↑ → 偏差↓、方差↑ |
| **min\_samples\_split** | 一个节点还要有这么多样本，才允许继续分裂 | 调大 → 偏差↑、方差↓ |
| **min\_samples\_leaf** | 叶节点至少要装多少样本 | 防止长出极小的叶子（把噪声单独隔离）；调大 → 偏差↑、方差↓ |
| **max\_features** | 每次分裂考虑多少个特征 | 调低 → 树之间更去相关、偏差↑；调高 → 偏差↓、树间相关性↑（**RF 的标志性旋钮**） |
| **bootstrap** | 是否使用自助抽样（True/False） | 设为 False（不做 bagging）→ 方差↑ |
| **criterion** | 不纯度度量（分类用 Gini / entropy；回归用 MSE / MAE） | 会影响分裂的选择与速度，但通常只是细节差异 |
| **class\_weight** | 分类里的类别权重方案 | 通过加重少数类误分类的惩罚，平衡不平衡数据 |

**`n_estimators` 的常用区间（MAGNet §8）**：**300–1000**（经验值）。**更多树单调更好，直到平台期** —— 机制是：预测是这 B 棵树的**平均**，加树只会让这个平均更靠近它的期望、方差单调下降，而**偏差几乎不变**，所以**树更多不会过拟合**。这正是它与 GBM 的关键差异：GBM 的 `n_estimators` 是**加性**的（每棵树在拟合前面的残差），因此有**内部最优点** —— 太少欠拟合、太多开始拟合噪声而过拟合。代价是**时间与内存随树数线性增长**；做法是**一路抬高，直到 OOB / 验证误差走平**。

**要留意的耦合关系（Interdependencies to watch）：**

* 森林更深（`max_depth` ↑）时，达到稳定误差所需的树可能更少（`n_estimators` ↓）。
* 每次分裂用的特征更少（`max_features` ↓）时，可以靠允许更小的叶子（`min_samples_leaf` ↓）来补偿，但有过碎的风险。

#### 超参数之间怎么相互影响

> MAGNet 专门问了这题（Q: How do those hyperparameters interact?），所以下面五条要能脱口而出；它们比上面的「Interdependencies to watch」更深一层。

* **`max_features` × `n_estimators`**：`max_features` 越低 → 每棵树越弱、越去相关 → **需要更多树**把多出来的噪声平均掉。**要成对调**。
* **`max_depth` × `min_samples_leaf`**：两者从**相反方向**限制复杂度（自上而下 vs 自下而上）。同时调基本冗余：**固定一个，调另一个**。
* **树复杂度 × `n_estimators`**：**更深、方差更高的树，从加树中获益更多**（比浅树多）。
* **`class_weight` × `min_samples_leaf`**：**重权少数类 + 极小叶节点 = 过拟合稀有类的最快路径**。若上调权重，就要**抬高叶节点最小样本数**。
* **`bootstrap=False` × `max_features=p`**：这个组合会得到 **B 棵完全相同的树，集成为零收益** —— 一个很好的「你到底懂不懂」的答案。

> 来源：MAGNet §8（Q: How do those hyperparameters interact?）；[[MAGNet 面试真题全解]]

### 3.7 调参策略（Tuning Strategies，嵌套在交叉验证里）

1. **网格搜索（grid search）**

   * 在用户定义的网格上**穷举**。
   * 优点：探索彻底；缺点：组合数呈指数增长。

2. **随机搜索（random search）**

   * 随机采样超参数组合。
   * 优点：通常更快找到好的区域；缺点：可能漏掉很窄的最优点。

3. **贝叶斯优化（Bayesian optimization）**（例如 tree-structured Parzen estimator, TPE）

   * 为验证集表现建一个**代理模型（surrogate model）**，然后**序贯地**细化搜索。
   * 优点：把过去的评估结果用得很充分；缺点：搭建起来更复杂。

> **永远**把超参数搜索**嵌套在交叉验证的折内**，以防乐观偏差（optimistic bias）：把数据切成 k 折，在 (k–1) 折上调参，在留出的那一折上测试，然后重复。

### Q: What tuning strategies do you use?

> 🎯 真题问法（MAGNet §8）｜ 深潜来源：MAGNet §8 Tuning strategies ＋ 本文件 §6 Tuning Strategies ＋ [[03. 答题模板与追问应对]]

> ⚡ 先说的那一句
> 「**随机搜索是第一遍的默认** —— 同样预算下它通常胜过网格，因为**只有少数参数真正重要**，而随机采样能给每个参数更多**不同取值**；只有**每次拟合都很贵、预算很紧**时才上贝叶斯优化；**搜索空间大、早期信号便宜**时用 successive halving / Hyperband。」

| 策略 | 怎么工作 | 什么时候用 |
|---|---|---|
| **Grid search** | 在指定网格上**穷举** | **参数少**、且你已定位到**粗范围**。**代价是各维度的乘积**，**超过 3–4 个参数就崩** |
| **Random search** | 从**分布**里采样组合 | **默认的第一遍**。同样预算下通常胜过网格 —— 因为只有少数参数真正重要，随机采样能给每个参数更多不同取值 |
| **Bayesian optimization**（TPE / GP；Optuna、Hyperopt） | 建目标函数的**代理模型（surrogate）**，按**期望改进（expected improvement）**挑下一个点 | **每次拟合都很贵、预算很紧时**。缺点：**串行，难以并行**；**模型便宜时不值当** |
| **Successive halving / Hyperband** | 用**便宜信号**先跑很多配置，**淘汰差的**，把预算**重新分配给好的** | **搜索空间大、早期信号便宜时** |

**永远**：在**验证 / CV 折**上调参，在**未动过的测试集**上报告；**如果调参很密集，考虑嵌套 CV**（内层调参、外层度量）。

> 🔗 会被追问到
> - 「**RF 需要调参多吗？**」→ 少：**`n_estimators` 抬到 OOB 平稳**、**`max_features` 与它成对调**、**`min_samples_leaf` 控噪声**；RF 对超参数不敏感，开箱即用（这也是它与 GBM 的差距所在）。
> - 「**Grid 为什么在 3–4 个参数后崩？**」→ 组合数是各维格点数的**乘积**（5 个参数各 5 档 = 3125 次拟合）；同样 60 次预算下，随机搜索能覆盖更多**不同取值**。
> - 「**贝叶斯优化一定能赢吗？**」→ 不一定：**模型便宜时它的开销不划算**，而且**串行**限制并行度；它赢在**每次评估都很贵**的场景。
> - 「**Hyperband 的「便宜信号」在保险里是什么？**」→ 小数据子集 / 少树 / 少轮次的验证损失；只要**排名**与全量训练一致，淘汰就是安全的。
> - 「**调完参的分数能直接当性能吗？**」→ 不能（**乐观有偏**）；**报告要用未动过的测试集或外层 CV**。

### 3.8 实操流程与优缺点

| 优点 | 缺点 |
| :--- | :--- |
| 几乎不用调参就能拿到高准确率 | 比单棵决策树更难解释 |
| 靠降方差对过拟合稳健 | 森林一大，计算与内存开销都很重 |
| 天然处理非线性交互与混合类型数据 | MDI 重要性偏向**类别数多**的变量 |
| 内置 OOB 误差估计，不必单独切验证集 | **不能外推到训练数据范围之外**（预测是观测到的 y 的平均，叶子只给得出训练里见过的 y 区间） |

实操顺序：

1. **先用默认值起步：** `n_estimators = 100`、`max_features = "sqrt"`（分类），不限制深度。
2. **快速验证：** 用 **OOB 误差（out-of-bag error）** 判断泛化能力，不必先切留出集。
3. **误差画像：** 画「验证误差 vs. `n_estimators`」曲线，找出**收益递减**的位置（平台期）。
4. **核心调参：** 用随机搜索或贝叶斯搜索，重点调 `max_depth`、`min_samples_leaf`、`max_features`。
5. **特征工程：** 算 **permutation importance**，决定保留、变换还是删掉哪些变量。
6. **解释：** 需要比原始重要性更深的洞察时，用 partial dependence plot 或 SHAP 值。

## 四、算一遍

这一节算两件事：树的数量与相关性怎么决定误差（第一部分），以及 bootstrap 到底留出多少数据可以当验证集（第二部分）。第一部分的 $\sigma^{2}$ 直接取 1，也就是把单棵树的误差方差当成单位量。

### 第一部分：方差分解 `ρσ²+(1−ρ)σ²/B`

公式只有两个输入：单棵树方差 $\sigma^{2}$（取 1）和树间相关系数 $\rho$。代入四个 $\rho$、三个 $B$：

| $\rho$ \ $B$ | **B = 1** | **B = 10** | **B = 100** | 地板 $\rho\sigma^{2}$ | B=100 时地板占多少 |
|---|---|---|---|---|---|
| **0**（完全独立） | 1.0000 | 0.1000 | 0.0100 | 0 | 0% |
| **0.2** | 1.0000 | 0.2800 | 0.2080 | 0.2 | 96.15% |
| **0.5** | 1.0000 | 0.5500 | 0.5050 | 0.5 | 99.01% |
| **0.9** | 1.0000 | 0.9100 | 0.9010 | 0.9 | 99.89% |

**第 1 步：看 B = 1 这一列。** 全是 1.0000。一棵树就是它自己，此时 $\rho$ 毫无意义——$\rho$ 描述的是「树和树像不像」，一棵树没有像不像的问题。

**第 2 步：看 B 从 1 到 10。** 这是收益最大的一段。$\rho=0$ 时方差掉到 0.1（降 90%）；$\rho=0.2$ 时掉到 0.28；到了 $\rho=0.9$，只掉到 0.91——**90% 的方差在第一棵树上就已经定下来了**。

**第 3 步：看 B 从 10 到 100。** 树多了九倍，收益只剩这么点：

| $\rho$ | 方差 0.9100→… B=10 | B=100 | 绝对降幅 | 相对降幅 |
|---|---|---|---|---|
| 0.2 | 0.2800 | 0.2080 | 0.0720 | 25.71% |
| 0.5 | 0.5500 | 0.5050 | 0.0450 | 8.18% |
| 0.9 | 0.9100 | 0.9010 | 0.0090 | 0.99% |

**这就是 $\rho\sigma^{2}$ 是地板的量化含义。** $\rho=0.5$ 时，100 棵树的方差 0.5050 里地板占 0.5000，剩下 0.0050 才是「加树买到的」。$\rho=0.9$ 时从 10 棵加到 100 棵，方差只从 0.9100 挪到 0.9010，相对降幅不到 1% —— 这时候再加树纯属浪费算力，该动的是 `max_features`。

**第 4 步：换成有单位的数。** 假设单棵树的预测误差标准差是 0.2（方差 $\sigma^{2}=0.04$，大约是一个叶子均值抖 20%）：

| 配置 | 方差 | 标准差 |
|---|---|---|
| 单棵树 | 0.0400 | 0.2000 |
| $\rho=0.5$、B=10 | 0.0220 | 0.1483 |
| $\rho=0.5$、B=100 | 0.0202 | 0.1421 |
| $\rho=0.9$、B=100 | 0.0360 | 0.1898 |

相关系数从 0.5 抬到 0.9（方差只差 0.0162），标准差从 0.1421 涨到 0.1898——**误差的绝对水平涨了三分之一**。这就是「降 $\rho$ 比加树重要」在数字上的样子。

### 第二部分：bootstrap 留出多少行

单条记录不被某次 bootstrap 抽中的概率是 $1-1/n$，$n$ 次独立抽样之后是 $(1-1/n)^n$：

| n | $(1-1/n)^n$ | 袋外比例 | 袋外条数 |
|---|---|---|---|
| 10 | 0.3486784401 | 34.87% | 3.5 |
| 100 | 0.3660323412732292 | 36.60% | 36.6 |
| 1000 | 0.3676954247709637 | 36.77% | 367.7 |
| → ∞ | $e^{-1}=0.3678794412$ | 36.79% | — |

三点读法：

1. **收敛很快。** n 从 10 到 1000，袋外比例从 34.87% 挪到 36.77%，只差 1.9 个百分点；n=10 就已经离极限 $e^{-1}$ 不到 2 个点了。所以「约三分之一」这句话对小样本也成立。
2. **每棵树的训练集里有重复行。** n=1000 时有放回抽 1000 次、只抽到 $1000\times(1-0.3677)=632.3$ 个不同行。也就是说每棵树的「有效样本量」只有 63%——B 棵树不是 B 份独立数据。
3. **OOB 是每行一部分树投的票。** 一条记录大约被 B 棵树中的 $0.368B$ 棵判过。B=100 时约 37 棵树。这 37 棵树是同一个 OOB 预测的来源，所以 OOB 误差本身也有噪声，不能当精确到小数点后三位的成绩单。

### 条件检验：把 $\rho$ 换成另一个值，结论会怎么变

上面两个计算都受 $\rho$ 支配，所以做两次对照：

- **对照一：假装树之间完全独立（$\rho=0$）。** 此时地板是 0，方差 $=1/B$：B=10 就已经 0.1000，B=100 是 0.0100。这正是「多人独立投票能消除误差」的世界。随机森林拿不到这个世界——树的训练数据来自同一份原始表，$\rho$ 恒大于 0。
- **对照二：把 $\rho$ 从 0.9 压到 0.5，树数保持 B=10。** 方差从 0.9100 掉到 0.5500，比在 $\rho=0.9$ 下把树数从 10 加到 100（0.9100→0.9010）多降了 35 倍。**同样的算力，动 `max_features` 比加 `n_estimators` 划算。**
- **反过来问：$\rho$ 压过头会怎样？** `max_features=1` 时每棵树每次只能看一个特征，$\rho$ 确实很低，但每棵树变得很弱、偏差明显上升，平均又压不掉偏差。所以 $\sqrt{p}$（分类）、$p/3$（回归）是权衡后的起点，不是「越小越好」。

## 五、什么情况下会失灵

### 承重假设一：每棵树要够深（低偏差）

随机森林只负责压方差，偏差这一半得由单棵树自己保证。

撤掉它的后果：把 `max_depth=2` 固定住，每棵树都欠拟合，平均之后还是欠拟合——**集成的偏差下限就是单棵树的偏差**。表现是训练误差和验证误差一起很高，加树完全没用。所以在森林里，第一阶段的树必须真的长满，这一条不能省。

### 承重假设二：样本量要够支撑 bootstrap

撤掉它的后果：n 很小时（比如 10 条），一份 bootstrap 样本里只有约 6.5 个不同行，剩下的都是重复。所有树看到的数据高度重叠，$\rho$ 天然接近 1，加树的收益立刻用完；同时每行只有约 3.5 个邻居，切点位置极不稳定。这时候先扩样本或改用强正则的 GLM，比堆树有用。

### 承重假设三：$m$ 既不能太小也不能太大

撤掉它的后果分两头：

- $m$ 太小（`max_features=1` 且只有一两个真变量）：树之间重新变得很像，$\rho$ 回升。极端情况 $p=1$ 时，随机抽特征什么都抽不到，随机森林退化成 bagging，天花板 = 单棵树的方差 $\sigma^{2}$。
- $m$ 太大（接近 $p$）：等于没做去相关，回到 bagging。

### 承重假设四：OOB 与上线数据同分布

bootstrap 是从训练集里有放回抽的，它保留的假设是「训练集与未来数据同分布、且样本之间可交换」。

撤掉它的后果：时序数据上，紧邻的两天高度相关，随机 bootstrap 会把未来信息混进每一棵树，OOB 误差**系统性偏乐观**——你报 3% 的误差，上线可能是 8%。另外，用 OOB 调过参之后，它就不再是干净的估计。处理：改用前向切分（forward chaining）或 out-of-time 验证集。

### 承重假设五：预测是训练 y 的平均

叶子给的是那个格子里 y 的均值，所以森林的预测区间被训练数据框住。

撤掉它的后果：**不能外推**。训练时保费区间是 500–3000 元，给它一个 15000 元的保单，预测仍然是 3000 附近那一片叶子的均值。真实关系如果随保费单调上升，森林在区间外只会给一条水平线。

### 与其他模型的边界

| 场景 | 用谁 | 为什么 |
|---|---|---|
| 表格数据、要开箱即用的高精度 | 随机森林 | 调参少，OOB 免费，对噪声稳健 |
| 要榨出最后 2–3 个点 | GBM / XGBoost | 加性拟合残差，上限高，但必须管住轮数 |
| 需要系数、要报备监管 | GLM | 系数即 odds ratio，单调性由构造保证 |
| 需要区间外的趋势 | GLM / GAM | 树给分段常数，外推只能给常数 |
| 变量的基数差别很大 | 随机森林 + permutation | MDI 会偏向高基数变量（见 [[7.4. Quantifying Feature Importance]]） |
| 时序 / 面板数据 | 前向切分 + RF 或 GBM | 随机 bootstrap 会打乱时间结构，OOB 偏乐观 |

## 六、常见误解

### 误解一：「树越多越容易过拟合」

**错误想法**：1000 棵树比 100 棵危险，`n_estimators` 得设小一点。

**为什么容易这么想**：GBM 的 `n_estimators` 确实有内部最优点（每棵树在拟合前一轮的残差，轮数多了就开始拟合噪声），这个结论很容易被搬过来；而且 sklearn 里 `n_estimators` 一调大，训练时间线性上涨，看起来「模型更复杂了」。

**错在哪一步**：把「训练更久」当成「容量更大」。随机森林的预测是 B 棵已经训练好的树的平均，增加 B 只是把平均多算几项，**没有改变任何一棵树的容量**。看第四节那张表：$\rho=0.9$ 时 B 从 10 到 100，方差 0.9100→0.9010，方向永远是降，没有回头路。真正会把随机森林弄过拟合的是「树太深 + 叶子太细 + 标签有噪声」，那是 `max_depth`、`min_samples_leaf` 的辖地。做对照：**RF 的 `n_estimators` = 越多越好（到平台）**，**GBM 的 = 有最优点**。

### 误解二：「MDI 排第一的变量就是最重要的变量」

**错误想法**：`feature_importances_` 最高那一列就是最强驱动因素，直接写进定价报告。

**为什么容易这么想**：名字里就带 importance，还归一化到合计 1；多数情况下排名和业务直觉也对得上（真变量确实靠前）。

**错在哪一步**：MDI 的分母是「这个机会被抽到的次数」，而取值多的变量（客户 ID 哈希、300 个水平的车型代码、连续变量）天然有更多候选切点被选中，分数被抬起来。跨基数比较得换置换重要性，并且必须在 OOB 上打乱——训练集上打乱几乎不掉分，因为模型已经记住了训练数据。另外两把尺子都只给幅度、不给方向。见 [[7.4. Quantifying Feature Importance]]。

### 误解三：「有 OOB 误差就不需要测试集了」

**错误想法**：OOB 是免费的样本外估计，直接报它当性能。

**为什么容易这么想**：机制上 OOB 确实只用每棵树没见过的行，完全就是样本外；森林越大还越稳，看起来可以放心引用。

**错在哪一步**：漏了「这个数字被你看过几遍」。你用 OOB 曲线挑 `max_features`、调 `min_samples_leaf`，就已经把这份数据用进了选择过程，它开始偏乐观。第二个坑是精度：每行的 OOB 预测平均只由约 $0.368B$ 棵树给出（B=100 时约 37 棵），噪声比一个完整模型的预测大得多；第四节算过这个比例。第三个坑最致命：时序数据上 bootstrap 会把时间混起来，OOB 误差可以直接偏乐观几倍。正确用法是——OOB 拿来看「树够不够了」和给变量排序，最终数字用一个没动过的测试集，或者嵌套 CV。

### 误解四：「都是树了，缺失值和量纲都不用管」

**错误想法**：原始表直接丢进 `RandomForestClassifier`，量纲和缺失值都不用预处理。

**为什么容易这么想**：树的分裂只比较大小关系，单调变换不改变分区，所以标准化确实没必要——这一半完全正确，而且很省事，于是顺手把缺失值也划进「不用管」那一类。

**错在哪一步**：把「算法性质」和「实现行为」混成一件事。量纲可以不处理，因为它不影响分区顺序；缺失值要看实现——scikit-learn 的随机森林在很长一段时间里不接受 `NaN`，必须自己补，而补什么值会改变切点集合，进而改变 MDI 排名。还有一层更容易忽略：类别变量怎么编码本身会动候选池。10 个原始特征 one-hot 成 40 列之后，`max_features=√p` 从 3 变成 6，但每个 dummy 单独看信息量稀薄，重要性被摊薄到几乎看不见。CART 的教科书写法是代理分裂（surrogate split），那是 `rpart` 的行为，不是「树模型」的通则。

## 七、面试怎么答

### 30 秒版

> 随机森林 = bagging + 每次分裂随机抽特征。B 棵长满不剪枝的树，各建在一份 bootstrap 样本上，每层只在 m 个特征里挑分裂，分类投票、回归平均。两处随机的分工不一样：bootstrap 制造多样性顺带送出 OOB 验证集，抽特征把树之间的相关性压下来。平均后的方差是 $\rho\sigma^{2}+(1-\rho)\sigma^{2}/B$，只有第二项随树数缩小，`ρσ²` 是地板，所以 `max_features` 才是决定上限的旋钮。分类默认 $m=\sqrt{p}$、回归 $p/3$。

### 2 分钟版（要包含的三块）

1. **机制**：树长满（低偏差是前提）、行抽样、列抽样、聚合；加树只降方差，误差单调收敛到平台。
2. **为什么第二层随机不能省**：单靠 bagging，$\rho$ 通常很高，加树的收益被 $\rho\sigma^{2}$ 挡住；抽特征是把 $\rho$ 压下去的唯一手段，代价是单棵树更弱。
3. **免费得到的与得不到的**：OOB 可以估泛化误差、做置换重要性，但没有独立测试集之前不能当最终成绩；预测是训练 y 的平均，所以不能外推。

### 会被追问到哪

| 追问 | 答法要点 |
|---|---|
| 「$m$ 为什么是 $\sqrt{p}$ 而不是别的？」 | 经验默认值，取向是「让树足够不同」；$m$ 越小 → $\rho$ 越低、单棵树越弱，要成对调 `n_estimators`，用 OOB 找平衡点 |
| 「OOB 误差怎么来的？」 | 单行不被抽中概率 $(1-1/n)^n \to e^{-1}\approx 0.368$；用没抽到它的约 37% 的树投票/平均算预测 |
| 「RF 和 GBM 的差别？」 | RF 加树只降方差、无内部最优点、调参少；GBM 加树在拟合残差、有最优点、上限高但要管轮数 |
| 「超参数怎么互相影响？」 | `max_features` × `n_estimators` 成对；`max_depth` × `min_samples_leaf` 方向相反、冗余；`bootstrap=False` × `max_features=p` = 零收益 |
| 「RF 怎么算特征重要性？」 | MDI（训练期不纯度下降，偏向高基数）＋ permutation（OOB 打乱后误差上升）；相关变量会分摊，要分组读 |
| 「Pros and cons？」 | 省调参、抗噪声、有 OOB；代价是慢、内存重、不可外推、MDI 有偏、解释性不如单棵树 |

## 🗣️ 英文表达 / How to Say It

**30-second version**

> "A random forest combines two ideas: bagging, so each tree is trained on a bootstrap sample, and random feature sampling, so each split only considers a random subset of the predictors. At each node we pick the best split among those features, and then we aggregate by majority vote or by averaging."

**Mechanism**

> "The feature sampling is the part that earns its keep. The variance of the average is rho sigma squared plus one minus rho times sigma squared over B, so as B grows only the correlated part survives — lowering rho is where the gain comes from. And it comes with a free validation estimate: each tree has its own out-of-bag rows."

**If they push back**

> "A common pitfall is expecting more trees to hurt. They don't — the error converges as B grows; what actually causes overfitting is deep trees plus noisy labels plus a small sample, which is why I'd control leaf size and check the out-of-bag error. The defaults I'd start from are a hundred trees and the square root of p for classification, and I'd stop adding trees when the out-of-bag error flattens."

## 🔤 本页术语 / Key Terms

| 中文 | English | 一句话 |
|---|---|---|
| 随机森林 | random forest | bagging + 每次分裂随机抽特征的树集成 |
| 袋装法 | bagging | 抽 B 份 bootstrap 样本各建模型再聚合 |
| 自助抽样 | bootstrap | 有放回抽 n 条；约 36.8% 的行抽不到 |
| 袋外样本 | out-of-bag (OOB) | 某棵树没抽到的行，天然是它的验证集 |
| 袋外误差 | out-of-bag error | 只用「没抽到该行」的树对它的预测误差 |
| 随机子空间 | random subspace | 每个节点只从随机抽出的 m 个特征里挑分裂 |
| 特征子抽样 | feature subsetting | `max_features` 控制，分类默认 $\sqrt{p}$、回归 $p/3$ |
| 树间相关性 | correlation $\rho$ | 平均压不下去的那块方差，$\rho\sigma^{2}$ 就是地板 |
| 不纯度平均下降 | mean decrease in impurity (MDI) | 分裂带来的不纯度下降按节点大小加权求和 |
| 置换重要性 | permutation importance | 打乱该变量后在 OOB 上量误差上升 |
| 基数 | cardinality | 变量的取值个数，决定它有多少候选切点 |
| 嵌套交叉验证 | nested cross-validation | 内层调参、外层度量，防乐观偏差 |
| 平台期 | plateau | 继续加树误差不再下降的位置 |
| 外推 | extrapolation | 预测落在训练 y 区间之外；树模型做不到 |
