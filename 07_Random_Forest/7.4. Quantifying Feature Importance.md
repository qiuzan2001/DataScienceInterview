## 速览 At a glance

**速记**

随机森林给两把量特征重要性的尺子，量的是两件不同的事。MDI 在训练时顺手累加每次分裂带来的不纯度下降，按节点大小加权，再归一化到合计 1；它便宜，但把「这个变量有多少个可切点」也一起算进了重要性，所以一个和 y 完全无关的高基数列能排到真变量前面——本页实测：同一个纯噪声列，取值从 2 种放开到 400 种，它的 MDI 从 0.0942 涨到 0.6004（6.4 倍），而置换重要度始终在 ±0.002 之间抖动。置换重要性（permutation importance）换了一个问法：把某一列的值在样本之间打乱，看袋外（OOB）误差涨多少，再跨树平均。它必须在 OOB 或测试集上算，在训练集上算会掉到 0。两把尺子都只给幅度、不给方向，遇到两个高度相关的变量会互相分担得分。

**一句面试答法**

> "There are two standard measures. MDI sums the impurity reduction each time a feature is used to split, weighted by the node size, and normalises it. Permutation importance shuffles one feature on the out-of-bag rows and measures how much the error rises. For comparing features with different cardinality I'd use permutation, and for correlated features I'd permute them as a group."

**术语**

| 中文 | English | 一句话 |
|---|---|---|
| 不纯度平均下降 | mean decrease in impurity (MDI) | 每次用该变量分裂带来的不纯度下降，按节点大小加权求和后归一化 |
| 置换重要性 | permutation importance | 打乱该变量的取值后，模型误差上升多少 |
| 袋外样本 | out-of-bag (OOB) samples | 某棵树的 bootstrap 没抽到的行，天然是它的测试集 |
| 基数 / 水平数 | cardinality | 一个变量能取多少个不同值，决定它有多少个候选切点 |
| 分组置换 | grouped permutation | 把一组相关变量一起打乱，避免互相顶替 |
| 偏依赖图 | partial dependence plot (PDP) | 看变量往哪个方向推预测，补上重要性缺的「方向」 |
| H 统计量 | H-statistic | 用二维 PDP 与两个一维 PDP 之和的差量化交互强度 |
| 方向 | direction | 变量变大时预测变大还是变小；重要性指标不给这个信息 |

## 一、先看一个问题

你给 12 万条车险保单跑完一个随机森林，p = 40 个变量。定价报告要求写「前 5 个驱动变量」，于是你顺手排了一下 `model.feature_importances_`。

排出来第一名是 `policy_id_hash`——建表时留着当主键的那一列。它和「是否出险」的关系是零，因为它是随机生成的。但它有 12 万个不同取值。

你会怎么处理？直接把主键删掉重排？那你得先能说清楚**为什么**该删它：MDI 到底把什么算成了贡献。删掉之后还有一个更隐蔽的版本：把「车型代码」这种 300 多个水平的类别变量留在里面，它会偷偷吃掉一部分本该属于真变量的分数。

真题里这件事被问过三次：

> (§8) "How does RF compute feature importance?"
> (§9) "How does GBM compute variable importance?"
> (§5) "Would you use a GBM's feature importance to pick features for a GLM?"

这两个问法考的其实是同一件事：**你知道这两个指标各自的偏置从哪来吗**。面试官听到「MDI 和 permutation 两个指标」只算答了一半，他会接着问「跨基数比较能不能直接用 MDI」——那才是分界线。

搞清楚「哪些特征在驱动模型决策」以及「它们怎么协同起作用」，落到工作上有三件事：

* **解释预测（interpret predictions）**：找出关键驱动因素。
* **做特征工程（engineer features）**：把精力集中在信息量最大的变量上。
* **发现交互（detect interactions）**：看出两个（或多个）特征何时在联合影响目标。

## 📖 标准定义

> **教材原文 · PSL §4.2.1 Introduction to Random Forest、§4.2.3 Variable Importance（页面 w4_2_randomforest.html）**（<https://liangfgithub.github.io/PSL/w4/w4_2_randomforest.html>）
> > "The first measure evaluates a variable’s importance based on the reduction in the residual sum of squares (RSS) it contributes to each tree. Whenever a split is made in a tree using a particular variable, RSS decreases. Those reductions are are aggregated across all the trees in the forest for each variable. The average RSS improvement gives us an indication of a variable’s importance."
> >
> > "The second measure focuses on prediction accuracy, using OOB samples. The process involves random shuffling of the j-th predictor and recording the new prediction error. The difference between the two prediction errors, before and after permutation, gives the importance measure for the j-th predictor variable."

**标准记法**：袋外样本概率：每个 $x_i$ 不被某次 bootstrap 抽中的概率 $\approx (1 - 1/n)^n \to e^{-1} \approx 0.368$。袋外误差 $\text{OOB-Err} = \frac{1}{n}\sum_{i=1}^n L\big(y_i, \hat{f}^{[-i]}(x_i)\big)$，$\hat{f}^{[-i]}$ 只用不含第 $i$ 个观测的树。重要性 I：分裂带来的 RSS 下降（按变量归集后取平均）；重要性 II：置换前后 OOB 预测误差之差，$\text{VI}_j = \frac{1}{B}\sum_b (\text{Err}^{\text{perm}}_b - \text{Err}_b)$。

**中文解释**：Bagging 抽 B 个 bootstrap 样本各长一棵树再平均，专治高方差低偏差的树；随机森林再多加一层限制：每次分裂只看随机抽出的 $m$ 个特征（分类 $\sqrt{p}$、回归 $p/3$），把树之间的相关性压下来。没被抽中的 OOB 样本天然可当验证集。重要性有两套：分裂的 RSS 收益，和 OOB 上打乱该变量后误差的上升。

## 二、核心直觉

### 两把尺子量的是两件事

MDI 问的是：**训练的时候，这个变量被用来切了几刀，每一刀把节点弄纯了多少。** 它是一本训练期的账本，记的是「模型内部发生过什么」。

Permutation 问的是：**把这一列的取值打乱之后，模型在没见过的样本上错了多少。** 它是一次测试期的损失测量，记的是「模型有多依赖这一列能对得上号」。

两者给出的数不一样，是因为它们统计的对象不同。

**这里像什么、不像什么**：可以把特征重要性想成给球队评功劳。MDI 是数每个球员碰到球的次数，置换重要性是把他换下场看比分掉多少。像的地方是两者都想回答「他贡献多大」；不像的地方在于碰球次数分不清「这球是他跑出来的」还是「对手漏给他的」——取值多的变量天然有更多碰球机会。这个差别就是后面所有坑的根。

### 三条先记住的结论

1. MDI 便宜、有偏：**偏向高基数变量**（类别水平多的、连续的）。
2. Permutation 更接近「模型的真实依赖」，代价是算 B 次以上，而且**必须在 OOB 或测试集上算**。
3. 两个指标都只给**幅度**，不给**方向**。想知道「变量变大，预测往哪边走」，要另外看 PDP 或 SHAP。

### 为什么 permutation 要放在 OOB 上

一颗树在它的 bootstrap 样本上可以把训练集背下来。在训练集上打乱一列，模型还有别的路径认出这一行（相邻取值、相关变量），误差几乎不涨。你会得到一排接近 0 的重要性，然后误以为「模型没用到任何变量」。OOB 行是这棵树**从没见过**的，打乱才会真的伤害它的预测。

## 三、机制

### 3.1 MDI：逐项定义

**第一步，单次分裂的不纯度下降。** 在节点 $t$、数据子集 $S_t$ 上，假设特征 $j$ 与阈值 $u$ 产生子节点 $S_L$、$S_R$，不纯度下降是

$$
\Delta I_{t}(j)
= I(S_t) \;-\; \frac{|S_L|}{|S_t|}\,I(S_L)\;-\;\frac{|S_R|}{|S_t|}\,I(S_R),
$$

其中 $I$ 是 Gini（分类）或 MSE（回归）；$|S_L|/|S_t|$ 是左子节点的样本占比，所以「大节点上的一刀」比「小节点上的一刀」分量更重。

**第二步，跨树累加。** 只要特征 $j$ 参与了某个分裂 $t$，就记下 $\Delta I_t(j)$。对所有树的所有节点求和，得到

$$
\text{MDI}_j = \sum_{b=1}^B \sum_{t \in T_b \,:\,\text{split on }j} \Delta I_t(j).
$$

$b$ 是树的编号（共 $B$ 棵），$t$ 遍历第 $b$ 棵树里**用到了 $j$** 的那些节点。注意求和范围：只在用到 $j$ 的节点上加，没用到的节点贡献 0。

**第三步，归一化。** 通常再做缩放，使 $\sum_j \text{MDI}_j = 1$。$\text{MDI}_j$ 越大，说明特征 $j$ 越频繁、也越有效地降低了不纯度。

**关键一步在这里**：这个求和的次数**取决于 $j$ 有多少个候选切点**。一个连续变量在一个 400 行的节点上有 399 个候选切点，一个二值变量只有 1 个。候选切点多，就更容易「碰巧」找到一刀把小样本切纯——那一刀的 $\Delta I>0$ 会被照单记入。所以 MDI 里混进了「运气」，而运气的多少由基数决定。这不是实现的 bug，是定义的直接后果。

> **它为什么能体现交互？**
> 如果特征 $j$ 在同一条分支上既出现在另一个特征 $k$ 之前的节点、也出现在它之后的节点，那么它的 $\Delta I_t(j)$ 就包含了这种联合划分的效果，从而间接反映了二者之间的交互。

MDI 的好处是**顺手就有、几乎零成本**（训练时顺便累加即可）；代价是它带有「分裂机会数」的偏置，跨基数比较时要小心——见下面 §2 的坑。

### 3.2 Permutation importance：四步

1. **基线表现**：在**袋外（out-of-bag, OOB）**或留出数据上算一个性能指标 $M$（例如 accuracy 或 MSE）。
2. **置换单个特征**：对特征 $j$，把它在样本之间的取值打乱（shuffle）——这样它与 $y$ 的关系被破坏，而其他特征保持不动。
3. **度量性能退化**：重新计算性能 $M_j^{\text{perm}}$。下降量

$$
\Delta M_j = M_{\text{baseline}} - M_j^{\text{perm}}
$$

就量化了模型有多依赖 $j$。$\Delta M_j$ 还可能算成负数——打乱之后模型碰巧蒙对了更多，这说明这个变量本来就没什么用（或者样本太少，噪声盖过了信号）。
4. **在 $B$ 棵树上取平均**：在**每棵树各自的 OOB 样本**上重复第 1–3 步，然后把 $\Delta M_j$ 在所有树上平均。（PSL §4.2：permutation importance = 在 **OOB** 上置换第 $j$ 个预测变量，比较置换前后的预测误差之差，再跨树平均。）

> **它怎么捕捉交互：**
> 因为只置换了 $j$，性能的下降里自然包含了 $j$ 与其他特征交互产生的影响。如果 $j$ 与 $k$ 是联合起作用的，那么置换 $j$ 也会削弱对 $k$ 的分裂的价值（反之亦然），这就把它们的协同（synergy）暴露出来。

> ⚠️ **三个容易踩的坑（PSL §4.2）**
>
> 1. **permutation 必须在 OOB（或测试集）上算，不要在训练集上算**：训练集上模型已经"记住"了模式，置换后性能几乎不掉（甚至下降为 0），会严重低估该特征的真实作用；只有在没见过的数据上置换才能暴露依赖。
> 2. **高基数（多水平类别）变量的重要性会被夸大**：MDI 尤其明显——可选分裂点越多，越容易"碰巧"降低不纯度。OOB 置换 + 跨树平均能缓解，但仍建议用 grouped permutation 或 holdout 复核。
> 3. **高度相关的特征会互相"分担"重要性**：把 $x_j$ 置换掉后模型可能改用与之相关的 $x_k$，于是两个特征的重要性都被低估；此时应按相关变量组一起置换，并配合 PDP / SHAP 看方向。

一句话对比：**MDI 快但会偏（尤其偏袒高基数变量），permutation 更可靠但更贵，而且必须在 OOB 上算。**

### 3.3 口径与写法差异

| 口径 | 怎么写 | 影响 |
|---|---|---|
| 归一化 | 各变量 $\text{MDI}_j$ 除以总和，合计为 1（scikit-learn 的 `feature_importances_` 就是这个） | 数值只能在**同一个模型内**比；换一个模型、换一批树，绝对值就不可比 |
| 不归一化 | 直接报 $\Delta I$ 的累加和 | 单位是「不纯度」，能看出信号总量有多少 |
| 节点加权 | 用 $|S_t|/n$ 加权（PSL 口径）或按样本数加权 | 加权后大节点上的一刀更重；不加权的写法在大数据上会把深层的碎节点算得过重 |
| 置换的性能指标 | accuracy、MSE、AUC、logloss 都可以 | 换了指标，排名会变——用 AUC 排和用 accuracy 排不是一回事 |
| 置换次数 | scikit-learn 的 `n_repeats` | 次数少时单次打乱的随机性会盖过真实差距，本页算例里跨树标准差是 0.11（信号变量）对 0.004（噪声变量） |
| R 的口径 | `randomForest::importance()` 里 `type=2` 是 Gini 下降（=MDI），`type=1` 是 OOB 打乱后的准确率下降（=permutation） | 软件里的名字不同，含义就是这两把尺子 |

> 软件默认值不等于正确答案：`sklearn.inspection.permutation_importance` 默认在**你传进去的那个数据集**上算。你传训练集，它就给你训练集上的置换重要性——正是要避免的那一种。要自己把 OOB 行或测试集传进去。

### 3.4 树结构本身就在编码交互

重要性分数能告诉你哪些特征重要、也暗示存在交互，但它并不会把交互显式地画出来。随机森林之所以天然能捕捉交互，是因为：

1. **顺序分裂（Sequential Splits）**
   一条分支可能在根节点先按 $x_j$ 分裂，往下再按 $x_k$ 分裂，于是等效地学到了形如

   $$
     \bigl(x_j \le u \bigr)\;\wedge\;\bigl(x_k > v \bigr)\;\implies\;\text{prediction}.
   $$

   的规则。$x_j$ 和 $x_k$ 单独看可能都排不进前 5，合起来却很有用。

2. **层级式划分（Hierarchical Partitioning）**
   从根到叶的每条路径都定义了多个特征条件的合取。模型这种分段常数（piecewise-constant）的预测曲面能逼近任意交互。

3. **如何检测交互**：

   * **偏依赖图（Partial Dependence Plots, PDP）**：把两个特征同时变化时模型的平均预测画出来，那些偏离「可加行为」的等值线就是交互的痕迹。
   * **H 统计量（H-Statistic, Friedman）**：用二维 PDP 与两个一维 PDP 之和的差异，量化两个特征之间交互的强度。

**逻辑主线**：分裂在最小化不纯度 → 记录每个特征贡献了多少（MDI）；置换会破坏一个特征的全部角色 → 度量的是总依赖，包含交互（Permutation）；树结构本身就在编码交互 → 顺序、层级式的分裂刻画了特征的协同。

## 四、算一遍

用一个能完全复现的小森林把两把尺子放一起对比。为了让数字能被手算，规模取得很小：$n=400$ 行、4 个变量、$B=60$ 棵树、`max_features`=2、`max_depth`=3、`min_samples_leaf`=5。

### 数据怎么造的（这一步决定了结论可信不可信）

| 变量 | 类型 | 与 $y$ 的真实关系 |
|---|---|---|
| $x_1$ | 二值 | 真信号：$x_1=1$ 时 $P(y=1)=0.9$，$x_1=0$ 时 0.1 |
| $x_2$ | 连续 | 弱信号：$x_2>0.5$ 时概率再抬 0.05 |
| $x_3$ | 高基数整数 | **纯噪声**，与 $y$ 独立；它的取值个数是本例要扫的旋钮 |
| $x_4$ | 二值 | **纯噪声**，与 $y$ 独立 |

$y$ 只在 $x_1,x_2$ 上有信号，所以「正确答案」是：$x_1$ 最重要，$x_2$ 次之，$x_3$ 和 $x_4$ 都该是 0。

```python
import random
N, B, M_FEATURES, MAX_DEPTH, MIN_LEAF = 400, 60, 2, 3, 5

def gini(rows):                       # 二分类的 Gini = 2p(1-p)
    p = sum(r["y"] for r in rows) / len(rows)
    return 2 * p * (1 - p)

def candidates(rows, j):              # 候选切点 = 相邻取值的中间值
    vals = sorted(set(r[j] for r in rows))
    mids = [(a + b) / 2 for a, b in zip(vals, vals[1:])]
    return mids[:30] if len(mids) > 30 else mids   # 模拟实现里的阈值子采样

# 生长、MDI 累加、OOB 置换平均：完整脚本见本页算例来源，核心是
#   Delta_I = gini(S) - (|L|/|S|)*gini(L) - (|R|/|S|)*gini(R)
#   MDI_j  += (|S|/n_tree) * Delta_I        # 只在用 j 分裂的节点上累加
#   perm_j  = mean over trees of ( err(shuffle x_j on OOB) - err(OOB) )
```

### 表 A：把 $x_3$（纯噪声）的取值个数从 2 抬到 400

| $x_3$ 的取值个数 | MDI($x_3$) 原始累加 | MDI($x_3$) 归一后 | MDI($x_3$)/MDI($x_4$) | 置换重要度($x_3$) | OOB 错误 |
|---|---|---|---|---|---|
| 2 | 0.0942 | 0.0050 | 0.96 | −0.00037 | 0.1366 |
| 5 | 0.3125 | 0.0171 | 2.20 | +0.00107 | 0.1455 |
| 20 | 0.4961 | 0.0286 | 3.88 | −0.00070 | 0.1723 |
| 100 | 0.5641 | 0.0314 | 5.96 | −0.00029 | 0.1520 |
| 400 | 0.6004 | 0.0346 | 6.00 | −0.00211 | 0.1720 |

$x_4$ 是同样纯噪声的二值变量，所以「MDI($x_3$)/MDI($x_4$)」这一列直接给出偏置的倍数：**从 0.96 涨到 6.00**。而 $x_3$ 与 $y$ 的统计关系从头到尾都是零。

**怎么读这两列**：

- MDI 列（原始累加）从 0.0942 涨到 0.6004，涨了 6.4 倍。多出来的部分全部来自「候选切点变多、更容易碰巧切纯小样本」。
- 置换列一直在 ±0.002 以内来回，符号还会变。这是噪声应该有的样子。
- OOB 错误从 0.1366 到 0.1720 波动，说明模型的真实水平没变——变的是账本，不是能力。

### 表 B：同一批树，四个变量的完整对照

| 特征 | 真实角色 | MDI 原始累加 | MDI 归一后 | 置换重要度 | 置换的跨树标准差 |
|---|---|---|---|---|---|
| $x_1$ | 真信号 | 15.8453 | 0.9128 | **+0.32873** | 0.11281 |
| $x_2$ | 弱信号 | 0.8127 | 0.0468 | +0.00123 | 0.01027 |
| $x_3$ | 纯噪声（400 水平） | 0.6004 | 0.0346 | −0.00211 | 0.01105 |
| $x_4$ | 纯噪声（二值） | 0.1000 | 0.0058 | +0.00008 | 0.00368 |

MDI 给的是 $x_1$ 0.9128，置换给的是 0.32873，两者绝对水平不可比（一个是份额，一个是错误率增量），但**排序**一致：$x_1$ 断层第一。分歧出在噪声变量上：MDI 会给 $x_3$ 记 0.6004 分（比弱信号 $x_2$ 的 0.8127 只差一点），置换把它按回 0 附近。

置换那一列的跨树标准差也要一起报：$x_1$ 是 0.11，噪声变量是 0.004。**当两个变量的置换重要度差距小于它的标准差时，排名不可信**——本例里 $x_2,x_3,x_4$ 三者之间的差距（0.003 以内）就小于各自的标准差，所以正确的说法是「除了 $x_1$，其余三个都没有证据说明有用」。

### 条件检验一：基数继续抬，MDI 还会涨吗

表 A 里从 100 到 400，原始累加只从 0.5641 到 0.6004（+6.4%），归一后从 0.0314 到 0.0346。原因是实现里对候选切点做了上限截断（`mids[:30]`），到 100 个取值时就已经超过上限，切点数量不再随取值数增长。**如果不截断，这一列会继续涨**。所以「高基数 → MDI 虚高」的准确说法是「**可用候选切点越多 → MDI 虚高**」：连续变量永远是满分基数，类别变量的水平数超过实现上限之后就不再增加了。

### 条件检验二：加一列 $x_1$ 的完全复制

把 $x_{1b}$ 设成 $x_1$ 的逐行复制（信息量为零重复），重跑同一批设置：

| 特征 | MDI 原始累加 | MDI 归一后 | 置换重要度 |
|---|---|---|---|
| $x_1$ | 9.1540 | 0.4682 | +0.18686 |
| $x_{1b}$ | 9.3343 | 0.4775 | +0.18506 |
| $x_2$ | 0.4955 | 0.0253 | +0.00125 |
| $x_3$ | 0.4433 | 0.0227 | +0.00097 |
| $x_4$ | 0.1226 | 0.0063 | −0.00117 |

对照表 B：$x_1$ 单独时 MDI 15.8453，现在掉到 9.1540（−42%）；置换从 0.32873 掉到 0.18686（−43%）。两个指标**都被复制列分走了一半**，而且两份加起来（MDI 18.4884 / 置换 0.37192）都不比原来小多少。

这一步说明的规矩是：**重要性分数属于「这一组变量」，不属于单个变量**。看到 0.47 和 0.48 两个并列第一，第一件事是查它俩的相关性，而不是二选一删掉。

## 五、什么情况下会失灵

### 承重假设一：样本之间可以互换（i.i.d.）

置换的做法是把一列的取值在行之间随机换位置。它成立的前提是**行之间没有依赖**。

撤掉它的后果：如果 400 行里其实只来自 40 个客户（每人 10 期），打乱「上一期是否出险」这一列，等于把一个客户的历史接到另一个客户身上，模型给出的误差上升里混进了「样本本来就不独立」的部分。此时置换重要度**方向不一定错，但幅度不可解释**，报告里的「+0.33 个误差点」没法对应到任何业务含义。处理：按客户分组做置换（grouped permutation），或者干脆用客户级别的留出集。

### 承重假设二：变量之间的候选切点数差不多

撤掉它的后果就是表 A：两个纯噪声变量，一个 MDI 0.0050、一个 0.0346，差 6 倍——噪声被排出了名次。这个错误在报告里最贵的形态是**删掉了一个真变量**：真变量如果是二值、而竞争者是 300 水平的地区代码，真变量的 MDI 会被压下去。

处理：跨基数比较用置换；必须用 MDI 时，先按基数分组，只在组内比。

### 承重假设三：OOB 行足够多

撤掉它的后果：$n$ 小的时候每棵树的 OOB 只剩几行（$n=100$ 时平均 36.6 行），置换一次动几行，误差估计的随机波动比真实效应还大。噪声变量的置换重要度会出现量级 0.01 的「正值」，和弱信号混在一起。

处理：增大 `n_repeats`、把 OOB 行攒起来算，或者改用留出集（hold-out）——代价是少了一批训练数据。

### 与其他模型的边界

| 场景 | 用谁 | 为什么 |
|---|---|---|
| 快速自查、变量几百个 | MDI | 训练时顺手算，零额外成本 |
| 跨基数比较、要写进报告 | permutation（OOB / holdout） | 不把「候选切点数」算成贡献 |
| 两个变量高度相关 | grouped permutation + PDP | 单独置换会互相顶替，两个都被低估 |
| 要方向（正/负效应） | PDP、SHAP、或换成 GLM | 重要性只有幅度 |
| 要拿 GBM 的重要性去挑 GLM 的变量 | 两边都算 + 业务先验，谨慎 | 树的重要性排的是「切得动」，GLM 要的是「Xβ 线性可加」，两者不是同一件事 |
| 要因果 | 都不行 | 都只描述模型，不描述数据生成过程 |

## 六、常见误解

### 误解一：「MDI 高，就是它重要」

**错误想法**：`feature_importances_` 排前 5 的那几个变量，就是这批数据里的驱动因素。

**为什么容易这么想**：MDI 的名字叫「平均不纯度下降」，听起来完全是「贡献」的意思；而且在只有几个低基数变量的干净数据上，MDI 和置换给出的排序确实一致（表 B 里 $x_1$ 的两个指标都断层第一）。

**错在哪一步**：漏了分母。MDI 的分母是「求和范围 = 被 j 分裂的节点数」，而这个数取决于候选切点数。表 A 里同一个纯噪声列，取值从 2 种到 400 种，原始累加从 0.0942 到 0.6004——变量一个字没改，重要性涨了 6.4 倍。**跨基数比 MDI 时，你比的是切点数量，不是信号强度。**

### 误解二：「重要性是 0.47，说明这个变量的影响是正的」

**错误想法**：重要性分数带符号，或者至少能读出方向。

**为什么容易这么想**：很多模型的解释输出（系数、SHAP 值）是带符号的，习惯被带了过来；而且「重要性」这个词在中文里有一个天然的「好处」联想。

**错在哪一步**：MDI 和置换都只统计**幅度**。$\Delta I$ 是非负量（分裂只会让不纯度不变或下降），置换量的是误差上升，两者在构造上就丢掉了符号。方向要单独算：PDP 看曲线往哪边走、SHAP 看每个样本的贡献是正是负。

### 误解三：「置换在训练集上算就行，样本还多」

**错误想法**：训练集有 12 万行，OOB 只有 4 万行；用全量数据算置换，估计更稳。

**为什么容易这么想**：样本越多估计越准，这是对的；而且训练集就在手边，不用再切数据。

**错在哪一步**：把「样本量」当成了唯一的误差来源。树在训练集上已经把行背下来了，打乱一列之后它还能从相邻取值或相关变量认出这些行，于是误差几乎不涨，所有变量都排在 0 附近。**这是系统性偏差，样本再多也压不下去。** 换到 OOB 行上，同一批变量的差距立刻出来（表 B：0.32873 对 −0.00211）。

### 误解四：「两个相关变量的重要性都很低，那就都删掉」

**错误想法**：$x_5$ 和 $x_6$ 各只有 0.02，加起来还不到 $x_1$ 的零头，留着没意义。

**为什么容易这么想**：默认重要性是可加的分数，0.02 + 0.02 = 0.04 就是这么小。

**错在哪一步**：置换 $x_5$ 时，模型立刻改用 $x_6$ 顶班，误差不涨，于是两个都被记成低分——**分数被分摊了，能力没有消失**。表 A/C 的对照实验就是这个机制的直接读数：$x_1$ 加一个复制列之后，两个都掉到 0.19 附近。判断方法：把它们当一组一起置换，或者分别删掉重训看掉多少分。

## 七、面试怎么答

### 30 秒版

> 随机森林有两套重要性。MDI 在训练时累加每次分裂的不纯度下降、按节点大小加权、再归一化，很便宜但偏向高基数变量——同一个纯噪声列，取值从 2 种到 400 种，MDI 能涨 6 倍。置换重要性把某一列在 OOB 行上打乱，看误差涨多少、跨树平均，代价高一点但更可信，也必须在 OOB 或测试集上算。两个都只给幅度不给方向，遇到相关变量会分摊分数。

### 2 分钟版（三块）

1. **两把尺子量什么**：MDI = 训练期的账本（用了多少次、每次切纯多少）；置换 = 测试期的损失（打乱之后模型错了多少）。指标本身都便宜，区别在于统计对象。
2. **偏置从哪来**：MDI 除以「被选中做分裂的节点数」，而这个数由候选切点数决定，所以高基数变量虚高。置换假定行可互换，所以相关变量互相顶替、样本不独立时幅度不可解释。
3. **报告里怎么写**：跨基数用置换 + 报跨树标准差；相关变量分组置换；方向用 PDP/SHAP；把 OOB/留出指标和重要性放在一起给，避免读者把「分数高」读成「改它能提分」。

### 会被追问到哪

| 追问 | 答法要点 |
|---|---|
| 「MDI 和 permutation 该报哪个？」 | 都要报：MDI 便宜可自查，置换用于对外的结论；两者排序不一致的地方就是需要解释的地方 |
| 「为什么 permutation 不能在训练集上算？」 | 树记住了训练行，打乱后误差几乎不涨 → 系统性低估；换 OOB 立刻显出差距（0.32873 对 −0.0021） |
| 「两个变量重要性加起来 0.9，能说它们解释了 90% 吗？」 | 不能。归一化后的分数是**份额**，分母是「所有变量累计的不纯度下降」，不是「预测能力」 |
| 「重要性高就删了会掉分吗？」 | 不一定。分数说的是「模型现在有用它」，不是「去掉它模型会变差」；真要看这个，得重训或做分组置换 |
| 「GBM 的重要性跟 RF 一样吗？」 | 名称一样、机制一样（split gain / OOB permutation），但 GBM 的树是串行拟合残差的，前面的树贡献被后面的掩盖，排名更不稳 |
| 「要不要用重要性做变量筛选？」 | 可以当粗筛，别当判据：先按相关组聚合、跨基数统一用置换，最后用留出集验证删变量前后的分数 |

## 🗣️ 英文表达 / How to Say It

**30-second version**

> "There are two standard measures. MDI sums the impurity reduction every time a feature is used to split, weighted by the node size, and normalises it. Permutation importance shuffles one feature and measures how much the metric drops, then averages across trees."

**Mechanism**

> "The important implementation detail is where the permutation happens. It has to be on out-of-bag or held-out data — per tree, on the rows that tree didn't see — and then averaged. On the training data the model has already memorised the pattern, so shuffling barely changes anything and you badly understate the feature's real role."

**If they push back**

> "A common pitfall is comparing MDI across features with different cardinality. A variable with many levels gets more chances to split, so its importance is inflated; I'd use permutation for cross-cardinality comparisons and still treat it with care. Also, when two features are highly correlated they share the credit and both look unimportant, so I'd permute them as a group. And importance tells you magnitude, not direction — for direction I'd look at partial dependence or SHAP."

## 🔤 本页术语 / Key Terms

| 中文 | English | 一句话 |
|---|---|---|
| 特征重要性 | feature importance | 变量对模型预测贡献的量化，本页有两套 |
| 不纯度平均下降 | mean decrease in impurity (MDI) | 分裂带来的不纯度下降，按节点大小加权累加后归一化 |
| 基尼重要性 | Gini importance | MDI 在分类树上的别名（R 里 `type=2`） |
| 置换重要性 | permutation importance | OOB 上打乱一列后误差的上升，跨树平均 |
| 平均准确率下降 | mean decrease in accuracy | permutation 在分类上的常见叫法（R 里 `type=1`） |
| 袋外样本 | out-of-bag (OOB) samples | bootstrap 没抽到的行，可当内部验证集 |
| 基数 | cardinality | 变量的不同取值个数，决定候选切点数 |
| 分裂机会数偏置 | split-opportunity bias | MDI 偏袒候选切点多的变量 |
| 归一化 | normalisation | 让各变量 MDI 合计为 1，只在同一模型内可比 |
| 分组置换 | grouped permutation | 把一组相关变量一起打乱，避免互相顶替 |
| 置换次数 | n_repeats | 每个变量重复打乱的次数，决定结论稳定性 |
| 跨树标准差 | standard deviation across trees | 置换重要度的不确定性，排名差距小于它就别排名 |
| 偏依赖图 | partial dependence plot (PDP) | 看方向与形状，补齐重要性缺的信息 |
| H 统计量 | H-statistic | 用 PDP 分解出的交互强度 |
| SHAP 值 | SHAP values | 逐样本的加性贡献分解，可给方向 |
