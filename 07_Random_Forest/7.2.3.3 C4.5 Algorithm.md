# C4.5：用增益率修掉 ID3 的多取值偏好（C4.5 Algorithm）

<!-- priority-banner -->
> [!important] 优先级 **⭐⭐ 高频** ｜ 重点：增益率・缺失值・误差剪枝
> 🚀 捷径：[[02. 三条学习路径]] ・ 📋 公式：[[04. 公式速查卡]] ・ ✅ 自测：[[99.3 决策树]] ・ 🔎 追问：[[05. 高频追问 TOP 30]]

## 速览 At a glance

**速记**

C4.5 保留了 ID3 的生长循环，只把「选哪个属性」这一步换掉：不再比裸的**信息增益（information gain）**，而是比**增益率（gain ratio）**——增益除以**分裂信息（split information）**，一个只由「这次把数据切成了几块、每块多大」决定的量。它修的是 ID3 的多取值偏好：取值越多，切出来的格子越碎也越容易纯，增益被抬高；分母跟着变大，正好把这份虚高抵掉。本页用同一份 10 笔保单算给你看：城市的增益 $0.570951$ bits 是出险 $0.256426$ 的 2.2 倍，ID3 选城市；除以分裂信息后城市掉到 $0.245895$、出险 $0.264098$，C4.5 选回出险。分母也有失灵的时候——切到每笔一个编号，增益顶到父熵、增益率 $0.292285$ 反超，所以 C4.5 还得配一道「增益不低于平均值」（本页数据里是 $0.223447$ bits）的门槛，先筛掉两个弱候选。另外三处改动同样重要：连续变量排序一次线性扫描、缺失值用分数实例加权、长完做基于误差的后剪枝。

**一句面试答法**

> "C4.5 is ID3 plus four fixes. The headline one is the gain ratio: gain divided by the split information, which only depends on how many parts the split creates and how big they are, so it cancels the bias toward high-cardinality features. It's not a complete fix — the ratio can over-reward features with a tiny denominator, which is why C4.5 first drops any attribute whose gain is below average. The other three fixes are on continuous variables, missing values through fractional instance weighting, and error-based post-pruning."

**术语**

| 中文 | English | 一句话 |
|---|---|---|
| 分裂信息 | split information | $-\sum_v w_v\log_2 w_v$，只看切了几块、每块多大 |
| 增益率 | gain ratio | 信息增益 / 分裂信息，C4.5 的分裂准则 |
| 多取值偏好 | bias toward multi-valued attributes | 取值越多，增益越容易虚高 |
| 平均增益门槛 | average-gain threshold | 先丢掉增益低于平均的属性，再比增益率 |
| 分数实例加权 | fractional instance weighting | 缺失值的样本按权重分到每一条分支 |
| 基于误差的剪枝 | error-based pruning | 长满后自底向上，把估计误差更差的子树换成叶子 |
| 连续性修正 | continuity correction | $\hat p=\frac{E+1/2}{N+1}$，避免小子树上误差估计为 0 |
| 悲观误差 | pessimistic error | 把训练集上的子树误差估得比实际更差一点，用来决定剪不剪 |

## 一、先看一个问题

一份 10 笔保单的数据：**6 笔续保、4 笔不续保**，四个候选特征——**近 3 年是否出险**（2 档）、**城市**（5 档，每城 2 笔）、**是否新车**（2 档）、**是否自动续保**（2 档）。

同事用 ID3 建了一棵，根节点是**城市**。业务看了一眼就问：为什么先看城市？城市只是记录字段，跟续保续不续有什么关系。

这个问题不好回答，因为同事的树没有算错。按 ID3 的准则，城市的分数就是更高：$0.570951$ bits 对 $0.256426$ bits。城市把 10 笔切成 5 个格子，其中 3 个格子各 2 笔、标签恰好一致，熵是 0——**增益看见的是这三个 0，看不见「2 笔」这个样本量**。

C4.5 在同一份数据上会选**出险**。它没有改循环，甚至没有改增益的算法，只是在增益下面加了一个分母：**分裂信息（split information）**，一个只由「切了几块、每块多大」决定的量。第四节会把这一步算出来——

| 候选 | $\operatorname{Gain}$ | $\operatorname{SI}$ | $\operatorname{GainRatio}$ | ID3 选 | C4.5 选 |
|---|---|---|---|---|---|
| 近 3 年有出险（2 档） | 0.256426 | 0.970951 | **0.264098** | | ✅ |
| 城市（5 档） | **0.570951** | 2.321928 | 0.245895 | ✅ | |
| 是否新车（2 档） | 0.046439 | 0.970951 | 0.047829 | | |
| 是否自动续保（2 档） | 0.019973 | 0.970951 | 0.020571 | | |

——名次在最后一列翻了回来。后两行连决赛都没进：C4.5 会先用「增益不低于平均值」（本页数据里是 $0.223447$ bits）把它们筛掉，那是它防分母过小的保险。

本页的分工：熵与信息增益怎么算、为什么贪心能成立，在 [[7.2.2.3.1 ID3 Algorithm]]（那一页把两个分数字算到了小数点后六位）；**本页负责说清分母为什么能修掉那个偏好、又修不掉什么**。分裂准则的全景在 [[7.2.2 Decision Tree]]，二分与 Gini 在 [[7.5 CART Algorithm]]。题库里的落点是 Q7「为什么信息增益偏爱取值多的特征？增益率怎么修？」。

## 二、核心直觉

### 2.1 先回顾 ID3 的两个量

决策树在每个节点只做一件事：问一个关于属性的*问题*，让子节点尽量纯。

* **目标**：尽可能快（问题数少）又尽可能准地预测新样本的类别。
* **思路**：每个内部节点针对一个属性问一个*问题*。

  * 最好的「第一个问题」，是那个能让后续问题都变简单的问题——也就是让子节点尽可能纯的问题。

纯度用**熵（entropy）**量：

$$
H(S)= -\sum_{c} p(c)\log_2 p(c)
$$

| 直觉                                                                      | 翻译                                                                         |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| *如果做完美压缩，平均要用几个 bit 才能把类别标签「说」出去？* | 熵高 ⇒ 你要学的东西还很多；熵低 ⇒ 几乎已经确定是哪一类 |

把纯度变成一条贪心规则：

1. **问完属性 $A$ 之后的期望不纯度**

   $$
   \overline{H}(S,A)=\sum_{v}\frac{|S_v|}{|S|}\,H(S_v)
   $$
2. **信息增益**（知道 $A$ 之后省下的 bit 数）：

   $$
   \text{Gain}(S,A)=H(S)-\overline{H}(S,A)
   $$
3. **贪心选择**：选 Gain *最大* 的 $A$；然后在每条分支里重复同样的动作。

> **为什么这里贪心能成立**
> 总的期望 bit 数 = 根节点问题的 bit 数 + 走到的那条分支里的 bit 数。
> 要让总和最小 ⇒ 先让第一项最小，*然后*再递归（这就是最优子结构性质 optimal-substructure property）。

### 2.2 ID3 里如何处理连续属性

* 在节点上把取值排序一次。
* 在每个「类别标签发生变化」处取中点作为候选切点。
* 把每个阈值当成一个两值属性来计算 Gain。

这套做法能用，但每个节点都要重排一次、每个阈值都要重算一遍增益。C4.5 把它改成了「排序一次、线性扫一遍」（3.3），这也是它跟 ID3 的第一处工程差别。

### 2.3 直觉：增益的刻度随「切了几块」漂
把分裂想成一次报销：你报了多大的一笔收益（增益），就得附上这次分裂开了几张发票（切了几块）。

* **收益是标签给的**：增益算的是类别混乱度掉了多少，跟标签有关系。
* **费用是结构给的**：$-\sum_v w_v\log_2 w_v$ 只看每块占多大比例，**跟标签完全无关**。切成 2 块各一半，它等于 1 bit；切成 5 块各 20%，它等于 $\log_2 5 = 2.321928$ bits。
* **比值就是「每张发票换了多少收益」**：切得越碎，费用越大，同样一笔收益的比值就越小。

ID3 的毛病在于只看收益、不看费用。取值多的属性天然能把数据切碎，格子小了就容易纯，收益被抬高——城市那 3 个纯格子就是费用没被计进去的直接后果。

**像什么、不像什么**：像按发票张数收费——**像的地方**是费用确实跟着「切了几块」涨。**不像的地方**是报销好歹还看看发票金额，而 SI 连金额都不看：切 2 块各一半和切 2 块 99% 比 1%，后者的费用只有 $0.080793$ bits，小得多。这就是增益率反过来偏爱「几乎不分裂」的属性的根源，3.1 末尾会讲到怎么用门槛兜住它。

### 2.4 ID3 的四个要害弱点（C4.5 的改动清单）

| 问题                                  | 症状                       | 根因                              |
| ---------------------------------------- | ----------------------------- | --------------------------------------- |
| 偏爱取值特别多的属性 | 「ZIP code」压过一切   | Gain 只要把数据切得够薄就会涨 |
| 树会爆炸                        | 出现只含单个样本的细枝          | 没有剪枝环节                         |
| 每个节点都对数值列重新排序    | 每个属性 $O(n\log n)$    | 朴素的「每个分裂都试一遍」                 |
| 无视缺失值里的结构      | 要么丢行，要么粗暴插补 | 可能浪费数据或引入偏差                  |

先记住这四条——下面把它们逐一修好。第一条对应 3.1 的增益率，第二条对应 3.3 的误差剪枝，第三条对应 3.3 的线性扫描，第四条对应 3.3 的分数实例加权。

## 三、机制

### 3.1 定义与逐项说明

#### 分裂信息与增益率

1. *分裂信息（Split-Info）*（「光凭 $A$ 就把数据切得多碎？」）

   $$
   \text{SplitInfo}(S,A)= -\!\!\sum_{v}\frac{|S_v|}{|S|}\log_2\frac{|S_v|}{|S|}
   $$

   逐项读：$|S_v|/|S|$ 是第 $v$ 条分支的样本占比（权重），对数只吃这个权重——**这一项里没有标签**，所以它测的是划分的结构，不是划分的好坏。
2. *增益率*

   $$
   \text{GainRatio}(S,A)=\frac{\text{Gain}(S,A)}{\text{SplitInfo}(S,A)}
   $$

   分子是标签带来的收益（比特），分母是结构带来的「碎片程度」（比特）。比值没有单位，只用来在候选之间排序。
3. **选属性的规则**

   * 先把 Gain 低于平均值的属性全部丢掉（防止分母过小导致虚高）。
   * 再在剩下的里面选正增益率最高的那个。

   这两步缺一不可：只比增益率会被「几乎不分裂」的属性骗到（下一个例子），只比增益就是 ID3 的老毛病。

*效果*：惩罚那些只会「把标签打散」、却不能真正分开类别的提问。

**一个极小的对照**：两个候选、父熵随便取 $1$ bit。候选甲切成 2 块各一半 → $\mathrm{SI} = 1$；候选乙切成 2 块 99% : 1% →

$$
\mathrm{SI} = -\Bigl(0.99\log_2 0.99 + 0.01\log_2 0.01\Bigr) = 0.080793\ \text{bits}
$$

分母只剩不到十分之一，**同样的增益一到乙手里就会被放大 12 倍**。这就是「先丢掉增益低于平均值的属性」这道门槛存在的理由——它不是锦上添花，是防反向偏置的必需品。

### 3.2 它是怎么来的：分母为什么能抵消偏置

**关键一步在这里**：增益之所以会被取值个数带跑，是因为「切得越碎，加权子熵越接近 0」——这是**结构**造成的，不是标签造成的。而 SI 是同一个结构的函数：切得越碎，它越大。一个随取值个数上升的量做分母，正好能抵消掉另一个随取值个数上升的量。

把这件事推到极端就能看清比例关系。设父集合有 $n$ 笔、属性 $A$ 每档恰好 1 笔（比如保单号），那么每一档都纯：

$$
\operatorname{Gain}(S,A) = H(S) - 0 = H(S),\qquad
\mathrm{SI}(S,A) = \log_2 n
$$

于是

$$
\operatorname{GainRatio}(S,A) = \frac{H(S)}{\log_2 n}
$$

增益**顶到了上界** $H(S)$（父节点的熵就是增益的天花板），而分母跟着档数 $n$ 一起涨——编号越细，比值掉得越多。对比 ID3：它的分数在 $\log_2 n$ 这一族属性上**全部相同**、全部等于 $H(S)$，名次完全分不出来；增益率至少给了它一个随 $n$ 单调下降的分数。这就是「增益率能修掉偏好」的机制层面解释（修到什么程度，第四节的算例会给出边界）。

循环本身不用动：熵不变、加权不变、递归不变，只是把 $\arg\max \operatorname{Gain}$ 换成「先过滤、再 $\arg\max \operatorname{GainRatio}$」。

### 3.3 变形与口径

#### 让树保持可控：**基于误差的剪枝（Error-Based Pruning）**

1. **先把树长满**，和 ID3 完全一样。
2. **自底向上扫一遍**

   * 对一个有 $N$ 个加权样本、$E$ 个错误的子树，估计其错误率
     $\hat{p}=\dfrac{E+\frac12}{N+1}$。
   * 如果把这个子树换成一个**叶子**（并加上复杂度惩罚后）估计错误数更低，就剪掉。
3. **结果**：树更小、更不容易过拟合，也更好读。

逐项读那个估计式：$E/N$ 是子树在训练集上的错误率，分子加 $1/2$、分母加 $1$ 是**连续性修正（continuity correction）**——不加它，一个 $E=0$ 的小子树会被估成「零错误」，永远不会被剪掉，而它的零错误多半只是样本太少。

#### 给数值分裂加速

* 在*根节点*对每个数值属性**只排序一次**（代价 $n\log n$）。
* 对每个后代节点：

  * 沿着已经排好序的列表从左往右扫，同时维护各类的滚动计数。
  * 只在**标签发生变化的边界**处评估 Gain / Gain Ratio——耗时与到达该节点的样本数成线性。

对照 ID3 的做法：每个节点、每个数值属性都要重新排一次序，所以每层都要付 $O(n_a\log n_a)$；C4.5 把排序费降成一次性支出，代价是要把每行样本的类别计数带着往下走。

#### 更聪明的缺失值处理：**分数实例加权（Fractional Instance Weighting）**

* 按属性 $A$ 分裂时，$A=?$ 的样本会被*按分数复制*到每一条分支上。

  * 分到分支 $v$ 的权重：正比于该节点上已知样本里 $v$ 出现的频率。
* 所有计数（增益、剪枝误差）都用这些权重，于是既不丢数据，也不需要任何全局猜测。

和插补的区别值得说清：插补**造出一个值**（均值、众数、众数池抽样），这个假值之后会参与所有计算；分数加权**不碰特征值**，只是让这一行在每条分支上各占一部分权重。预测一个新样本时也是这样：$A$ 缺失就沿所有分支走，把各叶子的结果按权重合成一个输出。

#### C4.5 算法骨架

```text
function C45(S, Attr):
    if stop(S): return Leaf(majority(S))
    bestA ← argmax GainRatio(S, Attr)      # numeric branch uses one-pass scan
    node  ← DecisionNode(bestA)
    for each branch b of bestA:
        Sb ← weightedSubset(S, bestA = b)  # weights handle missing values
        if Sb is empty:
            node.addBranch(b, Leaf(majority(S)))
        else:
            node.addBranch(b, C45(Sb, Attr))
    return PostPrune(node)                 # error-based pruning
```

*注意*：控制流仍然是那套熟悉的 ID3 循环，变的只是几个辅助函数。

#### 复杂度与实际收益

| 方面                      | ID3                | C4.5 的改进              | 什么时候重要                          |
| --------------------------- | ------------------ | ----------------------------- | ---------------------------------------- |
| 每个节点的数值分裂成本 | $O(n_a\log n_a)$   | $O(n_a)$                      | 浮点特征很多的数据集                |
| 属性偏置              | 高（偏爱多取值） | 由增益率控制      | 类别取值词表很大的数据 |
| 树的规模                   | 可能巨大   | 剪枝后小 25-50 % | 标签含噪、要求可解释性           |
| 缺失数据                | 丢弃 / 朴素填补  | 分数路由（fractional routing）            | 问卷数据、传感器缺口                     |

$n_a$ = 到达该节点的样本数。

#### 一句话心智模型

> **ID3** 问的是那个能最快砍掉不确定性的问题。
> **C4.5** 依然这么做——但它会检查这个问题是不是在「作弊」，会剪掉爱吹牛的子树，飞快地扫过数值，并且优雅地处理空值。

## 四、算一遍

用第一节那 10 笔保单。数据、熵、增益的数字和 [[7.2.2.3.1 ID3 Algorithm]] 完全一致，只多了一件事：C4.5 的第一道筛子要用平均值，所以四个候选得全部摆上桌。

| 保单 | 近 3 年有出险 $A$ | 城市 $B$ | 是否新车 $C$ | 是否自动续保 $D$ | 续保 $y$ |
|---|---|---|---|---|---|
| 1 | 否 | 广州 | 否 | 否 | 续 |
| 2 | 是 | 上海 | 否 | 是 | 续 |
| 3 | 否 | 杭州 | 是 | 否 | 续 |
| 4 | 是 | 上海 | 否 | 是 | 不续 |
| 5 | 是 | 深圳 | 是 | 否 | 不续 |
| 6 | 否 | 北京 | 否 | 是 | 续 |
| 7 | 否 | 深圳 | 是 | 否 | 不续 |
| 8 | 否 | 广州 | 是 | 否 | 续 |
| 9 | 是 | 北京 | 是 | 是 | 不续 |
| 10 | 否 | 杭州 | 是 | 否 | 续 |

### 第 1 步：父节点的熵，以及四个候选的增益

$$
H(S) = -\Bigl(\tfrac{6}{10}\log_2\tfrac{6}{10} + \tfrac{4}{10}\log_2\tfrac{4}{10}\Bigr) = 0.970951\ \text{bits}
$$

* **出险**：是 4 笔（1 续 / 3 不续）、否 6 笔（5 续 / 1 不续）→
  $\overline{H}(S,A) = \tfrac{4}{10}(0.811278) + \tfrac{6}{10}(0.650022) = 0.714525$，
  $\operatorname{Gain}(S,A) = 0.970951 - 0.714525 = 0.256426$ bits。
* **城市**：上海 1∶1、北京 1∶1、广州 2∶0、杭州 2∶0、深圳 0∶2 →
  $\overline{H}(S,B) = \tfrac{2}{10}(1)+\tfrac{2}{10}(1)+0 = 0.400000$，
  $\operatorname{Gain}(S,B) = 0.970951 - 0.400000 = 0.570951$ bits。
* **是否新车**：是 6 笔（3 续 / 3 不续，$H=1$）、否 4 笔（3 续 / 1 不续，$H=0.811278$）→
  $\overline{H}(S,C) = \tfrac{6}{10}(1)+\tfrac{4}{10}(0.811278) = 0.924511$，
  $\operatorname{Gain}(S,C) = 0.970951 - 0.924511 = 0.046439$ bits。
* **是否自动续保**：是 4 笔（2 续 / 2 不续，$H=1$）、否 6 笔（4 续 / 2 不续，$H=0.918296$）→
  $\overline{H}(S,D) = \tfrac{4}{10}(1)+\tfrac{6}{10}(0.918296) = 0.950978$，
  $\operatorname{Gain}(S,D) = 0.970951 - 0.950978 = 0.019973$ bits。

到这里 ID3 已经做完了选择：$0.570951$ 是四个增益里最大的，**选城市**。

### 第 2 步：给四个候选各算一个分母

$$
\mathrm{SI}(S,A) = -\Bigl(\tfrac{4}{10}\log_2\tfrac{4}{10}+\tfrac{6}{10}\log_2\tfrac{6}{10}\Bigr) = 0.970951\ \text{bits}
$$

$$
\mathrm{SI}(S,B) = -5\times\Bigl(\tfrac{2}{10}\log_2\tfrac{2}{10}\Bigr) = 5 \times 0.464386 = 2.321928\ \text{bits}
$$

$C$ 与 $D$ 都是二值、两支的样本数都是 6∶4，所以分母可以直接抄 $A$ 的：

$$
\mathrm{SI}(S,C) = \mathrm{SI}(S,D) = -\Bigl(\tfrac{6}{10}\log_2\tfrac{6}{10}+\tfrac{4}{10}\log_2\tfrac{4}{10}\Bigr) = 0.970951\ \text{bits}
$$

（$A$、$C$、$D$ 三个的 SI 都恰好等于 $H(S)$，因为它们的切法都是 4∶6 或 6∶4、跟类别比例撞了车。SI 里没有任何标签信息，这个相等是巧合。）

### 第 3 步：除法，以及门槛检查

$$
\operatorname{GainRatio}(S,A) = \frac{0.256426}{0.970951} = 0.264098,\qquad
\operatorname{GainRatio}(S,B) = \frac{0.570951}{2.321928} = 0.245895
$$

$$
\operatorname{GainRatio}(S,C) = \frac{0.046439}{0.970951} = 0.047829,\qquad
\operatorname{GainRatio}(S,D) = \frac{0.019973}{0.970951} = 0.020571
$$

**门槛检查**：C4.5 的第一道筛子是「丢掉增益低于平均值的属性」。四个候选的平均增益是

$$
\frac{0.570951 + 0.256426 + 0.046439 + 0.019973}{4} = \frac{0.893789}{4} = 0.223447\ \text{bits}
$$

对着这个门槛看一遍——城市 $0.570951$ 过，出险 $0.256426$ 过，新车 $0.046439$ 出局，自动续保 $0.019973$ 出局。**留在桌上的是城市和出险**，名次由增益率决定：$0.264098 > 0.245895$，**C4.5 选出险**。

门槛的脾气值得记一句：它不参与排名，只负责把明显不配参赛的候选请出去。这道题就算不做门槛，四个增益率里的最大值也是出险的 $0.264098$——门槛在这里是保险，不是决定项。

### 第 4 步：那一步到底改了什么

| 候选 | $\operatorname{Gain}$ | ID3 名次 | $\mathrm{SI}$ | $\operatorname{GainRatio}$ | C4.5 名次 |
|---|---|---|---|---|---|
| 出险 | 0.256426 | 第 2 | 0.970951 | **0.264098** | 第 1 ✅ |
| 城市 | **0.570951** | 第 1 ✅ | 2.321928 | 0.245895 | 第 2 |
| 是否新车 | 0.046439 | 第 3 | 0.970951 | 0.047829 | 第 3（门槛外） |
| 是否自动续保 | 0.019973 | 第 4 | 0.970951 | 0.020571 | 第 4（门槛外） |

**具体的那一步就是分母**：城市的增益比出险高 $0.570951-0.256426 = 0.314525$ bits，而它的分裂信息比出险高 $2.321928-0.970951 = 1.350977$ bits。收益多出来的那部分（约 0.31）顶不住费用多出来的那部分（约 1.35），比值于是反转。ID3 看不到 SI 那一列，所以它选错；C4.5 看得见。

### 条件检验：什么时候增益率也修不好

同样是这 10 笔数据，只改「城市」这一列的粒度：

| 城市切成几档 | 每档样本 | $\operatorname{Gain}$ | $\mathrm{SI}$ | $\operatorname{GainRatio}$ | 冠军 |
|---|---|---|---|---|---|
| 2 档（一线 / 非一线） | 6 + 4 | 0.019973 | 0.970951 | 0.020571 | 出险 0.264098 |
| 5 档（原样） | 2 × 5 | 0.570951 | 2.321928 | 0.245895 | 出险 0.264098 |
| 10 档（每笔一个编号） | 1 × 10 | 0.970951 | 3.321928 | **0.292285** | **编号** |

三种粒度下，SI 单调上升（$0.970951 \to 2.321928 \to 3.321928$）说明分母确实在按「切得多碎」收费。但最后一行的结果不好看：**每档 1 笔时，增益顶到父熵 $0.970951$，增益率 $0.292285$ 反超出险的 $0.264098$，C4.5 也会选编号。**（第一行那个 $0.019973$ 与「是否自动续保」的增益一模一样，因为两者都是 6∶4 的切法、两支的类别比例也相同——纯属巧合，不是同一个变量。）

原因不难看出：编号属性的增益已经顶到上界，分母再大也只是把它从 $0.970951$ 压到 $0.292285$，而一份 2 档属性的增益本来就只有 $0.256426$，能压的空间更小。**增益率把偏好从「越多取值越好」改成了「取值多到极致仍然可能占优」**，它削弱了偏置，没有消除偏置。工程上的兜底是「先丢掉增益低于平均的属性」那道门槛、限制候选属性的取值个数，以及在最终模型上做剪枝或交叉验证——这三件事 C4.5 或它的使用者也都要做。

## 五、什么情况下会失灵

### 承重假设一：分母的大小与「切碎程度」成正比

整条修正链建立在「SI 越大 ⇒ 切得越碎 ⇒ 增益越虚」这个对应关系上。

撤掉它的后果就在条件检验最后一行：每档 1 笔时增益顶到上界，SI $= \log_2 10 = 3.321928$ 虽然最大，除以它之后的 $0.292285$ 仍然高于一个只有 2 档的真变量（出险 $0.264098$）。换句话说，**只要一个属性的增益接近上界，分母就救不回来**。这类属性在现实里到处都有：保单号、客户 ID、时间戳、地址字符串。处理办法是建模前把它们从候选里剔掉，或者设一个取值个数上限。

### 承重假设二：反过来那半边偏好可以被门槛挡住

分母小的时候增益率会飙高：2 块 99% : 1% 的分裂，$\mathrm{SI} = 0.080793$ bits（本节 3.1 的计算）。因为这个分母极小，任何一点增益都会被放大十几倍。

撤掉它的后果：一个几乎不分裂的属性（比如 99% 的样本都取同一个值的字段）会因为分母小而拿到很高的增益率。C4.5 的对策是先算一遍增益、只在**增益不低于平均值**的属性里比增益率；但平均值不是判据——候选少的时候它会被一个极端值拉走，候选多的时候又会把增益中等、其实有信息的属性一起误伤。本页算例里它只做了一件保险的事（筛掉新车和自动续保），名次仍然由增益率决定。工程上还有两种常见补充：把「增益大于零」当硬门槛，或者直接按取值个数设上限。

### 承重假设三：训练集上的误差估计能代表泛化

误差剪枝用的是 $\hat p=\frac{E+1/2}{N+1}$，$E$ 和 $N$ 都来自**训练集**（带分数权重）。

撤掉它的后果：子树越小，这个估计越不可靠——连续性修正能避免「$E=0$ 就永不剪」的极端，但换不来无偏。剪得太狠会欠拟合（把本来有用的分支当噪声砍掉），剪得太松等于没剪（只含单个样本的枝条还在）。所以在要求稳定性的场景，用留出集或交叉验证来定剪枝点通常更靠得住（对比见 [[7.2.2.4. Pruning Decision Trees]] 与 [[7.5 CART Algorithm]] 的代价复杂度剪枝）。

### 承重假设四：缺失是随机的

分数实例加权按「该节点上已知样本里取值 $v$ 的频率」给缺失样本分配权重，这个做法默认缺失与取值本身无关（缺失随机）。

撤掉它的后果：如果一个字段的缺失**本身有含义**（高端客户不填收入、老客户不填投保年限），按已知样本的频率分配会把缺失样本塞进一个不代表它们的分布里，增益和剪枝误差都被这份偏差污染。此时更稳的做法是把「是否缺失」单独做成一个指示变量，或者接受丢行。

### 与其他算法的边界

| 场景 | 用谁 | 为什么 |
|---|---|---|
| 类别属性取值多、还有缺失值 | C4.5 | 增益率罚多取值，分数加权不用丢行 |
| 需要回归、或要求严格二分 | CART | Gini / SSE + 二叉 + 代价复杂度剪枝 |
| 只要规则清单、要能读 | C4.5（剪枝后） | 多路分裂 + 规则抽取，条件写成 `if 属性 = 值` |
| 属性取值极多且都是噪声 | 先剔列再建树 | 增益率对每档 1 笔的编号也失灵（第四节末） |

### C4.5 的强项——以及 [[7.5 CART Algorithm| CART]] 在哪里接手

从 C4.5 到 CART 是同一类升级：循环不动，换掉「怎么打分、怎么切、怎么剪」这三件事。

C4.5 是 ID3 的稳健、可上生产线的扩展：它解决了属性偏置、过拟合、数值脆弱性这些痛点，同时保留了原来的递归循环。但它仍然继承了一些设计选择——这些选择虽然优雅，却不是唯一做法：

| C4.5 继承下来的特点                                                             | 为什么有时会成为限制                                      | CART 的替代方案                                                          |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| **默认多路分裂（multi-way splits）**<br>每个类别特征可能长出很多分支 | 增加复杂度；更难可视化或导出成规则系统 | **只做二分（binary splits）**——树更简单，更容易转换与剪枝           |
| **基于熵的打分**<br>需要对数与分数 bit                | 数学上很讲道理，但更慢，尤其在大数据集上      | **Gini 不纯度 / MSE**——算得更快，效果往往一样好          |
| **靠误差估计做预剪枝**<br>一边长一边剪枝               | 在信息还不完整时就做剪枝决策               | **代价复杂度后剪枝（cost-complexity pruning，`ccp_alpha`）**——看到完整子树后再评估 |
| **内建缺失值处理**                                                 | 很优雅，但在 C4.5 之外不是标准做法                                | CART 不做这件事，假定由预处理或更简单的处理方式来解决        |

> **关键结论**：C4.5 在生长过程中就建成更聪明的树——而 **CART** 问的是另一个问题：能不能让树先长满、用更快的分裂准则、等看清全貌之后再剪枝？

## 六、常见误解

### 误解一：「C4.5 只是在 ID3 上改了个公式」

**错误想法**：把信息增益换成增益率，循环没动、伪代码没动，所以 C4.5 就是 ID3 加一个除法。

**为什么容易这么想**：从算法骨架上看确实如此——选属性、按分支递归、空分支回落多数类，四行代码和 ID3 一模一样；而增益率也只是把分子除以一个数。

**错在哪一步**：C4.5 一共改了四处，公式只是第一处。**连续变量**：ID3 要你先把数值列离散化（2.2 那三条），C4.5 在根节点排序一次、后代节点线性扫候选阈值（3.3）。**缺失值**：ID3 只能丢行或用众数/均值填掉，C4.5 用分数实例加权把样本按权重分到每条分支上。**剪枝**：ID3 完全没有，C4.5 长满之后自底向上做基于误差的剪枝。这四项各自对应 2.4 那张弱点表里的每一行。面试里被问「C4.5 和 ID3 的区别」，只答增益率会漏掉一半分数。

### 误解二：「增益率把多取值偏置治好了」

**错误想法**：既然增益率罚了取值多的属性，那 C4.5 就比 ID3 稳、不会再挑出 ID 这种字段。

**为什么容易这么想**：ID3 篇算例里那步修正确实漂亮——5 档城市的增益从第 1 名掉到第 2 名，比值 $0.245895$ 对 $0.264098$，看起来一刀切干净了。

**错在哪一步**：把「削弱」当成了「消除」。分母能抵消的只是**平均值上**的漂移，遇到增益顶到上界的属性（每档 1 笔的编号）它压不住：本页条件检验最后一行，编号的增益率 $0.292285$ 仍然高于真变量出险的 $0.264098$。而且这个分母有自己的尾症——$\mathrm{SI}$ 小的时候（2 块 99% : 1% → $\mathrm{SI} = 0.080793$）增益率会虚高十几倍，这才是「先丢掉增益低于平均值的属性」那道门槛真正在防的东西。修正是有方向的，收尾动作在门槛、在列筛选、在剪枝。

### 误解三：「分数实例加权就是换了个花样的插补」

**错误想法**：缺失值总得有个去处，C4.5 无非是按频率把它摊到各条分支上，说白了还是一种插补。

**为什么容易这么想**：两者看起来都在「给缺失的样本一个安排」，而且都用到已知样本的分布来定权重。

**错在哪一步**：插补是**往数据里写一个不存在的值**（均值 82.4、众数「华东」），这个假值之后会进入所有计算，还会把那一格的不纯度算低；分数加权**不造值**，只给这一行一个分数权重，让它同时属于几条分支。差别在后果上：插补出来的「均值客户」会被算成一个真实的计数，而加权样本在增益和剪枝误差里永远以分数出现，预测时也是沿所有分支加权合成。代价是计数不再是整数、实现更绕，也得假定缺失与取值无关（见第五节承重假设四）。

## 七、面试怎么答

### 30 秒版

> C4.5 保留 ID3 的生长循环，把分裂准则换成增益率：增益除以分裂信息，而分裂信息只看「切了几块、每块多大」，与标签无关。取值多的属性天然切得碎、增益虚高，分母跟着涨就把这份虚高抵掉——同一份数据上 ID3 选城市（增益 0.570951 对 0.256426），C4.5 选出险（增益率 0.264098 对 0.245895）。修正不彻底：每档 1 笔的编号增益率反而更高，所以还要先用平均增益过滤一轮。另外三处改动是连续变量、缺失值分数加权和误差剪枝。

### 2 分钟版（三块）

1. **准则怎么修**：$\operatorname{GainRatio} = \operatorname{Gain}/\mathrm{SI}$，$\mathrm{SI} = -\sum_v w_v\log_2 w_v$。增益随取值个数上升、SI 也随取值个数上升，一个做分子一个做分母正好对冲；换成编号属性看极限，增益顶到 $H(S)$、SI 顶到 $\log_2 n$，比值随档数单调下降，而 ID3 在这一族属性上分数**完全相同**。
2. **修到什么程度**：本页算例把 2 档、5 档、10 档并排放：5 档能纠正（0.245895 < 0.264098），10 档不行（0.292285 > 0.264098）。再加上分母小的时候会反向偏（SI = 0.080793），所以门槛是必需品。
3. **其余三处与边界**：连续变量排序一次线性扫、缺失值分数实例加权、长满后误差剪枝；C4.5 仍是多路分裂、仍要算对数、剪枝仍是启发式，最终让位给 CART 的二分 + Gini + 代价复杂度剪枝。

### 会被追问到哪

| 追问 | 答法要点 |
|---|---|
| 「增益率为什么能修掉多取值偏好？」 | 增益和 SI 都是「取值个数」的上升函数，一个做分子一个做分母；极端情形（每档 1 笔）增益顶到 $H(S)$、SI $=\log_2 n$，比值随 $n$ 单调下降 |
| 「它有没有副作用？」 | 有，方向相反：SI 小的时候增益率虚高（2 块 99%∶1% → SI 0.080793）。所以先丢掉增益低于平均的属性再比比值 |
| 「门槛一定管用吗？」 | 它只保证赢家的增益不低于平均，不是泛化保证；平均值会被极端值拉动，也会误伤增益中等的属性。本页算例里它筛掉了两个弱候选，名次仍由增益率决定 |
| 「连续变量怎么处理？」 | 根节点排序一次，后代节点顺着已排序列表扫、维护滚动计数，只在标签变化的边界评估准则；每节点线性 |
| 「缺失值怎么处理？」 | 分数实例加权：按已知样本里取值出现的频率把缺失样本分到各分支，权重一路带到增益与剪枝误差；不造假值，预测沿所有分支加权合成 |
| 「剪枝是怎么做的？」 | 长满后自底向上，子树估计误差率 $\hat p=(E+1/2)/(N+1)$（连续性修正），换成叶子后估计错误数更低就剪 |
| 「C4.5 和 CART 的分工？」 | C4.5：多路 + 增益率 + 内建缺失值 + 误差剪枝；CART：强制二分 + Gini/SSE + surrogate + 代价复杂度剪枝 |

| 平均增益门槛 | average-gain threshold | 先丢掉增益低于平均的属性，防分母过小虚高 |
| 基于误差的剪枝 | error-based pruning | 长满后自底向上，按估计误差把子树换成叶子 |
| 连续性修正 | continuity correction | $\hat p=(E+1/2)/(N+1)$，避免小子树估成零错误 |
| 分数实例加权 | fractional instance weighting | 缺失样本按频率分配到各分支，权重一路带着走 |
| 分数路由 | fractional routing | 预测时缺失样本沿所有分支走，结果加权合成 |
| 滚动计数 / 单次扫描 | one-pass scan | 排序一次之后线性扫候选阈值 |
| 规则抽取 | rule extraction | 把多路树改写成 `if 属性 = 值` 的规则集 |
