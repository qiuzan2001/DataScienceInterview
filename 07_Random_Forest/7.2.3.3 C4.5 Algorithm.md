## 1 决策树为什么要在那里不停提问

<!-- priority-banner -->
> [!important] 优先级 **⭐⭐ 高频** ｜ 重点：增益率・缺失值・误差剪枝
> 🚀 捷径：[[02. 三条学习路径]] ・ 📋 公式：[[04. 公式速查卡]] ・ ✅ 自测：[[99.3 决策树]] ・ 🔎 追问：[[05. 高频追问 TOP 30]]


* **目标**：尽可能快（问题数少）又尽可能准地预测新样本的类别。
* **思路**：每个内部节点针对一个属性问一个*问题*。

  * 最好的「第一个问题」，是那个能让后续问题都变简单的问题——也就是让子节点尽可能纯的问题。

## 2 深入 ID3——最原始的蓝图

### 2.1 用熵度量「纯度」

$$
H(S)= -\sum_{c} p(c)\log_2 p(c)
$$

| 直觉                                                                      | 翻译                                                                         |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| *如果做完美压缩，平均要用几个 bit 才能把类别标签「说」出去？* | 熵高 ⇒ 你要学的东西还很多；熵低 ⇒ 几乎已经确定是哪一类 |

### 2.2 把纯度变成一条贪心规则

1. **问完属性 $A$ 之后的期望不纯度**

   $$
   \overline{H}(S,A)=\sum_{v}\frac{|S_v|}{|S|}\,H(S_v)
   $$
2. **信息增益**（知道 $A$ 之后省下的 bit 数）：

   $$
   \text{Gain}(S,A)=H(S)-\overline{H}(S,A)
   $$
3. **贪心选择**：选 Gain *最大* 的 $A$；然后在每条分支里重复同样的动作。

> **为什么这里贪心能成立**
> 总的期望 bit 数 = 根节点问题的 bit 数 + 走到的那条分支里的 bit 数。
> 要让总和最小 ⇒ 先让第一项最小，*然后*再递归（这就是最优子结构性质 optimal-substructure property）。

### 2.3 ID3 里如何处理连续属性

* 在节点上把取值排序一次。
* 在每个「类别标签发生变化」处取中点作为候选切点。
* 把每个阈值当成一个两值属性来计算 Gain。

### 2.4 朴素 ID3 的几个要害弱点

| 问题                                  | 症状                       | 根因                              |
| ---------------------------------------- | ----------------------------- | --------------------------------------- |
| 偏爱取值特别多的属性 | 「ZIP code」压过一切   | Gain 只要把数据切得够薄就会涨 |
| 树会爆炸                        | 出现只含单个样本的细枝          | 没有剪枝环节                         |
| 每个节点都对数值列重新排序    | 每个属性 $O(n\log n)$    | 朴素的「每个分裂都试一遍」                 |
| 无视缺失值里的结构      | 要么丢行，要么粗暴插补 | 可能浪费数据或引入偏差                  |

先记住这四条——下一个算法把它们逐一修好。

## 3 C4.5——给 ID3 装上「街头智慧」

### 3.1 更公平的分裂打分：**增益率（Gain Ratio）**

1. *分裂信息（Split-Info）*（「光凭 $A$ 就把数据切得多碎？」）

   $$
   \text{SplitInfo}(S,A)= -\!\!\sum_{v}\frac{|S_v|}{|S|}\log_2\frac{|S_v|}{|S|}
   $$
2. *增益率*

   $$
   \text{GainRatio}(S,A)=\frac{\text{Gain}(S,A)}{\text{SplitInfo}(S,A)}
   $$
3. **选属性的规则**

   * 先把 Gain 低于平均值的属性全部丢掉（防止分母过小导致虚高）。
   * 再在剩下的里面选正增益率最高的那个。

*效果*：惩罚那些只会「把标签打散」、却不能真正分开类别的提问。

---

### 3.2 让树保持可控：**基于误差的剪枝（Error-Based Pruning）**

1. **先把树长满**，和 ID3 完全一样。
2. **自底向上扫一遍**

   * 对一个有 $N$ 个加权样本、$E$ 个错误的子树，估计其错误率
     $\hat{p}=\dfrac{E+\frac12}{N+1}$。
   * 如果把这个子树换成一个**叶子**（并加上复杂度惩罚后）估计错误数更低，就剪掉。
3. **结果**：树更小、更不容易过拟合，也更好读。

---

### 3.3 给数值分裂加速

* 在*根节点*对每个数值属性**只排序一次**（代价 $n\log n$）。
* 对每个后代节点：

  * 沿着已经排好序的列表从左往右扫，同时维护各类的滚动计数。
  * 只在**标签发生变化的边界**处评估 Gain / Gain Ratio——耗时与到达该节点的样本数成线性。

---

### 3.4 更聪明的缺失值处理：**分数实例加权（Fractional Instance Weighting）**

* 按属性 $A$ 分裂时，$A=?$ 的样本会被*按分数复制*到每一条分支上。

  * 分到分支 $v$ 的权重：正比于该节点上已知样本里 $v$ 出现的频率。
* 所有计数（增益、剪枝误差）都用这些权重，于是既不丢数据，也不需要任何全局猜测。

---

## 4 C4.5 算法骨架

```text
function C45(S, Attr):
    if stop(S): return Leaf(majority(S))
    bestA ← argmax GainRatio(S, Attr)      # numeric branch uses one-pass scan
    node  ← DecisionNode(bestA)
    for each branch b of bestA:
        Sb ← weightedSubset(S, bestA = b)  # weights handle missing values
        if Sb is empty:
            node.addBranch(b, Leaf(majority(S)))
        else:
            node.addBranch(b, C45(Sb, Attr))
    return PostPrune(node)                 # error-based pruning
```

*注意*：控制流仍然是那套熟悉的 ID3 循环，变的只是几个辅助函数。

## 5 复杂度与实际收益

| 方面                      | ID3                | C4.5 的改进              | 什么时候重要                          |
| --------------------------- | ------------------ | ----------------------------- | ---------------------------------------- |
| 每个节点的数值分裂成本 | $O(n_a\log n_a)$   | $O(n_a)$                      | 浮点特征很多的数据集                |
| 属性偏置              | 高（偏爱多取值） | 由增益率控制      | 类别取值词表很大的数据 |
| 树的规模                   | 可能巨大   | 剪枝后小 25-50 % | 标签含噪、要求可解释性           |
| 缺失数据                | 丢弃 / 朴素填补  | 分数路由（fractional routing）            | 问卷数据、传感器缺口                     |

$n_a$ = 到达该节点的样本数。

## 6 一句话心智模型

> **ID3** 问的是那个能最快砍掉不确定性的问题。
> **C4.5** 依然这么做——但它会检查这个问题是不是在「作弊」，会剪掉爱吹牛的子树，飞快地扫过数值，并且优雅地处理空值。

## 7 C4.5 的强项——以及 [[7.5 CART Algorithm| CART]] 在哪里接手

C4.5 是 ID3 的稳健、可上生产线的扩展：它解决了属性偏置、过拟合、数值脆弱性这些痛点，同时保留了原来的递归循环。但它仍然继承了一些设计选择——这些选择虽然优雅，却不是唯一做法：

| C4.5 继承下来的特点                                                             | 为什么有时会成为限制                                      | CART 的替代方案                                                          |
| ----------------------------------------------------------------------------------- | -------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| **默认多路分裂（multi-way splits）**<br>每个类别特征可能长出很多分支 | 增加复杂度；更难可视化或导出成规则系统 | **只做二分（binary splits）**——树更简单，更容易转换与剪枝           |
| **基于熵的打分**<br>需要对数与分数 bit                | 数学上很讲道理，但更慢，尤其在大数据集上      | **Gini 不纯度 / MSE**——算得更快，效果往往一样好          |
| **靠误差估计做预剪枝**<br>一边长一边剪枝               | 在信息还不完整时就做剪枝决策               | **代价复杂度后剪枝（cost-complexity pruning，`ccp_alpha`）**——看到完整子树后再评估 |
| **内建缺失值处理**                                                 | 很优雅，但在 C4.5 之外不是标准做法                                | CART 不做这件事，假定由预处理或更简单的处理方式来解决        |

> **关键结论**：C4.5 在生长过程中就建成更聪明的树——而 **CART** 问的是另一个问题：能不能让树先长满、用更快的分裂准则、等看清全貌之后再剪枝？
