# 8.3 装袋法（Bagging / Bootstrap Aggregating）

## 速览 At a glance

**速记**

不剪枝的深树有两个毛病同时出现：训练集上几乎不出错，换一份数据重训就换一副样子。Bagging 修的是后一个 —— 它从原始数据里**有放回**地抽 $B$ 份同样大小的样本，每份各训一棵树，回归取平均、分类取多数投票。平均不改变预测的均值位置，只把围绕均值的散布收紧，所以它降方差、不动偏差；每份样本平均漏掉约 36.8% 的行，这些「袋外」行可以当验证集，不用另切一份数据。能降多少由树之间的相关性卡住：平均后方差是 $\rho\sigma^2+(1-\rho)\sigma^2/B$，第一项与 $B$ 无关，是地板。$\sigma^2=1$、$\rho=0.5$ 时，树从 1 棵加到 10 棵，方差 1.000→0.550；再加到 100 棵只到 0.505。随机森林多做的就是压低这个 $\rho$：每次分裂只从随机抽出的 $m$ 个特征里挑最优分裂。样本量小的数据上别用 36.8% 这个近似：$n=10$ 时实际漏掉比例是 34.87%。

**一句面试答法**

> "Bagging stands for bootstrap aggregating: draw B bootstrap samples, fit a base learner on each, and average the predictions or take a majority vote. It cuts variance and leaves bias roughly where it was, because the base learner is already a low-bias, high-variance model like an unpruned tree. Each bootstrap sample leaves out about thirty-seven percent of the rows, and those out-of-bag rows give you a validation estimate for free."

**术语**

| 中文 | English | 一句话 |
|---|---|---|
| 装袋 | bagging / bootstrap aggregating | 有放回抽样 + 平均 |
| 自助抽样 | bootstrap | 有放回抽 $n$ 个点，同一样本可被抽多次 |
| 基学习器 | base learner | 被装袋的单个模型，常用不剪枝深树 |
| 汇总 | aggregation | 回归取平均、分类取多数投票 |
| 袋外样本 | out-of-bag (OOB) | 某次 bootstrap 没抽中的那约 36.8% 的行 |
| 袋外误差 | OOB error | 只用没见过该行的树算出的误差，近似测试误差 |
| 相关系数 | correlation $\rho$ | 两棵树的预测有多像，决定方差地板 |
| 稳定性 | stability | 换一份训练数据，模型变多少；树很不稳定 |
| 特征子采样 | feature subsampling / $m$ | 每次分裂只看随机抽出的 $m$ 个特征 |
| 变量重要性 | variable importance | 分裂带来的 RSS 下降，或打乱该变量后 OOB 误差的上升 |
| 置换重要性 | permutation importance | 打乱某列后 OOB 误差的增量 |

## 一、先看一个问题

面试官那句 **"What is OOB error?"** 看着是个定义题，但答「袋外误差就是没被抽中的样本上的误差」会被立刻追一句：**为什么它能替代交叉验证？** 要答这句得先知道 bagging 抽样后每份样本里剩下什么。

先看一个具体场景。手上有 20 万行车险理赔数据，要预测赔付金额。你训了一棵不限深度的回归树：训练集 $R^2$ 0.94，五折交叉验证 $R^2$ 0.61。剪枝到深度 6，训练 $R^2$ 掉到 0.72，交叉验证反而是 0.63。

这个组合说明问题不在树「学得不够」，而在它**学得太贴合当前这份数据**：训练集的个体噪声被它记住了，换一组数据就还回去。你不需要更多特征、也不需要更复杂的模型结构，你需要的是让预测不要依赖「恰好抽到了这几行」。

Bagging 给的办法很直接：把这份数据当成一份样本，反复有放回地重抽，训一批树，再平均。平均之后那部分「因为恰好抽到这几行才出现的偏差」会互相抵消 —— 但不是全部抵消，能抵消多少由一个量决定，下面会算出来。

## 📖 标准定义

> **教材原文 · PSL §4.2.1 Introduction to Random Forest、§4.2.3 Variable Importance（页面 w4_2_randomforest.html）**（<https://liangfgithub.github.io/PSL/w4/w4_2_randomforest.html>）
> > "Bagging (Bootstrap Aggregation) is a technique where we generate multiple bootstrap samples, fit a regression tree model to each, and average the predictions from these trees. Specifically, for each of the ‘B’ bootstrap samples, we fit the data to a regression tree to obtain individual trees T1, T2, …, TB. The final prediction is the average of the predictions from these ‘B’ trees."
> >
> > "These omitted data points are referred to as “ Out-of-Bag ” (OOB) samples."

**标准记法**：袋外样本概率：每个 $x_i$ 不被某次 bootstrap 抽中的概率 $\approx (1 - 1/n)^n \to e^{-1} \approx 0.368$。袋外误差 $\text{OOB-Err} = \frac{1}{n}\sum_{i=1}^n L\big(y_i, \hat{f}^{[-i]}(x_i)\big)$，$\hat{f}^{[-i]}$ 只用不含第 $i$ 个观测的树。重要性 I：分裂带来的 RSS 下降（按变量归集后取平均）；重要性 II：置换前后 OOB 预测误差之差，$\text{VI}_j = \frac{1}{B}\sum_b (\text{Err}^{\text{perm}}_b - \text{Err}_b)$。

**中文解释**：Bagging 抽 B 个 bootstrap 样本各长一棵树再平均，专治高方差低偏差的树；随机森林再多加一层限制：每次分裂只看随机抽出的 $m$ 个特征（分类 $\sqrt{p}$、回归 $p/3$），把树之间的相关性压下来。没被抽中的 OOB 样本天然可当验证集。重要性有两套：分裂的 RSS 收益，和 OOB 上打乱该变量后误差的上升。

> 完整条目与更多来源见 [[定义原文库#C13. 随机森林 / m 的推荐值 / OOB / 两种重要性|C13. 随机森林 / m 的推荐值 / OOB / 两种重要性]]

上面这段是**面试要说出口的措辞**。下面先讲它为什么成立，再算一遍。

## 二、核心直觉

Bagging 是 **Bootstrap Aggregating** 的缩写，两个词各对应一根柱子：

1. **Bootstrapping（有放回抽样）**：从原始数据里反复做有放回的随机抽样，每个「bootstrap 样本」既像原数据集、又和原数据集不同。每个样本平均留下约 63.2% 的原始行（漏掉约 36.8%）；同一行可能在一份样本里出现两次、在另一份里一次都没出现。
2. **Aggregation（把多个学习器聚合）**：每份样本训一个基模型，回归取平均、分类取多数投票。

**像什么、不像什么。** 像一个 100 人的气象员小组各自写下明天的气温，再取平均 —— 像的地方是个体的随机抖动在平均里相互抵消；**不像的地方**是气象员的错误大致独立，而同一份数据上长出来的两棵深树不是。强预测变量会反复主导分裂，两棵树长得像、错的样本也像，所以抵消得不彻底。这个「不彻底」有多大，第三节的方差公式说了算，也是整页最该记的一个数。

**它不动什么。** 每棵树都是长到尽的。长到尽的树偏差已经很低（它把训练集背下来了），所以集成的预测均值与单棵树的均值几乎一样。平均不会把这个均值往真值方向推，只是压小了围绕均值的散布。这一条解释了为什么「bagging 降偏差」是错的。

## 三、机制

### 3.1 算法四步

1. **Bootstrap Sampling（自助抽样）**
   - 给定大小为 $n$ 的数据集，对 $b=1,\dots,B$ 重复：**有放回**地抽 $n$ 个样本点，记为 $D_b$。
   - 每个 $D_b$ 里都有重复行，平均漏掉约 $0.368n$ 个点。
2. **Train Base Learners（训练基学习器）**
   - 在每个 $D_b$ 上单独拟合所选基学习器（常用决策树），得到 $f_1, f_2, \dots, f_B$。
   - 每份样本略不同，所以每个 $f_b$ 抓到的是噪声的不同侧面 —— 这是它们预测结果不相关的来源。
3. **Aggregate Predictions（聚合预测）**
   - **回归：**
     $$
     \hat{f}(x) = \frac{1}{B}\sum_{b=1}^B f_b(x).
     $$
   - **分类：**
     $$
     \hat{y}(x) = \operatorname{mode}\bigl\{f_1(x),\,f_2(x),\,\dots,f_B(x)\bigr\}.
     $$
4. **Out-of-Bag (OOB) Estimation（袋外估计）**
   - 对每个原始观测，大约三分之一的树**没见过它**（它没被那几次抽样抽中）。
   - 只用这些「没见过它」的树来做预测，就得到测试误差的近似无偏估计 —— 相当于白送一个验证集，不必再单独划分。

### 3.2 方差分解：关键一步在相关性

已知每个单独预测器 $f_b(x)$ 的方差是 $\sigma^2$、两两相关系数是 $\rho$，则平均后的方差是

$$
\mathrm{Var}\bigl(\tfrac{1}{B}\sum_{b=1}^B f_b(x)\bigr)
= \frac{\sigma^2}{B} + \frac{B-1}{B}\,\rho\,\sigma^2
= \rho\,\sigma^2 + \frac{1-\rho}{B}\,\sigma^2.
$$

逐符号读：

- $\sigma^2$：单个基学习器的预测方差。
- $\rho$：任意两棵树预测的相关系数（平均），衡量「它们是不是一起错」。
- $\sigma^2/B$：完全独立时的方差。这一项随 $B$ 一起缩小。
- $\frac{B-1}{B}\rho\sigma^2$：相关部分。$B$ 大时这个系数趋近 1，整项趋近 $\rho\sigma^2$。

**关键一步**：不要把 $\rho$ 当成小量忽略。$B\to\infty$ 时第一项归零，剩下的 $B$ 又动不了的 $\rho\sigma^2$ 就是**地板**。加树只能逼近地板，降地板只能去降 $\rho$ —— 随机森林抽特征（见 3.4）做的是后一件事。

### 3.3 OOB 估计是怎么来的

第 $i$ 个观测被某一次有放回抽样漏掉的概率是 $(1-1/n)$；$B$ 次独立抽样都没抽到它的概率是 $(1-1/n)^B$，随 $B$ 迅速趋近 0 —— 所以每行总有一批树没见过它。把这些树的预测单独收集起来算损失，就得到 $\text{OOB-Err}$：

$$
\text{OOB-Err} = \frac{1}{n}\sum_{i=1}^n L\bigl(y_i,\ \hat{f}^{[-i]}(x_i)\bigr)
$$

- $\hat{f}^{[-i]}$：只用**不含第 $i$ 行**的那些树组成的子集成。
- $L$：损失函数（回归用平方误差，分类用 0-1 或对数损失）。
- 求和除以 $n$：对所有行取平均。

袋外误差的好处是不用手工切验证集；代价是它对每行用到的树数比 $B$ 少一个量级，$B$ 小的时候噪声大。

### 3.4 随机森林：把 $\rho$ 压下来

标准 bagging 是在 bootstrap 样本上长树，**随机森林（Random Forest）**额外加了一层随机性：

- **Feature Subsampling at Splits（分裂时抽特征）**：每个节点分裂时不再考虑全部 $p$ 个特征，而是随机取大小为 $m$ 的子集（分类常用 $m=\sqrt{p}$，回归常用 $m=p/3$），只在这个子集里选最优分裂。
- **Why It Helps（为什么有用）**：同一份数据上的两棵深树往往很像，因为强预测变量会反复主导分裂。限制候选特征后，树被迫探索其他预测变量，从而压低方差公式里的 $\rho$。
- **Key Hyperparameters（关键超参数）**：
  1. **Number of Trees ($B$)**：树越多方差越低，过了某个阈值就是边际收益递减。
  2. **Feature Subset Size ($m$)**：在「单棵树够强」与「树之间相关性低」之间做平衡。
  3. **Tree Depth / Min. Samples per Leaf**：控制单棵树的偏差；树越浅越不容易过拟合，但会引入偏差。
- **Outcomes（效果）**：
  - **Superior Accuracy**：随机森林通常比纯 bagged 树略胜一筹，优势稳定。
  - **Variable Importance**：在 OOB 数据上把某个特征的取值打乱，看预测误差涨多少；也可以按分裂带来的 RSS 下降归集（两套口径，见 📖 标准定义里的重要性 I / II）。

### 3.5 优缺点

**Pros（优点）**

- **降方差**：平均抹平单棵树的波动，预测更稳。
- **易并行**：$B$ 个模型各自独立训练，天然适合多核或分布式。
- **抗过拟合**：单棵深树容易过拟合，bagged 树合起来泛化好得多。
- **自带误差估计**：OOB 误差给出一个不用额外切数据的泛化度量。

**Cons（缺点）**

- **偏差不变**：bagging 不解决基学习器的系统性误差。如果每棵树都稳定地错（高偏差），平均也救不了。
- **计算开销**：训练和存储 $B$ 个模型很吃内存和时间。
- **可解释性下降**：很多棵树组成的集成丢掉了单棵树的决策路径，解释更难。

**逻辑串联**：bagging 用「平均多个有噪声但近似无偏的模型」对抗方差，bootstrap 负责注入多样性；随机森林再加特征随机性，把模型之间的相似性打断，把降方差榨得更彻底。主线始终是偏差-方差权衡 —— 如果偏差才是主要矛盾，应该转向 boosting 或更强的基学习器。

## 四、算一遍：方差能降多少、降到哪停

### 第 1 步：把公式代入数字

固定单个基学习器的方差 $\sigma^2=1$（单位无所谓，看比例），按 $\rho$ 和 $B$ 算 $\rho\sigma^2+\frac{1-\rho}{B}\sigma^2$。$B=1$ 时公式给出 $\rho+(1-\rho)=\sigma^2=1.000$，和「只有一棵树」一致，这一步是校验公式没错。

| $\rho$ | $B=1$ | $B=10$ | $B=100$ | 地板 $\rho\sigma^2$ | $B=100$ 距地板还差 |
|---|---|---|---|---|---|
| 0.0 | 1.0000 | 0.1000 | **0.0100** | 0.0 | 0.0100 |
| 0.2 | 1.0000 | 0.2800 | **0.2080** | 0.2 | 0.0080 |
| 0.5 | 1.0000 | 0.5500 | **0.5050** | 0.5 | 0.0050 |
| 0.9 | 1.0000 | 0.9100 | **0.9010** | 0.9 | 0.0010 |

### 第 2 步：读这张表

**从左往右看（加树）**：$\rho=0.5$ 时，1 棵树 1.000 → 10 棵 0.550 → 100 棵 0.505。前 10 棵树买到 0.450 的方差下降，后 90 棵只买到 0.045 —— **十分之一都不到**。这解释了为什么实践里 $B$ 常用几百而不是几万。

**从下往上看（相关性）**：同样是 100 棵树，$\rho=0$ 时方差 0.010，$\rho=0.9$ 时是 0.901。**同样的树数，方差差 90 倍**，差的全部是那一项 $\rho\sigma^2$。所以「树数」和「相关性」不是两个平行的旋钮：树数只能接近地板，相关性决定地板在哪。

### 第 3 步：袋外比例 $(1-1/n)^n$

每份 bootstrap 样本漏掉的行占比：

| $n$（样本量） | 漏掉比例 $(1-1/n)^n$ | 留下比例 | 每 100 行漏掉几行 |
|---|---|---|---|
| 10 | 34.87% | 65.13% | 34.9 |
| 100 | 36.60% | 63.40% | 36.6 |
| 1000 | 36.77% | 63.23% | 36.8 |
| $\to\infty$ | $e^{-1}=36.79\%$ | 63.21% | 36.8 |

算 $n=10$ 那一行：$(1-0.1)^{10}=0.9^{10}=0.348678$。算 $n=100$：$0.99^{100}=0.366032$。

**这两行之间的差别是这一节的实际用处**：小样本上直接写「37%」会错 **1.9 个百分点**（$n=10$ 时真实值是 34.87%）。样本量上千之后 36.8% 才够用。同样的道理，$n=10$、$B=100$ 时每行只有约 35 棵树没见过它（$0.3487\times100=34.87$），OOB 误差本身的噪声比 $n=1000$ 时大得多。


### 第 4 步：条件检验——把 $\rho$ 抬起来

假设两份数据上做同样的事，样本量都是 100，袋外比例都是 36.6%（不随 $\rho$ 变），只改树之间的相关性：

| $\rho$ | $B=100$ 时集成方差 | 相对单棵树（1.000）的降幅 |
|---|---|---|
| 0.0 | 0.0100 | −99.0% |
| 0.2 | 0.2080 | −79.2% |
| 0.5 | 0.5050 | −49.5% |
| 0.9 | 0.9010 | −9.9% |

$\rho=0.9$ 那张成绩单，正好是「所有树都用同一个主导变量」时的典型形态：加 100 棵树，方差只降 9.9%，几乎白干。真实数据里随机森林的收益主要来自把 $\rho$ 从 bagging 的高位压到低位这一下。

## 五、什么情况下会失灵

### 承重假设一：基学习器是高方差、低偏差的

Bagging 的全部收益来自「平均能消掉的那部分抖动」。撤掉它：换成深度 2 的树桩，每棵树本身偏差就很高、方差很低，平均之后方差压得更低，但**偏差一点没动**。具体后果是集成结果和单棵树桩一样欠拟合，训练误差和验证误差都停在同一个水平上。这种情况的标准处理是换 boosting，不是加树。

### 承重假设二：bootstrap 能造出真正不同的树

如果每个 bootstrap 样本训出来的树几乎一样（$\rho$ 接近 1），公式里的地板就顶到 $\sigma^2$。撤掉它的后果已经量化过：$\rho=0.9$、$B=100$ 时方差只从 1.000 降到 0.901。常见的触发条件是特征数很少而其中一个变量极强 —— 所有树都在同一个变量上做第一次分裂，之后也大同小异。处理办法是压 $m$（每次分裂少看几个特征），代价是单棵树变弱、需要更多树。

### 承重假设三：OOB 误差是泛化误差的可靠估计

OOB 用「没见过第 $i$ 行的树」预测第 $i$ 行。撤掉这个假设有两个具体后果：一是**时间序列或分组数据**里，同一客户的多行会同时出现在袋内和袋外，「没见过这一行」不等于「没见过这个客户」，OOB 误差会系统性偏低（以为泛化好，其实是记住了同组信息）；二是 $B$ 很小或 $n$ 很小的时候，每行只有几十棵甚至几棵袋外树，OOB 误差的随机波动大到不能当判据（$n=10$、$B=100$ 时每行约 35 棵）。

### 与其他模型的边界

| 场景 | 用谁 | 为什么 |
|---|---|---|
| 单棵树过拟合、换数据就变 | bagging / 随机森林 | 正好是高方差场景，加树就有收益 |
| 训练误差本身也高 | boosting / GBM | 这是偏差问题，平均救不了 |
| 特征少、又有一个超强变量 | 随机森林（压 $m$） | 不压相关性的 bagging 会停在地板上 |
| 样本量小、要严格的泛化估计 | 显式交叉验证 | 小样本下 OOB 误差噪声大，别拿它当唯一依据 |
| 有时间序列或分组结构 | 分组 CV / 时序 CV | 「袋外」不等于「没见过」 |
| 要报告系数方向和显著性 | 单个 GLM | 集成只给排序与重要性，不给方向 |

## 六、常见误解

### 误解一：「bagging 主要降偏差」

**错误想法**：集成多个模型，模型变复杂了，偏差自然跟着降。

**为什么容易这么想**：很多总结表把「集成」整体说成既降偏差又降方差；而且树多了训练集的拟合确实更稳。

**错在哪一步**：漏看了基学习器是**长到尽**的树。长到尽的树在训练集上几乎不出错，偏差本来就低得没什么可降；平均只作用在「围绕均值的散布」上。判断这条最快的办法是看公式：$\rho\sigma^2+\frac{1-\rho}{B}\sigma^2$ 里没有任何一项和偏差有关。要降偏差得让新模型去拟合还没修掉的残差，那是 boosting 的机制。

### 误解二：「树越多越好，加到 2000 棵肯定比 200 棵强」

**错误想法**：既然方差随 $B$ 下降，那就多加点。

**为什么容易这么想**：曲线确实一直不涨回去，而且 bagging 加树不会让验证误差变差，看起来「加就完了」。

**错在哪一步**：看漏了收益的形状和地板。$\rho=0.5$ 时第 1 棵到第 10 棵买到 0.450 的下降，第 10 棵到第 100 棵只买到 0.045；再往上就是逼近 0.500 那块地板。代价却是线性涨的：训练时间、存储、推理延迟都按 $B$ 走。判断树数够不够，看 OOB 或验证误差有没有在动，不是看 $B$ 的大小。

### 误解三：「OOB 误差可以完全替代独立测试集」

**错误想法**：既然 OOB 是「没见过该行的树」给出的预测，那就等于样本外误差。

**为什么容易这么想**：在标准的 i.i.d. 表格数据上它确实近似无偏，而且省事。

**错在哪一步**：把「没见过这一行」当成了「没见过这一行的信息」。数据里有重复行、有同一客户的多条记录、有时间顺序时，袋外树可能见过它的孪生样本，OOB 会偏乐观。另外 OOB 是**同一份训练数据**、同一套超参数下的估计，而调参过程本身会利用它；如果拿 OOB 反复选超参，它就不再是干净的样本外估计。

### 误解四：「bootstrap 只用 63.2% 的行，等于浪费了三分之一数据」

**错误想法**：每棵树只看到 63.2% 的行，还不如直接全量训练。

**为什么容易这么想**：从「信息量」看，漏掉的行确实没参与这棵树的训练。

**错在哪一步**：漏掉的那部分不是损失，是**被换成了验证集**。全量训练的 100 棵树会高度相关（$\rho$ 大，地板高），而 bootstrap 抽样的 100 棵树各看各的噪声侧面，$\rho$ 小。而且被漏掉的行不是永远不进模型：换一份样本它们就进去了，100 棵树合起来每行平均被约 63 棵树看过。真要说浪费，浪费的是「每棵树都只看了一部分数据」这一层，换来的方差下降在第四节已经算过 —— $\rho=0.2$、$B=100$ 时是 −79.2%。

## 七、面试怎么答

### 30 秒版

> Bagging 是 bootstrap aggregating：有放回抽 $B$ 份样本，每份训一个基学习器，回归取平均、分类投票。它降方差、几乎不动偏差 —— 因为基学习器是不剪枝的深树，偏差本来就低，平均只是收紧散布。每份样本平均漏掉约 36.8% 的行，这些袋外行可以当验证集用。能降多少由树之间的相关性决定，地板的 $\rho\sigma^2$ 加再多树也压不下去，随机森林抽特征就是为了压它。

### 2 分钟版（要包含的三块）

1. **机制**：bootstrap 抽样 → 各训一棵树 → 平均/投票；四步流程加上 OOB 估计。
2. **为什么降方差**：$\rho\sigma^2+(1-\rho)\sigma^2/B$。$B$ 大时只有 $\rho\sigma^2$ 留下；$\rho=0.5$ 时 10 棵到 100 棵只从 0.550 降到 0.505，$\rho=0.9$ 时 100 棵只从 1.000 降到 0.901。由此推出随机森林的 $m$ 子采样和「树数到几百就够了」。
3. **OOB 与边界**：漏掉比例 $(1-1/n)^n\to e^{-1}=36.79\%$，$n=10$ 时实际 34.87%、每行只有约 35 棵袋外树；数据有分组或时间结构时 OOB 偏乐观。偏差高时换 boosting。

### 会被追问到哪

| 追问 | 答法要点 |
|---|---|
| 「袋外误差和交叉验证什么关系？」 | 用途相同（估泛化误差）；OOB 不用重训，但要求样本近似 i.i.d.，且不能反复拿它调参 |
| 「为什么随机森林通常比 bagging 强？」 | 分裂时只看 $m$ 个特征，把树之间的 $\rho$ 压下来，直接降低方差地板 |
| 「$m$ 怎么选？」 | 分类常从 $\sqrt{p}$ 起，回归常从 $p/3$ 起；$m$ 越小单棵树越弱、树之间越不相关，用 OOB 误差平衡 |
| 「重要性两套口径有什么差别？」 | 分裂的 RSS 收益偏向高基数/连续变量；置换重要性基于 OOB 误差，更贴近预测表现，但相关特征下会互相分摊 |
| 「bagging 能用于线性回归吗？」 | 能，但收益很小：线性模型本身稳定（低方差），平均几乎不改变结果；它治的是不稳定学习器 |
| 「树数怎么定？」 | 看 OOB 或验证误差曲线是否走平，而不是越大越好 |

## 🗣️ 英文表达 / How to Say It

**30-second version**

> "Bagging stands for bootstrap aggregating: draw B bootstrap samples, train a base learner on each one, and then average the predictions or take a vote. It reduces variance without moving bias much, because the base learner is already a low-bias, high-variance model like a deep tree."

**Mechanism**

> "The variance of the average is rho sigma squared plus one minus rho times sigma squared over B, so as B grows it's the correlation that limits you — which is exactly what the random forest fixes by sampling features. Each bootstrap sample leaves out about thirty-seven percent of the rows, and those out-of-bag rows give you a validation estimate for free."

**If they push back**

> "A common pitfall is saying bagging reduces bias. It doesn't — averaging many approximately unbiased deep trees leaves the mean roughly where it was, and only the scatter shrinks. If each tree is systematically wrong, averaging won't help at all, and that's when boosting is the better tool."
